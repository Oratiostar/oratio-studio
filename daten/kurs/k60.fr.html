60.1 Quelle carte pour quoi ?

Question Réponse
ESP32 ou Arduino ? ESP32 : WLAN, Bluetooth, plus rapide, 3,3 V. Arduino Nano : simple, robuste, 5 V, mais sans radio
Pi Pico ou Arduino Uno R4 ? Pico : très bon marché, PIO (entrée/sortie programmable), bonne puissance. Uno R4 : beaucoup de logiciels, 5 V, grand écosystème
Pi Zero ou ESP32 pour une horloge ? ESP32 : démarre aussitôt, consomme peu. Pi Zero : un Linux complet, démarre lentement, consomme plus
Y a-t-il quelque chose d'encore plus petit ? Oui : ESP32-C3, ATtiny, RP2040 en petits formats
Un ESP32 peut-il lire mes scripts Bash ou Python ? Non. Il lui faut du C++ (Arduino/PlatformIO) ou MicroPython

60.2 Avec quoi programme-t-on un ESP32 ?

  • IDE Arduino ou PlatformIO dans VS Code : C++ avec les bibliothèques Arduino.
  • MicroPython : Python sur la puce.
  • ESP-IDF : l'environnement de développement officiel, détaillé.

Même sans portable, un Raspberry Pi peut servir d'ordinateur de développement (chapitre 17).

60.3 Arduino IDE sur le Raspberry Pi

L'IDE 1.x tourne sur le Pi, l'IDE 2.x n'existe pas officiellement pour ARM64. Alternatives : arduino-cli dans le terminal ou PlatformIO. Dans le menu des cartes, on choisit la carte présente, par exemple Arduino Nano (pour les clones avec le processeur ATmega328P (Old Bootloader)).

60.4 Broches et adresses I²C

  • Sur l'Arduino Nano/Uno, A4 (SDA) et A5 (SCL) sont imposés.
  • Sur l'ESP32, les broches sont librement choisissables (par défaut : SDA 21, SCL 22), avec Wire.begin(sda, scl).
  • L'adresse (par exemple 0x3C) se trouve avec le scanner I²C.
  • UART, I²C, SPI : aucun n'est « meilleur ». UART est simple (deux lignes), I²C partage deux lignes avec beaucoup d'appareils, SPI est le plus rapide et demande plus de lignes (chapitre 12).

60.5 Sauvegarder un programme de la puce (ISP)

Avec un programmateur et la prise ISP (six broches), on peut lire le contenu d'une puce AVR, à condition que la protection en lecture ne soit pas activée. Sur l'Arduino, cela marche aussi avec avrdude via USB (chapitre 16). On obtient le fichier compilé (.hex), pas le code source.

60.6 Sons et mélodies

  • tone(pin, frequenz, dauer) joue un son sur le haut-parleur ou le buzzer.
  • Une mélodie est une liste de notes (fréquences, par exemple NOTE_E5) et de durées (4 = noire, 8 = croche ; un nombre négatif signifie une note pointée).
  • Les grands tableaux de mélodie se placent avec PROGMEM dans la mémoire du programme, pour que la mémoire de travail ne soit pas pleine.
  • Lire du MP3 : l'Arduino lui-même non. Il faut pour cela un module comme le DFPlayer Mini.
  • Un codeur rotatif (Rotary Encoder) fournit deux signaux (A et B), dont l'ordre donne le sens de rotation, et le plus souvent un bouton.

60.7 Principe de programmation EVA et choix de la langue

EVA signifie Entrée, Verarbeitung (traitement), Ausgabe (sortie). Chaque programme suit ce schéma : lire le bouton (entrée), décider (traitement), allumer la LED (sortie).

  • C++ tourne nettement plus vite que Python et est la norme sur les microcontrôleurs.
  • Python est plus facile à apprendre et idéal pour les interfaces, les scripts et le Raspberry Pi.
  • Un long programme (plus de 1000 lignes) est normal en C++. Pour commencer, un petit squelette avec setup() et loop() suffit.

60.8 Affichages et pixels

  • Piloter chaque pixel un par un : avec une bibliothèque graphique, on écrit dans une mémoire d'image (framebuffer). La bibliothèque l'envoie à l'écran. Il ne faut pas saisir chaque pixel individuellement ; on dessine des lignes, des cercles, des textes et des images.
  • Les panneaux HUB75 demandent beaucoup de lignes et un pilotage rapide. Sur le Pi, rpi-rgb-led-matrix s'en charge, sur l'ESP32 une bibliothèque DMA et sur le Pico le pilote PIO (chapitre 19).
  • Les rubans de LED à pixels individuels s'appellent WS2812B (aussi NeoPixel).

60.9 Amplifier les sorties et plus de broches

Les sorties trop faibles se commandent avec des pilotes (chapitre 67). Les registres à décalage comme le 74HC595 étendent les broches.
