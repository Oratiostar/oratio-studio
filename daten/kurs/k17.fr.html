17.1 Pourquoi PlatformIO ?

L'IDE Arduino est simple. PlatformIO dans VS Code convient mieux aux projets plus grands : plusieurs cartes, un fichier de configuration (platformio.ini), gestion des bibliothèques, meilleurs messages d'erreur.

17.2 Installation

sudo apt update
sudo apt upgrade -y
sudo apt install code -y
code --version

Puis dans VS Code :

  1. Cliquer à gauche sur Extensions.
  2. Chercher et installer PlatformIO IDE.
  3. Redémarrer VS Code.
  4. Cliquer à gauche sur la tête d'alien, puis sur New Project.
  5. Choisir le nom du projet, la carte et le framework : Arduino.

Noms de cartes :

  • Arduino Nano ATmega328
  • Arduino Mega or Mega 2560 ATmega2560
  • Espressif ESP32 Dev Module

17.3 Le fichier platformio.ini

C'est le fichier de configuration du projet :

[env:esp32dev]
platform = espressif32
board = esp32dev
framework = arduino
monitor_speed = 115200
lib_deps =
    adafruit/Adafruit SSD1306
    adafruit/Adafruit GFX Library
    adafruit/Adafruit BusIO
  • platform – la famille de puces
  • board – la carte précise
  • framework – Arduino
  • monitor_speed – vitesse en bauds du moniteur série
  • lib_deps – bibliothèques chargées automatiquement

Le programme se trouve dans src/main.cpp et commence par #include <Arduino.h>.

17.4 Commandes PlatformIO dans le terminal

pio run                       # kompilieren
pio run --target upload       # hochladen
pio run -t clean              # aufräumen
pio pkg update                # Pakete aktualisieren
pio pkg install --library "adafruit/Adafruit BusIO"
pio system prune --force      # alte Reste löschen

17.5 Le scanner I²C – le programme de diagnostic le plus important

Quand un écran I²C n'affiche rien, on vérifie d'abord si le microcontrôleur le voit :

#include <Wire.h>

void setup() {
  Serial.begin(9600);
  Wire.begin();
  Serial.println("I2C Scanner");
}

void loop() {
  byte error, address;
  int devices = 0;
  for (address = 1; address < 127; address++) {
    Wire.beginTransmission(address);
    error = Wire.endTransmission();
    if (error == 0) {
      Serial.print("Gefunden bei 0x");
      if (address < 16) Serial.print("0");
      Serial.println(address, HEX);
      devices++;
    }
  }
  if (devices == 0) Serial.println("Kein Geraet gefunden");
  delay(3000);
}

Ouvrir ensuite le moniteur série avec la bonne vitesse (ici 9600). Message typique : Gefunden bei 0x3C (trouvé à 0x3C). C'est l'adresse de l'OLED. Si rien n'est trouvé, le problème vient du câblage, de la tension ou de l'écran. Mon ESP32 n'a reconnu l'écran que « sporadiquement », je l'ai donc testé en contre-épreuve sur le Nano : cela permet de distinguer une panne de l'écran d'une panne de l'ESP32.

Câblage d'un OLED I²C sur l'ESP32 :

OLED ESP32
GND GND
VCC 3V3
SCL GPIO 22
SDA GPIO 21
RES ne pas brancher (ouvert)

Sur les modules que j'avais sur le Nano, RES était relié à 5 V (« ne pas laisser ouvert »). Cela dépend du module ; en cas de doute, consultez la fiche technique ou le dos de la carte.

17.6 L’erreur de compilation `esp32-hal-periman.h`

Le compilateur s'est arrêté sur #include "esp32-hal-periman.h". Ce fichier fait partie du noyau ESP32 et est inclus par une autre bibliothèque. Voici le chemin vers la solution :

  1. Vérifier les premières lignes de main.cpp. Seuls les #include nécessaires doivent y figurer.
  2. pio pkg update, puis pio system prune --force et ensuite pio run.
  3. Vérifier si main.cpp inclut encore une ancienne bibliothèque inadaptée.

Leçon générale : les erreurs de compilation ont presque toujours une ligne précise. Copier la ligne, la chercher dans main.cpp et circonscrire la cause.

17.7 LVGL – qu’est-ce que ça a apporté ?

À quoi sert LVGL (une bibliothèque graphique pour écrans) ? Elle rend les animations et mouvements plus fluides, et permet de construire des menus avec des éléments prêts à l'emploi. Mais elle n'embellit pas automatiquement l'apparence. Le design reste à faire soi-même.

17.8 Carte SD sur l’ESP32

Un module de carte SD (SPI) peut fonctionner avec l'écran. Les deux partagent SCK et MOSI, la carte SD reçoit son propre Chip-Select :

Module SD ESP32
VCC 3,3 V
GND GND
MISO GPIO 19
MOSI GPIO 23
SCK GPIO 18
CS GPIO 13 
#include <SPI.h>
#include <SD.h>
#define SD_CS 13

void setup() {
  SPI.begin(18, 19, 23);
  if (SD.begin(SD_CS)) {
    Serial.println("SD Karte OK");
  } else {
    Serial.println("SD Fehler");
  }
}

17.9 Sauvegarder le firmware : esptool

Avant d'écraser le firmware d'usine d'un appareil fini (par exemple une montre DSTIKE), on peut le sauvegarder :

esptool.py --chip esp32s3 --port /dev/ttyUSB0 read_flash 0 0x1000000 backup.bin
esptool.py --chip esp32s3 --port /dev/ttyUSB0 write_flash 0 backup.bin

(Sous Windows le port s'appelle COM3, sur le Pi /dev/ttyUSB0 ou /dev/ttyACM0.) On peut ainsi restaurer à tout moment l'état à la livraison. La taille 0x1000000 correspond à 16 Mo de flash, cela dépend de l'appareil.
