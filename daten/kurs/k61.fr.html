61.1 Python : différences importantes

  • print écrit du texte dans le terminal. Pour chercher des erreurs, c'est l'outil le plus simple (print("hier")).
  • os.system("befehl") lance une commande, mais n'est pas sûr avec des entrées venant de l'extérieur. Mieux vaut subprocess.run([...]) ou subprocess.Popen([...]) avec une liste composée de la commande et des arguments.
  • JSON comme base de données : pour de petits programmes, un fichier JSON est le stockage le plus simple (noms, chemins, réglages). Règle de base : réglages en JSON, logique dans le code. On peut alors ajouter des applications sans modifier le code.
  • Peut-on utiliser n'importe quelle commande Linux ? Oui, toute commande que le terminal connaît peut être lancée avec subprocess.
  • Majuscules et minuscules : Python distingue Name et name. Les classes s'écrivent habituellement GroßBuchstabe, les fonctions et variables klein_mit_unterstrich.
  • ComboBox ou QInputDialog : une ComboBox est un champ de choix qui reste dans la fenêtre. QInputDialog est une fenêtre popup avec une saisie ou un choix.
  • PyQt5 ou PyQt6 : les deux se ressemblent, mais ne sont pas compatibles (par exemple exec_() contre exec()). Utiliser une seule version de façon cohérente.

61.2 Glisser-déposer dans Qt

Au lieu de gérer soi-même les événements de souris (mousePressEvent, mouseReleaseEvent), Qt offre une prise en charge intégrée du glisser-déposer. Elle est plus stable quand beaucoup d'éléments sont déplacés. En glissant, on peut assombrir l'élément en calculant sa couleur à partir de la couleur de base.

61.3 Python ou C++ pour mon projet ?

Le C++ (par exemple avec Qt) est plus rapide et demande moins de mémoire, mais le développement prend plus de temps. Pour une interface avec des boutons qui lancent des scripts, Python est assez rapide. Un programme pour le Raspberry Pi peut être réécrit en C++ et compilé là, il ne tourne alors que sur l'architecture adaptée (ARM64).

61.4 Lancer son programme plus tôt ou comme écran de démarrage

Le démarrage automatique (chapitre 5) démarre après la connexion. Si l'on veut démarrer plus tôt (par exemple une vidéo au démarrage), il faut un service systemd. Les services démarrent avant la connexion et peuvent jouer aussitôt un programme ou une vidéo. La durée de lecture se règle avec une heure de début et de fin, par exemple avec mpv --start=8 --end=19 video.mp4.

61.5 Steam Deck et jeux rétro

Formats de fichiers PS1 :

Format Description
BIN + CUE Image plus description des pistes
CHD image compressée, économise de la place, lue par la plupart des émulateurs (recommandé)
PBP Format de paquet Sony, souvent pour des jeux autonomes
M3U Liste de lecture pour les jeux à plusieurs disques

Conversion : chdman createcd -i spiel.cue -o spiel.chd. Pour plusieurs disques, on crée un CHD par disque et un .m3u avec les noms de fichiers.

BIOS : sous RetroDECK dans le dossier ~/retrodeck/bios/. La PS2 demande un sous-dossier ps2, parce que l'émulateur (PCSX2) y attend les fichiers.

Bazzite ou SteamOS ? SteamOS est le système de Valve pour le Deck. Bazzite est un système semblable basé sur Fedora, qui tourne aussi sur d'autres consoles portables (par exemple appareils Intel et AMD).

Étendre le stockage : le Steam Deck et le ROG Ally acceptent une carte microSD ou un SSD M.2 remplaçable (taille 2230 ou 2242). Vérifier le format avant l'achat.
