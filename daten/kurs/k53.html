So ist dieses Lexikon aufgebaut: Jede Meldung steht fett, darunter Bedeutung, Ursache und Lösung. Mit der Suchfunktion des PDF-Programms lässt sich nach einem Teil der Meldung suchen. Die Meldungen sind nach Thema geordnet (Kapitel 53 bis 58).

Die Grundregel: Lies die Meldung von unten nach oben. Die letzte Zeile nennt meist die eigentliche Ursache, die Zeilen davor zeigen, wo es passiert ist.

53.1 Befehl nicht gefunden

bash: xyz: Kommando nicht gefunden / command not found

Bedeutung: Die Shell kennt den Befehl xyz nicht.

Mögliche Ursachen und Lösungen:

Ursache Prüfen Lösung
Tippfehler (Groß-/Kleinschreibung zählt) Befehl noch einmal exakt abtippen korrigieren
Programm nicht installiert which xyz zeigt nichts sudo apt install xyz
Programm nur in einer eigenen Umgebung zum Beispiel pio (PlatformIO) oder code den vollen Pfad verwenden, zum Beispiel ~/.platformio/penv/bin/platformio, oder VS Code installieren
Befehl gehört zu einem anderen System sudo: pacman: command not found auf dem Pi, sudo: apt: command not found auf dem Steam Deck auf dem Raspberry Pi nutzt man apt, auf dem Steam Deck (SteamOS, Arch-Basis) pacman
Panel-/Desktop-Programm gibt es in dieser Version nicht zum Beispiel lxpanelctl: command not found auf neuem Raspberry Pi OS mit labwc abmelden und neu anmelden statt das Panel neu zu starten
Programm im aktuellen Ordner ./programm statt programm Pfad mit ./ davor angeben

curl: command not found

sudo apt install curl. Danach den Befehl wiederholen.

Fehler: Paket powershell kann nicht gefunden werden

apt kennt das Paket nicht, weil PowerShell nicht in den Standard-Paketquellen liegt. Entweder die Microsoft-Paketquelle einrichten oder PowerShell nicht auf dem Pi installieren. Die meisten Aufgaben löst man auf Linux mit bash.

Zeile 1: from: Kommando nicht gefunden (Zeile 2, Zeile 3 ...)

Bedeutung: Eine Python-Datei wurde wie ein Shell-Skript gestartet. Die Shell liest from ... import ... als Befehl from und kennt ihn nicht.

Lösung: Python-Dateien immer mit dem Interpreter starten:

python3 datei.py

Soll die Datei direkt per ./datei.py laufen, braucht sie in der ersten Zeile #!/usr/bin/env python3 und chmod +x datei.py.

bad interpreter: /bin/bash^M

Ursache: Die Datei wurde unter Windows gespeichert und hat Windows-Zeilenenden (CRLF).

Lösung:

sed -i 's/\r$//' script.sh

53.2 Rechte und Dateien

Permission denied / Keine Berechtigung

Bedeutung: Der Benutzer darf die Datei oder den Ordner nicht lesen, schreiben oder ausführen.

Vorgehen:

  1. Rechte ansehen: ls -l datei
  2. Besitzer und Rechte ändern, je nach Fall:
chmod +x script.sh            # ausführbar machen (Zeile ./script.sh Permission denied)
sudo chown oratio:oratio datei  # Besitzer ändern
sudo chmod -R 755 ordner        # Ordner lesbar und betretbar (siehe 2.10)
  1. Nur wenn nötig sudo verwenden. Auf Datenpartitionen, die einem anderen System gehören (zum Beispiel Batocera SHARE), schafft sudo chmod -R 777 /media/oratio/SHARE Schreibrechte (Kapitel 26.6).

bash: ./script.sh: Permission denied

Das Skript ist nicht ausführbar: chmod +x script.sh, dann ./script.sh.

No such file or directory / Datei oder Verzeichnis nicht gefunden

Bedeutung: Der Pfad stimmt nicht.

Prüfen: pwd (wo bin ich?), ls (was liegt hier?), Groß-/Kleinschreibung, Leerzeichen (Pfade mit Leerzeichen in Anführungszeichen setzen), Tilde ~ nur am Anfang eines Pfades.

Wichtig: Steht vor einem Befehl ein <, versucht die Shell, die Datei als Eingabe zu lesen (<wlr-randr ... führt zu „Datei nicht gefunden"). Befehl ohne das < eingeben.

ls: cannot access '/dev/ttyUSB*': No such file or directory

Es ist kein USB-Seriell-Gerät erkannt. Siehe Kapitel 55.4 (Board nicht erkannt).

53.3 Programme und Pakete

E: Unable to locate package ...

sudo apt update ausführen, Namen prüfen (apt search name).

error: externally-managed-environment (bei pip install)

Neues Raspberry Pi OS erlaubt pip nicht im System. Lösung: eine virtuelle Umgebung benutzen (Kapitel 3):

python3 -m venv ~/.venvs/projekt
source ~/.venvs/projekt/bin/activate
pip install paket

ModuleNotFoundError: No module named 'xyz'

Das Python-Paket fehlt in der benutzten Umgebung. Prüfen, ob die richtige Umgebung aktiv ist (source .../activate), dann pip install xyz. Wird das Programm mit sudo gestartet, sieht es die Umgebung nicht: sudo -E oder den vollen Pfad des Python-Programms der Umgebung verwenden (typisch bei No module named 'rgbmatrix', siehe 33.6).

cannot execute binary file: Exec format error

Bedeutung: Das Programm ist für eine andere Prozessorarchitektur gebaut. Typisch: eine amd64-Datei (Steam Deck, PC) auf dem ARM64-Raspberry-Pi.

Lösung: Die passende Version für ARM64 verwenden oder das Programm aus der Paketquelle installieren (sudo apt install rpi-imager). Architektur prüfen: uname -m (aarch64 = ARM64, x86_64 = amd64).

53.4 Terminal-Besonderheiten

  • ^[[A erscheint statt der Pfeiltaste: Die Shell kennt die Zeilenbearbeitung nicht (zum Beispiel in sh statt bash). Mit bash starten.
  • unexpected end of file in einem Skript: Eine Klammer, ein if ohne fi oder ein do ohne done fehlt.
  • Befehl hängt: Strg+C bricht ab. Ein Programm im Hintergrund wird mit kill PID beendet (PID über ps aux | grep name).
