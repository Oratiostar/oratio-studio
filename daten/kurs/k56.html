56.1 Bildschirm, Wayland und Kanshi

failed to connect to display

Bedeutung: wlr-randr oder ein anderes Wayland-Werkzeug läuft unter X11 (oder ohne Desktop-Sitzung).

Lösung: Mit echo $XDG_SESSION_TYPE prüfen, welches System läuft. Unter Wayland gilt wlr-randr, unter X11 gilt xrandr. Per SSH muss die Wayland-Umgebung gesetzt sein (Kapitel 10.3).

unexpected '{' in output und failed to parse config file: error on line 2, column 21

Bedeutung: Die installierte Kanshi-Version kennt die Schreibweise mit geschweiften Klammern hinter output HDMI-A-1 nicht. Kanshi startet deshalb nicht (Exit 1 kanshi, ps aux | grep kanshi zeigt nichts).

Lösung: Die ältere Schreibweise verwenden, mit Klammern nur um das Profil:

profile {
    output HDMI-A-1 scale 3
}

Dann kanshi im Terminal starten und auf applying profile achten.

Skalierung ist nach Neustart oder Monitorwechsel wieder falsch

Die Einstellung wird nicht gespeichert. Lösung: Kanshi mit Autostart plus Watchdog-Skript (Kapitel 10.6).

Befehl wirkt, aber nach dem Neustart ist alles zurückgesetzt

wlr-randr wirkt nur für die laufende Sitzung. Dauerhaft braucht es Kanshi oder einen Eintrag in ~/.config/labwc/autostart.

56.2 Start und Boot

Device-tree file 'bcm2712-rpi-5-b.dtb' not found und The installed operating system (OS) does not indicate support for Raspberry Pi 5

Das System auf dem Medium ist nicht für den Pi 5 gebaut (BCM2712), meist ein Pi-4-Image (BCM2711). Prüfen: Auf der Boot-Partition muss bcm2712-rpi-5-b.dtb liegen. Das richtige Image schreiben (Kapitel 26.3).

USB boot requires high current (5 volt 5 amp) power supply

Der Pi 5 verlangt für USB-Boot ein 5-V/5-A-Netzteil. Das offizielle 27-Watt-Netzteil verwenden.

Es startet immer das falsche System (SD vor NVMe)

Boot-Reihenfolge in raspi-config ändern (Advanced Options, Boot Order, B2 NVMe/USB Boot) oder beim Start die Leertaste für das Boot-Menü drücken (Kapitel 26.7 und 26.8).

Blitz-Symbol, Ruckeln, Neustarts, Under-voltage detected

Unterspannung. vcgencmd get_throttled zeigt den Zustand (0x0 ist in Ordnung). Lösung: Netzteil mit genug Leistung und gutes Kabel, auch bei 35-Watt-Netzteilen anderer Hersteller kann der Pi „zu wenig Strom" melden, wenn sie nicht die benötigte Spannungsstufe liefern.

56.3 Laufwerke

/dev/nvme0n1 does not exist

Die NVMe-SSD wird nicht erkannt. lsblk zeigt, unter welchem Namen sie erscheint (über USB zum Beispiel sda). Dann Kabel, Adapter, PCIe-Einstellungen und Stromversorgung prüfen.

Read Capacity(10) failed und sda 0B

Der Pi erkennt den USB-Adapter, aber die SSD meldet 0 Byte. Das ist kein Formatierungsproblem. Ursachen in dieser Reihenfolge prüfen: SSD sitzt nicht richtig im Gehäuse, Adapter verträgt diese SSD nicht, SSD defekt. SSD neu einsetzen, anderen Adapter probieren, lsblk erneut ansehen.

invalid token: exfat (bei parted ... mkpart primary exfat)

parted kennt exfat als Partitionstyp nicht. Partition mit fat32 als Bezeichnung anlegen und danach mit mkfs.exfat wirklich formatieren:

sudo parted /dev/sda --script mkpart primary fat32 0% 100%
sudo apt install exfatprogs
sudo mkfs.exfat /dev/sda1

fdisk: cannot open /dev/sda: Das Argument ist ungültig

Der Befehl wurde mit einem falschen Zeichen eingegeben: fdisk -l (kleines L), nicht -I. Ohne Laufwerk aufrufen: sudo fdisk -l oder sudo parted -l.

umount: /dev/sda1: not mounted

Kein Fehler. Das Laufwerk war schon ausgehängt.

mount: ... wrong fs type, bad option, bad superblock

Dateisystem fehlt oder passt nicht. Mit lsblk -f ansehen. Fehlt es, formatieren (Vorsicht, löscht alle Daten): sudo mkfs.ext4 /dev/sda1.
