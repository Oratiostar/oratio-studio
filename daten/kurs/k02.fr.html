Je me suis posé cette question moi-même : pourquoi rend-on des choses exécutables, et que se passe-t-il si on ne le fait pas ? La réponse est l’une des idées les plus importantes de Linux.

2.1 Un fichier n’est pas automatiquement un programme

Pour Linux, tout est d’abord un simple fichier, que ce soit foto.jpg, brief.txt ou script.sh. Pour qu’un fichier téléchargé (par exemple une facture qui est en réalité un code malveillant) ne puisse pas se lancer tout seul, il faut d’abord le rendre explicitement exécutable.

2.2 Lire les droits avec `ls -l`

ls -l
-rw-r--r--  test.txt
-rwxr-xr-x  script.sh

Les premiers caractères sont les droits :

  • r = read, lire
  • w = write, écrire (modifier)
  • x = execute, exécuter

Les groupes représentent le propriétaire, le groupe et tous les autres. Avec -rwxr-xr-x, le propriétaire peut tout faire, les autres peuvent lire et exécuter.

2.3 `chmod +x` – rendre un fichier exécutable

chmod +x display_watchdog.sh

Avant, c’était -rw-r--r--, après -rwxr-xr-x. Sans ce droit, le lancement donne Permission denied (permission refusée).

2.4 Pourquoi nano peut quand même ouvrir le fichier

Lire n’est pas exécuter. nano n’a besoin que du droit de lecture r. Pour lancer, il faut x.

2.5 Que signifie `./` ?

./display_watchdog.sh

./ signifie « dossier actuel ». La commande veut dire : « Lance le fichier display_watchdog.sh de ce dossier. » Sans ./, Linux ne cherche que dans certains dossiers système.

2.6 Pourquoi `bash script.sh` fonctionne même sans `+x`

bash display_watchdog.sh

Ici, ce n’est pas le fichier qui est lancé, mais le programme bash, qui lit simplement le fichier. C’est pourquoi cela marche souvent même sans le droit x.

2.7 Le shebang

Presque chaque script commence par la ligne

#!/bin/bash

C’est ce qu’on appelle le shebang. Il indique à Linux avec quel programme lancer le script (ici : bash). Pour les scripts Python, on trouve #!/usr/bin/env python3.

2.8 Changer le propriétaire avec `chown`

Ce qui a été créé avec sudo appartient à l’utilisateur root, et le compte normal n’a pas le droit de le modifier. Cela m’est arrivé avec le SSD et avec le fichier app_config.json. Avec chown, on rend le fichier :

sudo chown oratio:oratio /mnt/ssd
sudo chown -R oratio:oratio /home/oratio/Freenove_Tower_Cooler_for_Raspberry_Pi

La forme est utilisateur:groupe. L’option -R s’applique à tout le contenu du dossier.

2.9 Qu’est-ce que `sudo` ?

sudo exécute une commande en tant qu’administrateur (root). C’est nécessaire pour les installations, le formatage des disques et tout ce qui modifie le système. À retenir : ce qui est précédé de sudo peut modifier le système. Vérifier deux fois.

2.10 Les droits en chiffres : 4, 2, 1

Au lieu de rwx, on peut aussi écrire les droits sous forme de nombre. C’est plus court et très utilisé avec chmod. Chaque droit a une valeur :

Droit Lettre Nombre
lire (read) r 4
écrire (write) w 2
exécuter (execute) x 1
aucun droit - 0

On additionne les nombres des droits que l’on veut autoriser :

Droits Calcul Chiffre
--- rien 0 0
--x exécuter seulement 1 1
-w- écrire seulement 2 2
-wx écrire et exécuter 2 + 1 3
r-- lire seulement 4 4
r-x lire et exécuter 4 + 1 5
rw- lire et écrire 4 + 2 6
rwx tout 4 + 2 + 1 7

Un chmod avec des nombres comporte trois chiffres, dans l’ordre pour le propriétaire (User), le groupe (Group) et tous les autres (Others) :

chmod  7  5  5  datei
       │  │  └── alle anderen: 5 = r-x
       │  └───── Gruppe:       5 = r-x
       └──────── Besitzer:     7 = rwx

Les valeurs les plus courantes :

Nombre Droits Signification Usage typique
755 rwxr-xr-x le propriétaire tout, les autres lisent et lancent programmes, scripts, dossiers
644 rw-r--r-- le propriétaire lit et modifie, les autres lisent seulement fichiers normaux, par exemple .py, .json, .txt
664 rw-rw-r-- le propriétaire et le groupe peuvent modifier fichiers que le groupe modifie aussi
600 rw------- seulement le propriétaire, personne d’autre clés privées, mots de passe
700 rwx------ seulement le propriétaire, tout dossiers et scripts privés
777 rwxrwxrwx tout le monde peut tout faire À éviter, un risque de sécurité

Exemples :

chmod 664 app_ui_oled.py                # Datei: Besitzer und Gruppe dürfen ändern
chmod -R 755 /home/oratio/Freenove_Tower_Cooler_for_Raspberry_Pi
find /home/oratio/Freenove_Tower_Cooler_for_Raspberry_Pi -type d -exec chmod 755 {} \;   # nur Ordner
find /home/oratio/Freenove_Tower_Cooler_for_Raspberry_Pi -type f -exec chmod 644 {} \;   # nur Dateien

La dernière paire est la bonne façon de réparer tout un dossier de projet : les dossiers reçoivent 755 (ils ont besoin de x pour qu’on puisse y entrer), les fichiers reçoivent 644. find ... -type d ne trouve que les dossiers, -type f que les fichiers, -exec chmod ... {} \; exécute la commande pour chaque résultat.

La même chose avec des lettres :

chmod u+x script.sh        # dem Besitzer (u = user) Ausführen geben
chmod g+w datei            # der Gruppe (g) Schreiben geben
chmod o-r datei            # den anderen (o = others) Lesen wegnehmen
chmod a+x script.sh        # allen (a = all) Ausführen geben; ohne Buchstabe wie "chmod +x"
chmod u=rwx,go=rx script   # genau setzen: das ist dasselbe wie 755

Comment lire ls -l :

-rwxr-xr-x  1 oratio oratio  842 Nov  2 02:10 display_watchdog.sh
│└┬┘└┬┘└┬┘    └──┬─┘ └──┬─┘
│ │  │  │        │      └── Gruppe
│ │  │  │        └───────── Besitzer
│ │  │  └── andere: r-x = 5
│ │  └───── Gruppe:  r-x = 5
│ └──────── Besitzer: rwx = 7
└────────── Typ: - Datei, d Ordner, l Link

Cet exemple correspond donc à 755. Pour t’entraîner, calcule : rw-r----- donne 6, 4, 0, donc 640.

Particularité des dossiers : r signifie « lister le contenu », w signifie « y créer et supprimer des fichiers », x signifie « y entrer ». Sans x, on ne peut pas entrer dans le dossier, même si on a le droit de le lire. C’est pourquoi les dossiers reçoivent généralement 755 et non 644.
