La différence la plus importante : avec Bash, tout est du texte. Avec PowerShell, ce sont des objets. Dans PowerShell, Get-Process renvoie par exemple des objets avec des propriétés comme Name, CPU, Id, que l'on peut utiliser directement avec Where-Object ou Select-Object. Avec Bash, il faut découper les lignes de texte avec grep, awk ou cut.

25.6 Pièges typiques lors du changement

  1. Séparateur de chemin. C:\Users\Oratio\Desktop sous Windows, /home/oratio/Desktop sous Linux.
  2. Fins de ligne. Windows enregistre les fichiers texte avec retour chariot et saut de ligne (CRLF), Linux seulement avec saut de ligne (LF). Un script .sh avec des fins de ligne Windows s'arrête souvent avec un message comme bad interpreter: /bin/bash^M. Réparation : sed -i 's/\r$//' script.sh.
  3. Rendre exécutable. Sous Linux, un script a besoin de chmod +x script.sh et se lance avec ./script.sh. Sous Windows, un double-clic sur .bat et .ps1 suffit selon les réglages.
  4. Les scripts PowerShell sont bloqués par défaut. Si .ps1 ne démarre pas, un message parle de la stratégie d'exécution. On peut l'assouplir une fois, pour la session en cours seulement : Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass.
  5. Majuscules/minuscules. Datei.TXT et datei.txt sont deux fichiers différents sous Linux.
  6. Espaces dans le chemin. Toujours mettre entre guillemets : cd "/media/oratio/SHARE/meine roms".

25.7 Un exemple : le script de hash

Un exemple pratique est un script qui accepte des fichiers par glisser-déposer, calcule pour chacun un hash SHA-256 et regroupe les fichiers de même hash comme doublons. Le cœur en PowerShell :

$files  = Get-ChildItem -Recurse -File -Path $ordner
$groups = $files | ForEach-Object { Get-FileHash -LiteralPath $_.FullName -Algorithm SHA256 } |
          Group-Object Hash
foreach ($g in $groups) {
    if ($g.Count -gt 1) {
        Write-Host "Duplikate:" $g.Group.Path
    }
}

La même idée en Bash :

find "$ordner" -type f -exec sha256sum {} + | sort | uniq -w64 -D

Améliorations :

  • Parcourir les dossiers de façon récursive, pour que cela ne fonctionne pas seulement avec des fichiers isolés.
  • Ignorer les chemins invalides avec un avertissement au lieu d'abandonner.
  • Regrouper d'abord par taille de fichier et ne calculer le hash que des fichiers de même taille. Cela économise souvent 90 à 99 % des calculs de hash, car des fichiers de tailles différentes ne peuvent jamais être identiques.
  • Barre de progression, durée, temps restant et export en TXT et CSV sur le bureau.

Erreur typique à l'implémentation : le script s'arrête après « 41 fichiers trouvés » avec Cannot bind argument to parameter 'Text' because it is an empty string. Cause : une cmdlet (par exemple Write-Host ou Write-Progress) reçoit un texte vide comme paramètre obligatoire, parce qu'une variable est encore vide. Solution : vérifier la variable avant ou lui donner une valeur par défaut. Plus de détails dans le lexique des erreurs (chapitre 53 et suivants).

À retenir : en transposant un script de Bash vers PowerShell, l'idée ne change pas, seule la syntaxe change : variables avec $, objets au lieu de texte, autres noms pour les commandes.
