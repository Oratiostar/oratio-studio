Avec les microcontrôleurs, il y a trois sources d'erreur que l'on sépare l'une après l'autre : 1. la liaison avec l'ordinateur (câble, port, pilote, mode de démarrage), 2. le programme (compilation, téléversement), 3. le circuit (alimentation, niveaux, câblage). Qui fait d'abord tourner un simple programme Blink (seulement la LED intégrée) sait ensuite : ordinateur, câble, carte et outil sont en ordre. Tout le reste est alors le circuit ou le programme.

51.1 Connexion : la carte est introuvable

Symptôme Commande Interprétation Solution
Aucun port dans l'IDE Arduino/PlatformIO ls /dev/ttyUSB* /dev/ttyACM* avant et après le branchement rien de nouveau n'apparaît : le câble n'a que des lignes de charge, ou la carte est défectueuse essayer un autre câble de données
Port présent, Permission denied ls -l /dev/ttyUSB0, groups L'utilisateur n'est pas dans le groupe dialout sudo usermod -aG dialout $USER, se déconnecter et se reconnecter
Le port apparaît et disparaît aussitôt dmesg -w au branchement brltty accapare le port sudo apt remove brltty
Le port alterne entre ttyUSB0 et ttyUSB1 ls /dev/serial/by-id/ noms fixes via le numéro de série utiliser ce chemin au lieu de ttyUSB0
L'ESP32-S3 apparaît comme ttyACM0, autrement après le téléversement dmesg | tail l'USB natif redémarre Rechoisir le port après chaque téléversement
Windows : appareil « Inconnu » Gestionnaire de périphériques Pilote CH340/CP210x manquant installer le pilote adapté

51.2 Le téléversement échoue

Message Signification Solution
avrdude: stk500_getsync(): not in sync: resp=0x00 Le Nano ne répond pas Choisir la carte « Nano », processeur « ATmega328P (Old Bootloader) » (avec PlatformIO board = nanoatmega328 ; les clones ont souvent besoin de l'ancien bootloader) ; autre câble ; ne rien laisser branché sur les broches D0/D1
avrdude: ser_open(): can't open device Port occupé ou manquant Moniteur série ouvert ? Le fermer. Rechoisir le port
A fatal error occurred: Failed to connect to ESP32: Wrong boot mode detected L'ESP32 n'est pas en mode de chargement Maintenir la touche BOOT, appuyer brièvement sur RESET, relâcher BOOT, puis téléverser
Failed to connect … No serial data received Câble/port/boot Câble de données ; touche comme ci-dessus ; réduire le débit de téléversement (upload_speed = 115200)
A serial exception error occurred: Could not configure port Puce USB/pilote autre port, câble
Le téléversement réussit, le programme ne tourne pas Le mode de démarrage reste actif après le téléversement, appuyer sur RESET ; ne pas maintenir BOOT enfoncé
Sketch too big / region 'iram0_0_seg' overflowed Mémoire pleine Choisir un schéma de partition (ESP32) plus grand, réduire bibliothèques/polices
Comportement de l'ancien programme Le téléversement est-il vraiment terminé ? chercher dans la sortie « Hard resetting » ou « bytes written »

51.3 Compilation (compilateur)

La première erreur de la sortie est la vraie ; toutes les suivantes sont le plus souvent des erreurs en cascade.

Message Cause Solution
fatal error: X.h: No such file or directory Bibliothèque manquante installer dans le gestionnaire de bibliothèques ; PlatformIO : lib_deps
'X' was not declared in this scope Faute de frappe, variable hors de son bloc, en-tête manquant Vérifier l'orthographe (majuscules/minuscules !)
expected ';' before … Point-virgule manquant, le plus souvent dans la ligne précédente Regarder la ligne précédente
expected '}' at end of input Parenthèse non fermée Vérifier l'indentation ; fonction de l'éditeur « parenthèse correspondante »
multiple definition of … Fonction/variable dans deux fichiers dans l'en-tête, seulement déclarer (extern), définir une seule fois
undefined reference to … Fonction déclarée mais jamais définie / bibliothèque non incluse Ajouter la définition ; lib_deps
conflicting declaration deux bibliothèques du même nom en retirer une
Erreur seulement avec PlatformIO, pas dans l'IDE .ino a des prototypes automatiques, .cpp non Déclarer les fonctions avant utilisation, #include <Arduino.h>

51.4 Moniteur série

Symptôme Interprétation Solution
Bouillie de caractères (ÿþ…) Débit dans le moniteur ≠ Serial.begin(…) régler le même nombre (115200 contre 9600)
Rien dans le moniteur Le programme ne tourne pas, mauvais port, ESP32-S3 sans USB CDC on boot RESET ; vérifier le port ; option « USB CDC On Boot: Enabled »
Du texte seulement au démarrage, puis silence Le programme reste dans une boucle ou un delay poser des repères Serial.println("A"); et couper en deux (chapitre 47)
Redémarrage sans fin avec Guru Meditation Error / Brownout detector was triggered Reset dû à une erreur ou à l'alimentation Lire le texte d'erreur : Brownout = la tension s'effondre → meilleur câble/bloc, condensateur 100–470 µF ; LoadProhibited = pointeur invalide
rst:0x1 (POWERON_RESET) à répétition Alimentation ou erreur de programme voir ci-dessus
E (…) i2c: … Erreur I²C chapitre 51.6

51.5 Alimentation et niveaux

Question Mesurer/vérifier Remarque
La carte a-t-elle 5 V ou 3,3 V ? Multimètre sur VCC/GND USB 5 V, les broches de l'ESP32 travaillent à 3,3 V
Toutes les masses sont-elles reliées ? Test de continuité entre les points GND Sans masse commune, aucun signal ne fonctionne
Le consommateur reçoit-il assez ? Mesurer le courant Une broche ne fournit que quelques milliampères (Arduino env. 20 mA) ; moteurs, relais, rubans de LED demandent un étage de pilotage et leur propre alimentation
Signal 5 V sur une entrée 3,3 V ? Mesurer le niveau peut endommager l'ESP32/Pi → convertisseur de niveau ou diviseur de tension
Quelque chose chauffe-t-il ? Doigt/caméra thermique débrancher aussitôt ; court-circuit, polarité inversée
La LED ne s'allume pas Polarité, résistance série (par ex. 220 Ω à 5 V), mode de broche OUTPUT Patte longue = plus
Le bouton donne des valeurs aléatoires L'entrée flotte utiliser INPUT_PULLUP ; bouton vers GND
Le bouton rebondit (déclenché plusieurs fois) Serial.println à chaque appui Anti-rebond : temps de blocage de 20–50 ms
