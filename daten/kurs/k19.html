Mein erstes großes Projekt; mit der Bauform der Anzeige hat vieles angefangen.

19.1 Die Hardware

  • Waveshare RGB-LED-Matrix 64×32 = 2048 LEDs
  • HUB75-Flachbandkabel (viele Leitungen für Farben, Zeilenwahl und Takt)
  • getrennte Stromversorgung für das Panel (viel Strom!)
  • Steuerung durch: Raspberry Pi 4, ESP32-WROOM-32, ESP32-S3 oder Pico H

19.2 Die Bibliothek rpi-rgb-led-matrix auf dem Pi

sudo apt update
sudo apt install -y git python3-dev python3-pillow python3-pip build-essential
cd ~
git clone https://github.com/hzeller/rpi-rgb-led-matrix.git
cd ~/rpi-rgb-led-matrix
make build-python PYTHON=$(which python3)
sudo make install-python PYTHON=$(which python3)

Testen:

cd examples-api-use
sudo ./demo -D0 --led-rows=32 --led-cols=64

Wenn das Panel nichts anzeigt oder flackert:

sudo ./demo -D0 --led-rows=32 --led-cols=64 --led-slowdown-gpio=4

Die wichtigsten Optionen:

Option Bedeutung
--led-rows=32 Zeilen des Panels
--led-cols=64 Spalten des Panels
--led-chain=1 Anzahl hintereinander geschalteter Panels
--led-slowdown-gpio=4 GPIO langsamer machen (hilft bei schnellem Pi und flackerndem Bild)
--led-no-hardware-pulse Hardware-Puls aus (wenn Ton aktiv ist)

19.3 Eigenen C++-Code kompilieren

cd ~/Desktop/RGB-Matrix-Px-xx/example/Rasberry-Pi/examples-api-use
g++ -Wall -O3 -I../include nature.cc -o nature -L../lib -lrgbmatrix -lrt -lm -lpthread
sudo ./nature --led-rows=32 --led-cols=64 --led-chain=1 --led-slowdown-gpio=4 --led-no-hardware-pulse

Zerlegt:

  • g++ – der C++-Compiler
  • -O3 – schnell optimieren
  • -I../include – hier liegen die Header-Dateien
  • nature.cc -o nature – aus nature.cc wird das Programm nature
  • -L../lib -lrgbmatrix – die Bibliothek zum Verlinken
  • sudo – die Matrix braucht direkten Zugriff auf die Pins

Fehler, die mir begegnet sind:

  1. 'cos' was not declared in this scope → es fehlt #include <cmath> ganz oben.
  2. Ein Fehler mit .red, .green, .blue → bei der Version der Bibliothek heißen sie .r, .g, .b. Gelöst mit: sed -i 's/\.red/.r/g; s/\.green/.g/g; s/\.blue/.b/g' arcade.cc
  3. Ein Programm startet nicht → die ganze Fehlermeldung lesen, meist ein Tippfehler in einer Zeile.

19.4 Mein „Oratio"-Display

Das Beispielprojekt: Das Display zeigt zuerst meinen Namen bunt wie ein Regenbogen auf schwarzem Hintergrund, danach Seiten mit Wetter, Uhrzeit und Datum und dann Effekte. Die Erfahrungen dazu:

  • Weiß in den Farben macht die Schrift zu hell, nimm nur kräftige Farben.
  • Zu dicke Schrift lässt die Buchstaben zusammenkleben, lieber etwas dünner.
  • Effektszenen: matrixRain, cyberText, fireworks, scanner, „Oratio Cosmos" mit Feuerhimmel und Partikeln.

Das Ausführen lässt sich mit einem Alias oder einem Start-Script vereinfachen.

19.5 Pico H und ESP32-S3

  • Raspberry Pi Pico H kann Animationen, Uhr ab einem festen Wert, Lauftext und feste Bilder, aber kein Internet und keine IP-Anzeige. Er braucht den PIO-Treiber, also Dateien wie hub75.pio und CMakeLists.txt. Ohne die Treiberdateien lässt sich kein funktionierender Code erfinden. Mit find . -iname "*pico*" -o -iname "*.pio" findet man sie im Beispielordner.
  • ESP32-S3 von Waveshare hat eine feste Pinbelegung für HUB75, die man aus der Dokumentation übernehmen muss, nicht aus dem Gedächtnis:
HUB75 GPIO HUB75 GPIO
R1 1 A 7
G1 2 B 15
B1 3 C 16
R2 4 D 42
G2 5 E 46
B2 6 CLK 41
LAT 40
OE 39

Wichtig: Diese Belegung gilt für das ESP32-S3-Board. Mein ESP32-WROOM-32 hat andere Pins. Wer hier die falsche Tabelle benutzt, bekommt kein Bild.

19.6 Rechenbeispiel: wie viele Panels wären 4K?

Ein 64×32-Panel hat 2048 Pixel. Für 3840 Pixel Breite: 3840 ÷ 64 = 60 Panels. Für 2160 Pixel Höhe: 2160 ÷ 32 = 67,5, also 68 Reihen. Das wären 60 × 68 = 4080 Panels, etwa 11,5 m × 6,5 m groß. Ein schönes Beispiel dafür, wie man mit einer Überschlagsrechnung die Machbarkeit prüft.
