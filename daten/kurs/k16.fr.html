16.1 Notions de base

  • Sketch – un programme Arduino (fichier avec l'extension .ino)
  • setup() – s'exécute une fois au démarrage
  • loop() – s'exécute ensuite en boucle
  • Carte / FQBN – le nom de la carte, par exemple arduino:avr:nano
  • Port – l'interface USB, le plus souvent /dev/ttyUSB0 ou /dev/ttyACM0
  • Bibliothèque (library) – du code tout fait pour un composant

16.2 Le premier programme : le clignotement

void setup() {
  pinMode(LED_BUILTIN, OUTPUT);
}

void loop() {
  digitalWrite(LED_BUILTIN, HIGH);
  delay(1000);
  digitalWrite(LED_BUILTIN, LOW);
  delay(1000);
}

pinMode configure la broche en sortie, digitalWrite l'allume ou l'éteint, delay(1000) attend 1000 millisecondes. Quand la LED intégrée clignote, toute la chaîne fonctionne : programme, compilateur, téléversement et carte.

16.3 Arduino CLI sur le Raspberry Pi

L'ancien Arduino IDE 1.0 m'a posé des problèmes sur le Pi : les bibliothèques Adafruit BusIO et GFX ne fonctionnaient pas correctement, et la désinstallation était difficile (il avait été installé avec « Pi Apps »). La meilleure solution a été arduino-cli, un programme pour le terminal.

Installation :

curl -fsSL https://raw.githubusercontent.com/arduino/arduino-cli/master/install.sh | sh
sudo mv bin/arduino-cli /usr/local/bin/
arduino-cli version

Installer le paquet de cartes :

arduino-cli core update-index
arduino-cli core install arduino:avr

Chercher la carte :

arduino-cli board list

Mon clone de Nano est apparu comme /dev/ttyUSB0, mais comme « Inconnu ». C'est normal pour beaucoup de clones de Nano.

Installer les bibliothèques :

arduino-cli lib install "Adafruit SSD1306"
arduino-cli lib install "Adafruit GFX Library"

Créer le projet, compiler, téléverser :

mkdir ~/OLED_Test
cd ~/OLED_Test
nano OLED_Test.ino
arduino-cli compile --fqbn arduino:avr:nano:cpu=atmega328old .
arduino-cli upload -p /dev/ttyUSB0 --fqbn arduino:avr:nano:cpu=atmega328old .

L'astuce importante du bootloader : beaucoup de clones de Nano ont besoin de :cpu=atmega328old (ancien bootloader). Si le téléversement échoue, la variante sans cet ajout aide :

arduino-cli compile --fqbn arduino:avr:nano .
arduino-cli upload -p /dev/ttyUSB0 --fqbn arduino:avr:nano .

Le point . à la fin signifie « le sketch du dossier actuel ».

16.4 Ordre : un dossier par projet

Chaque projet a son propre dossier, et le fichier .ino porte le même nom que le dossier :

/home/oratio/
├── OLED_Test/
│   └── OLED_Test.ino
├── Blink_Test/
│   └── Blink_Test.ino
├── Uhr_Projekt/
│   └── Uhr_Projekt.ino
└── Wetterstation/
    └── Wetterstation.ino

Les commandes de compilation et de téléversement restent toujours les mêmes tant que la même carte et le même port sont utilisés. Seul le dossier change :

cd ~/Uhr_Projekt
arduino-cli compile --fqbn arduino:avr:nano:cpu=atmega328old .
arduino-cli upload -p /dev/ttyUSB0 --fqbn arduino:avr:nano:cpu=atmega328old .

Ce n'est qu'avec une autre carte (ESP32, Uno, Mega) ou un autre port (ttyUSB1) qu'il faut modifier les commandes.

16.5 L’écran OLED SSD1306 (128×64, I²C)

Câblage Nano ↔︎ OLED :

Écran Arduino Nano
GND GND
VCC 5 V
SCL A5
SDA A4

Programme d'exemple :

#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>

#define SCREEN_WIDTH 128
#define SCREEN_HEIGHT 64

Adafruit_SSD1306 display(SCREEN_WIDTH, SCREEN_HEIGHT, &Wire, -1);

void setup() {
  Wire.begin();

  if (!display.begin(SSD1306_SWITCHCAPVCC, 0x3C)) {
    while (true);
  }

  display.clearDisplay();
  display.setTextSize(1);
  display.setTextColor(SSD1306_WHITE);

  display.setCursor(0, 0);
  display.println("Hallo Oratio");
  display.setCursor(0, 15);
  display.println("Arduino Nano");

  display.display();
}

void loop() {
}

Les commandes les plus importantes pour l'écran :

Commande Effet
display.clearDisplay() Effacer la mémoire d'image
display.setTextSize(2) Taille de la police
display.setCursor(x, y) Position du texte en pixels
display.println("Text") Écrire du texte
display.setRotation(1) Faire pivoter l'image (0–3)
display.display() tout dessiner (sans cette commande l'écran reste vide !)

Leçon « Écran cassé ? » : quand on ne lit rien, l'écran est le plus souvent en bon état. L'écriture est simplement trop petite (setTextSize(1)) et l'image en mode portrait. Avec setRotation(1) et setTextSize(2) ou 3, le texte devient bien lisible. Vérifier d'abord si le logiciel est mal réglé avant de soupçonner le matériel.

16.6 Pourquoi l’écran était-il vide la deuxième fois ?

Pourquoi l'écran reste-t-il parfois vide ? Voici le lien : la mémoire d'image de l'écran est vidée avec clearDisplay(), et c'est seulement display.display() qui la transfère à l'écran. Si cela manque, l'écran reste vide ou affiche encore quelque chose du programme précédent.

16.7 Une autre bibliothèque : U8g2

Quand les bibliothèques Adafruit posent problème, U8g2 est une alternative qui se passe souvent d'Adafruit GFX :

#include <Wire.h>
#include <U8g2lib.h>

U8G2_SSD1306_128X64_NONAME_F_HW_I2C u8g2(U8G2_R0);

void setup() {
  u8g2.begin();
  u8g2.clearBuffer();
  u8g2.setFont(u8g2_font_ncenB08_tr);
  u8g2.drawStr(0, 20, "Hallo");
  u8g2.sendBuffer();
}

void loop() {}

16.8 Faire travailler ensemble Raspberry Pi et Arduino

Il existe plusieurs façons de rendre un Nano avec écran « intelligent » :

  1. Le Pi comme cerveau : le Pi récupère l'heure, la météo, la température du CPU et l'IP et les envoie par USB (série) au Nano, qui les affiche. Si l'on débranche le Pi, plus aucune nouvelle donnée n'arrive.
  2. Régler une seule fois : le Pi règle l'horloge, puis le Nano fonctionne seul. Mais l'heure se perd après une coupure de courant et dérive.
  3. Horloge temps réel (RTC, par exemple DS3231) : le Nano garde l'heure même sans courant et sans Pi. C'est la bonne solution pour une horloge autonome.

16.9 Voir et sauvegarder des programmes : avrdude

Peut-on sauvegarder un programme depuis l'Arduino ? Oui, avec avrdude :

avrdude -c arduino -p m328p -P /dev/ttyUSB0 -b 115200 -U flash:r:backup.hex:i    # auslesen
avrdude -c arduino -p m328p -P /dev/ttyUSB0 -b 115200 -U flash:w:backup.hex:i    # zurückschreiben

(Sous Windows le port s'appelle COM3, sur le Pi /dev/ttyUSB0.) Important : on n'obtient que la version compilée (.hex), pas le code source (.ino). Elle suffit pour transférer le projet sur un autre Arduino. Si le bit de verrouillage est activé, la puce ne peut pas être lue.
