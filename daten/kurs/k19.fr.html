Mon premier grand projet ; beaucoup de choses ont commencé avec la forme de l'affichage.

19.1 Le matériel

  • Matrice LED RGB Waveshare 64×32 = 2048 LED
  • Câble plat HUB75 (nombreuses lignes pour les couleurs, la sélection de ligne et l'horloge)
  • alimentation séparée pour le panneau (beaucoup de courant !)
  • Pilotage par : Raspberry Pi 4, ESP32-WROOM-32, ESP32-S3 ou Pico H

19.2 La bibliothèque rpi-rgb-led-matrix sur le Pi

sudo apt update
sudo apt install -y git python3-dev python3-pillow python3-pip build-essential
cd ~
git clone https://github.com/hzeller/rpi-rgb-led-matrix.git
cd ~/rpi-rgb-led-matrix
make build-python PYTHON=$(which python3)
sudo make install-python PYTHON=$(which python3)

Tester :

cd examples-api-use
sudo ./demo -D0 --led-rows=32 --led-cols=64

Si le panneau n'affiche rien ou scintille :

sudo ./demo -D0 --led-rows=32 --led-cols=64 --led-slowdown-gpio=4

Les options les plus importantes :

Option Signification
--led-rows=32 Lignes du panneau
--led-cols=64 Colonnes du panneau
--led-chain=1 Nombre de panneaux chaînés
--led-slowdown-gpio=4 Ralentir les GPIO (aide avec un Pi rapide et une image qui scintille)
--led-no-hardware-pulse Désactiver l'impulsion matérielle (quand le son est actif)

19.3 Compiler son propre code C++

cd ~/Desktop/RGB-Matrix-Px-xx/example/Rasberry-Pi/examples-api-use
g++ -Wall -O3 -I../include nature.cc -o nature -L../lib -lrgbmatrix -lrt -lm -lpthread
sudo ./nature --led-rows=32 --led-cols=64 --led-chain=1 --led-slowdown-gpio=4 --led-no-hardware-pulse

Décomposé :

  • g++ – le compilateur C++
  • -O3 – optimiser pour la vitesse
  • -I../include – les fichiers d'en-tête se trouvent ici
  • nature.cc -o nature – de nature.cc naît le programme nature
  • -L../lib -lrgbmatrix – la bibliothèque à lier
  • sudo – la matrice a besoin d'un accès direct aux broches

Erreurs rencontrées :

  1. 'cos' was not declared in this scope → il manque #include <cmath> tout en haut.
  2. Une erreur avec .red, .green, .blue → dans cette version de la bibliothèque ils s'appellent .r, .g, .b. Résolu avec : sed -i 's/\.red/.r/g; s/\.green/.g/g; s/\.blue/.b/g' arcade.cc
  3. Un programme ne démarre pas → lire tout le message d'erreur, c'est le plus souvent une faute de frappe dans une ligne.

19.4 Mon écran « Oratio »

Le projet d'exemple : l'écran affiche d'abord mon nom en couleurs d'arc-en-ciel sur fond noir, puis des pages avec la météo, l'heure et la date, puis des effets. Les enseignements :

  • Le blanc dans les couleurs rend l'écriture trop claire, utilisez seulement des couleurs vives.
  • Une écriture trop épaisse fait coller les lettres, mieux vaut un peu plus fin.
  • Scènes d'effets : matrixRain, cyberText, fireworks, scanner, « Oratio Cosmos » avec ciel de feu et particules.

L'exécution peut être simplifiée par un alias ou un script de démarrage.

19.5 Pico H et ESP32-S3

  • Raspberry Pi Pico H sait faire des animations, une horloge à partir d'une valeur fixe, du texte défilant et des images fixes, mais pas d'Internet ni d'affichage de l'IP. Il lui faut le pilote PIO, donc des fichiers comme hub75.pio et CMakeLists.txt. Sans les fichiers du pilote, on ne peut pas inventer de code fonctionnel. Avec find . -iname "*pico*" -o -iname "*.pio" on les trouve dans le dossier d'exemple.
  • L'ESP32-S3 de Waveshare a un brochage fixe pour HUB75, qu'il faut reprendre de la documentation et non de mémoire :
HUB75 GPIO HUB75 GPIO
R1 1 A 7
G1 2 B 15
B1 3 C 16
R2 4 D 42
G2 5 E 46
B2 6 CLK 41
LAT 40
OE 39

Important : ce brochage vaut pour la carte ESP32-S3. Mon ESP32-WROOM-32 a d'autres broches. Avec le mauvais tableau, pas d'image.

19.6 Exemple de calcul : combien de panneaux pour de la 4K ?

Un panneau 64×32 a 2048 pixels. Pour 3840 pixels de large : 3840 ÷ 64 = 60 panneaux. Pour 2160 pixels de haut : 2160 ÷ 32 = 67,5, donc 68 rangées. Cela ferait 60 × 68 = 4080 panneaux, environ 11,5 m × 6,5 m. Un bel exemple de la façon dont un calcul d'ordre de grandeur permet de vérifier la faisabilité.
