Ce chapitre est placé à un seul endroit pour ne pas devoir être répété dans chaque chapitre de projet. Ce sont les choses que j'ai réapprises sans cesse dans des projets très différents – Pi, microcontrôleur, Control Center, Steam Deck, Windows. Pour chaque point est indiqué où il est devenu important pour la première fois.

46.2 Fichiers, droits, chemins

  • Droits : les fichiers créés avec sudo appartiennent à root ; le programme en tant qu'utilisateur normal n'a pas le droit de les écrire. Vérifier le propriétaire (ls -l), le changer avec chown (chapitre 2). Conséquence dans le Control Center : la fenêtre tourne sans sudo (chapitre 32.5).
  • Rendre les chemins absolus : BASE_DIR = os.path.dirname(os.path.abspath(__file__)). Les chemins relatifs cassent dès que le programme démarre depuis un autre dossier (icône du bureau, démarrage automatique).
  • Une copie avant chaque modification : cp datei datei.bak ; surtout pour cmdline.txt, config.txt, fstab, mais aussi pour tout fichier Python un peu gros.
  • Vérifier la syntaxe avant de lancer : python3 -m py_compile datei.py, bash -n skript.sh, python3 -m json.tool datei.json.
  • Fins de ligne Windows (^M, bad interpreter) : sed -i 's/\r$//' datei.
  • Ne jamais mélanger tabulations et espaces (TabError) : dans l'éditeur, convertir les tabulations en espaces, ou expand -t 4 (chapitre 32.4).

46.4 Architecture et plateforme

  • Ne jamais copier des fichiers de programme entre des appareils d'architecture différente. uname -m : aarch64 = Pi (ARM), x86_64 = Deck/PC. Les scripts (Python, Bash) ne posent pas de problème, les binaires oui (Exec format error, chapitre 43.6.4).
  • Une seule détection, tout ce qui est propre à l'appareil derrière : un dossier pour le Pi et le Deck, plattform.py reconnaît l'appareil (chapitre 43.3).
  • Les commandes ne sont pas les mêmes partout : apt (Pi), pacman (SteamOS), winget (Windows) ; lxterminal (Pi) contre konsole (KDE). Toujours demander d'abord command -v.
  • Deux familles de fenêtres noires : Windows (CMD) et Linux (bash) comprennent des commandes différentes (chapitre 25, 28.3). Avant de taper, demander : dans quel système suis-je ?

46.6 Sécurité des données

  1. Avant mkfs, parted, fdisk, dd : exécuter lsblk et reconnaître le disque à sa taille, pas à son nom.
  2. Avant rm -r : vérifier le chemin avec ls.
  3. Jamais le disque système comme cible : les programmes qui peuvent effacer des disques ne le proposent même pas (chapitre 39.2).
  4. Ne jamais brancher l'original et la copie en même temps sur un ordinateur (mêmes identifiants, chapitre 28.12).
  5. Sauvegarde des réglages : chaque jour automatiquement (chapitre 36.4), plus les profils (chapitre 38.13).
  6. Scripts d'Internet (curl … | sh) seulement depuis des sites officiels.

46.7 Matériel et alimentation

  • L'alimentation d'abord : un bloc d'alimentation trop faible produit des erreurs apparemment aléatoires. vcgencmd get_throttled sur le Pi ; les matrices de LED et les moteurs ont leur propre alimentation.
  • Relier la masse (GND) partout.
  • Vérifier la tension : 3,3 V ou 5 V ? Une entrée 3,3 V ne supporte pas 5 V (chapitre 38.5, 51).
  • Câble de données contre câble de charge : certains câbles USB n'ont pas de lignes de données. L'appareil n'apparaît alors nulle part (chapitre 28.10, 51).
  • Ne jamais alimenter servos et moteurs par le Pi.

46.8 Écrire et transmettre

  • Mises à jour en ZIP avec seulement les fichiers modifiés dans l'arborescence ; pour une sauvegarde complète, tout fournir.
  • Noter quelle était la solution : c'est précisément pour cela que ce livre existe.
  • Dire honnêtement ce qui n'a pas été testé. Dans cette documentation, pour beaucoup de fonctions, il est indiqué ce qui n'a été vérifié qu'en essai à blanc ou dans un environnement de test et ce qui reste à vérifier sur du vrai matériel (clone de sauvegarde, point d'accès, caméra, audio, cadran).
