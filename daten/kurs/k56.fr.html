56.1 Écran, Wayland et Kanshi

failed to connect to display

Signification : wlr-randr ou un autre outil Wayland tourne sous X11 (ou sans session de bureau).

Solution : vérifier avec echo $XDG_SESSION_TYPE quel système tourne. Sous Wayland vaut wlr-randr, sous X11 vaut xrandr. Par SSH, l'environnement Wayland doit être défini (chapitre 10.3).

unexpected '{' in output et failed to parse config file: error on line 2, column 21

Signification : la version installée de Kanshi ne connaît pas l'écriture avec accolades après output HDMI-A-1. Kanshi ne démarre donc pas (Exit 1 kanshi, ps aux | grep kanshi n'affiche rien).

Solution : utiliser l'ancienne écriture, avec des accolades seulement autour du profil :

profile {
    output HDMI-A-1 scale 3
}

Puis lancer kanshi dans le terminal et guetter applying profile.

L'échelle est de nouveau fausse après redémarrage ou changement de moniteur

Le réglage n'est pas enregistré. Solution : Kanshi avec démarrage automatique plus script Watchdog (chapitre 10.6).

La commande agit, mais après le redémarrage tout est réinitialisé

wlr-randr n'agit que pour la session en cours. Pour durer, il faut Kanshi ou une entrée dans ~/.config/labwc/autostart.

56.2 Démarrage et boot

Device-tree file 'bcm2712-rpi-5-b.dtb' not found et The installed operating system (OS) does not indicate support for Raspberry Pi 5

Le système sur le support n'est pas construit pour le Pi 5 (BCM2712), le plus souvent une image Pi 4 (BCM2711). Vérifier : sur la partition de démarrage doit se trouver bcm2712-rpi-5-b.dtb. Écrire la bonne image (chapitre 26.3).

USB boot requires high current (5 volt 5 amp) power supply

Le Pi 5 exige pour le démarrage USB un bloc d'alimentation 5 V/5 A. Utiliser le bloc officiel de 27 watts.

C'est toujours le mauvais système qui démarre (SD avant NVMe)

Changer l'ordre de démarrage dans raspi-config (Advanced Options, Boot Order, B2 NVMe/USB Boot) ou, au démarrage, appuyer sur la barre d'espace pour le menu de démarrage (chapitre 26.7 et 26.8).

Symbole d'éclair, saccades, redémarrages, Under-voltage detected

Sous-tension. vcgencmd get_throttled montre l'état (0x0 est correct). Solution : bloc d'alimentation de puissance suffisante et bon câble ; même avec des blocs de 35 watts d'autres fabricants, le Pi peut signaler « pas assez de courant » s'ils ne fournissent pas le palier de tension requis.

56.3 Disques

/dev/nvme0n1 does not exist

Le SSD NVMe n'est pas reconnu. lsblk montre sous quel nom il apparaît (via USB par exemple sda). Vérifier alors câble, adaptateur, réglages PCIe et alimentation.

Read Capacity(10) failed et sda 0B

Le Pi reconnaît l'adaptateur USB, mais le SSD annonce 0 octet. Ce n'est pas un problème de formatage. Vérifier les causes dans cet ordre : le SSD n'est pas bien en place dans le boîtier, l'adaptateur ne supporte pas ce SSD, SSD défectueux. Remettre le SSD, essayer un autre adaptateur, regarder de nouveau lsblk.

invalid token: exfat (avec parted ... mkpart primary exfat)

parted ne connaît pas exfat comme type de partition. Créer la partition avec fat32 comme désignation, puis la formater réellement avec mkfs.exfat :

sudo parted /dev/sda --script mkpart primary fat32 0% 100%
sudo apt install exfatprogs
sudo mkfs.exfat /dev/sda1

fdisk: cannot open /dev/sda: Das Argument ist ungültig

La commande a été saisie avec un mauvais caractère : fdisk -l (L minuscule), pas -I. Appeler sans disque : sudo fdisk -l ou sudo parted -l.

umount: /dev/sda1: not mounted

Pas d'erreur. Le disque était déjà démonté.

mount: ... wrong fs type, bad option, bad superblock

Le système de fichiers manque ou ne convient pas. Le regarder avec lsblk -f. S'il manque, formater (attention, efface toutes les données) : sudo mkfs.ext4 /dev/sda1.
