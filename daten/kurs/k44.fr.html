44.1 Idée

Le site est un site web statique : du pur HTML, CSS et JavaScript, sans serveur et sans base de données. Le navigateur charge les fichiers et exécute lui-même les programmes (calculatrices, outils, cours). Il n'y a ainsi rien à maintenir, rien à pirater, et l'hébergement est gratuit.

Pourquoi ainsi ? Les contenus (tables d'électronique, comparatifs, glossaire) existaient déjà sous forme de fichiers JSON dans l'Atlas du Control Center (chapitre 39.6). Un site web n'a qu'à les afficher. Il n'est donc pas né de deuxième projet, mais une deuxième présentation des mêmes données.

Les cinq mondes : Tech Studio, monde de Noël, Lifestyle, cours d'allemand, outils. Tout est entièrement bilingue (allemand/français ; les textes français se trouvent dans daten/sprache_fr.json). L'en-tête s'appelle « Oratio Place » sur chaque page.

Pourquoi les bibliothèques sont en local : une page qui charge des scripts depuis des serveurs étrangers cesse de fonctionner quand ce serveur disparaît, et transmet des données sur les visiteurs. Les fichiers locaux évitent les deux.

44.4 bauen_web.py – générer les données

Le script lit les fichiers de monde de l'Atlas (Oratio_Menu/Apps/Oratio_Atlas/Daten/welt_*.json), les copie dans daten/ et produit les index de recherche (index.json, suche.json). Le déroulement :

  1. Déterminer la source : dossier à côté du dossier web, ou la variable d'environnement ATLAS_ORDNER.
  2. Pour chaque welt_*.json : lire, copier, inscrire nom/sous-titre/couleur dans la liste des mondes.
  3. Rassembler les textes des pages en un pur texte de recherche avec une fonction flach(...) (les brochages, cercles et diagrammes temporels sont omis, parce qu'ils ne sont que des données de dessin).
  4. Écrire l'index et la recherche (json.dump(..., separators=(",", ":")) = sans espaces, économise de la place).

44.5 Mettre à jour

  1. Modifier les contenus dans le Control Center (fichiers de l'Atlas).
  2. Dans le dossier web, exécuter python3 bauen_web.py.
  3. Ne téléverser dans le dépôt que les fichiers modifiés.
  4. Sur GitHub, sous Settings → Pages, vérifier que le domaine oratioplace.com est bien inscrit.

Quand un nouveau dépôt est créé : le domaine doit être réinscrit dans les réglages de Pages, et le DNS chez Porkbun doit continuer de pointer vers GitHub Pages. Sans ces deux étapes, le site n'est plus joignable sous le domaine après le déménagement.

44.6 Oratio Desk

desk.html est un écran d'accueil dans le navigateur sur le modèle du Control Center : pages à balayer, tuiles en grille, widgets, applications dans des fenêtres, dock, fonds et styles au choix (clair, sombre, verre). Les fichiers :

Fichier Contenu
werkzeuge/desk.js Noyau : état, grille, édition, fenêtres (« applications »), fonds, sauvegarde
werkzeuge/desk_c.js Calculatrice (standard, scientifique, conversion) comme widget et comme application
werkzeuge/desk_t.js Application horloge (heure mondiale, réveil, chronomètre, minuteur), les widgets correspondants et focus (Pomodoro)
werkzeuge/desk_w.js autres widgets et applications : calendrier, horloge analogique, tâches, notes, compte à rebours, habitudes, eau, liens, appareil, dé

Important : tout reste dans le navigateur (localStorage). Rien n'est envoyé, et il n'y a aucun accès au Pi. Le Desk montre à quoi ressemble l'utilisation et offre de petits outils qui tournent dans le navigateur. Une indication clignotante « NEU » mène au Desk depuis la page d'accueil.

Idée de construction : un noyau (desk.js) fournit des fonctions auxiliaires et un registre (Desk.u, Desk.data()) ; les autres fichiers y déclarent leurs widgets. C'est le même schéma que « un fichier par widget » dans le Control Center (chapitre 37.4).

44.7 Ce que ce projet m’a appris

  • Séparer les données et l'affichage : comme le contenu est en JSON, un script suffit pour montrer les mêmes données à deux endroits.
  • Statique est stable : pas de base de données, pas de serveur, pas de maintenance.
  • Livrer tout le nécessaire : police, bibliothèques, images se trouvent dans le même dépôt.
  • Ne pas tout téléverser : après une modification, ne remplacer que les fichiers modifiés.
