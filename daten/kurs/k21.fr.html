21.1 Le matériel

Le Waveshare ESP32-S3-Touch-AMOLED-1.75 est un écran rond de 466 × 466 pixels, piloté par quatre lignes de données (QSPI). Le contrôleur s'appelle CO5300. Le processeur ESP32-S3 dispose de 8 Mo de PSRAM (mémoire externe), nécessaire pour le tampon d'image.

Signal GPIO
CS 12
SCK 38
D0 / D1 / D2 / D3 4 / 5 / 6 / 7
RST 39

Réglages dans l'IDE Arduino : mettre PSRAM sur « OPI PSRAM », sinon la mémoire ne suffit pas pour le tampon d'image. Le décalage de colonne du contrôleur est 6 (COL_OFFSET 6), sinon l'image est décalée.

21.2 Structure du logiciel

Arduino_DataBus *bus = new Arduino_ESP32QSPI(12, 38, 4, 5, 6, 7);
Arduino_GFX *gfx = new Arduino_CO5300(bus, 39, 0, 466, 466, 6, 0, 0, 0);

Arduino_GFX est la bibliothèque graphique. Le bus transmet, la classe Arduino_CO5300 connaît les commandes du contrôleur.

21.3 Comment naît le cadran 1:1

Objectif : le cadran d'une montre numérique Casio doit avoir exactement le même aspect sur l'écran. Le calcul :

  1. Le modèle est recadré ; le centre du cadran se trouve en (324, 295) dans la découpe, l'échelle est 0,6 (unités du modèle → pixels de l'écran).
  2. Un script Python (PIL) dessine le fond et les glyphes en résolution quadruple (suréchantillonnage) et les réduit – cela lisse les bords.
  3. Les chiffres sont des masques à sept segments : grand 50×96 (épaisseur de trait 13,5), secondes 33×60 (9), date 25×45 (7,4). Les jours de la semaine ont leur propre police en capitales.
  4. Le cadre est créé avec une transformée de distance (scipy) : la distance au bord extérieur détermine les bandes de couleur.
  5. Le script écrit des en-têtes C (face_bg.h, glyphs.h, layout.h) qui sont intégrés au programme sous forme de tableaux RGB565.
  6. Le sketch dessine le fond une fois, incruste chaque seconde les masques dans la bonne couleur (masque alpha) et rend le tout dans un tampon PSRAM qui part d'un seul coup vers l'écran.

RGB565 : 5 bits de rouge, 6 de vert, 5 de bleu, soit 16 bits par pixel – moitié moins que 24 bits et courant pour les écrans.

Vérification : un petit programme C++ sur l'ordinateur avec les mêmes fonctions a confirmé que la sortie du sketch est identique au pixel près à l'aperçu Python. Aucun test sur le vrai matériel. Le Wi-Fi et NTP pour l'heure sont facultatifs ; l'indicateur de batterie est fixé à 100 %, la liaison avec la puce d'alimentation AXP2101 reste à faire.

21.4 Évaluation du sketch `Oratio_Casio_Watch.ino`

  • Points positifs : interrupteur tactile, compteur de pas, structure claire.
  • Problèmes : les coins de l'écran rond sont coupés (contenu trop à l'extérieur) ; certains libellés sont masqués ; les broches diffèrent de celles des exemples Waveshare ; setBrightness() peut provoquer une erreur de compilation selon le pilote.
  • Décision en suspens : reprendre l'interrupteur tactile et le compteur de pas dans le cadran 1:1 ; et déterminer si la carte est la variante 1.75 ou 1.75C.
