33.1 Der Name des neuen Tabs

Nach dem Skript-Tab kam der Wunsch nach einem Tab nur für Raspberry-Pi-Befehle, die ich ständig brauche: Bildschirm auf 4K stellen, Temperatur lesen, neu starten. Vor dem Bauen musste der Name feststehen, weil er in Dateien, Klassen und Beschriftungen wiederkehrt. Meine Überlegungen:

Kandidat Bewertung
„Tools“ zu allgemein, sagt nicht, dass es um den Pi geht
„Commander“ klingt nach Dateiverwaltung (wie ein Zwei-Fenster-Dateimanager)
„Oratio Pi Tools“ trägt meinen Namen wie die anderen Teile und sagt, worum es geht

Namensregel für Dateien und Klassen, die ich mir dabei gesetzt habe:

  • Dateien und Module in Python klein mit Unterstrich: pi_tools.py.
  • Klassen in „CamelCase“, ohne Unterstrich: PiToolsTab.
  • Ordnernamen dürfen groß beginnen: Pi_Tools/.
  • Was in der Oberfläche steht („Oratio Pi Tools“, mit Leerzeichen), ist nur ein Text, den man an einer Stelle als Tab-Namen einträgt. Er muss nichts mit dem Dateinamen zu tun haben.

from pi_tools import PiTools heißt: aus der Datei pi_tools.py die Klasse PiTools holen. Das erste Wort ist die Datei (das Modul), das zweite die Klasse darin.

33.2 Ein Tab mit festen Buttons

Der erste Entwurf bestand aus einer Klasse mit Schaltflächen und je einer Funktion pro Befehl:

class RaspberryPiTab(QWidget):
    def __init__(self):
        super().__init__()
        layout = QGridLayout()
        btn_4k = QPushButton("4K Scale 3")
        btn_reboot = QPushButton("Neustart")
        btn_temp = QPushButton("Temperatur")
        layout.addWidget(btn_4k, 0, 0)
        layout.addWidget(btn_reboot, 0, 1)
        layout.addWidget(btn_temp, 1, 0)
        self.setLayout(layout)
        btn_4k.clicked.connect(self.set_4k)
        btn_reboot.clicked.connect(self.reboot)
        btn_temp.clicked.connect(self.temp)

    def set_4k(self):
        subprocess.Popen(["wlr-randr", "--output", "HDMI-A-1",
                          "--mode", "3840x2160", "--scale", "3"])

    def reboot(self):
        subprocess.Popen(["lxterminal", "-e", "sudo reboot"])

    def temp(self):
        subprocess.Popen(["lxterminal", "-e", "vcgencmd measure_temp"])

Das funktioniert. Das Problem zeigt sich bei Befehl 20: Die Klasse bekommt für jeden Befehl eine Funktion, der Code wird unübersichtlich, und jede neue Schaltfläche heißt Python-Code ändern.

33.3 Die Daten in eine JSON-Datei

JSON ist ein Textformat für Listen und Einträge. Statt jede Schaltfläche in Python zu schreiben, steht in einer Datei, was es gibt. Der Python-Code liest die Datei und baut die Schaltflächen:

[
    {"name": "Backup", "file": "backup.py"},
    {"name": "Hash",   "file": "hashchecker.sh"},
    {"name": "Kanshi", "type": "import"},
    {"name": "OLED",   "file": "OLED/oled.py"}
]
with open("oratio_apps.json", "r") as f:
    apps = json.load(f)
for i, app in enumerate(apps):
    ...   # pro Eintrag eine Kachel anlegen

Folgen, die ich bemerkte:

  • Die Anzahl der Kacheln steht nicht mehr im Programm. 25 Einträge ergeben 25 Kacheln, 30 ergeben 30.
  • Die Position kommt ebenfalls aus der Datei: "row" und "col" (später "slot"). Zwei Einträge auf demselben Platz überdecken sich, der zuletzt angelegte liegt oben.
  • JSON verlangt genaue Syntax: Anführungszeichen, Kommas zwischen den Einträgen, keines nach dem letzten. Ein vergessenes Komma lässt die ganze Datei scheitern. Prüfen: python3 -m json.tool oratio_apps.json.

33.4 Zwei Arten, ein Programm zu öffnen

Ein Eintrag kann auf zwei Arten starten, und die Wahl hat sichtbare Folgen:

Art Wie Wann sinnvoll
run_file() startet einen neuen Prozess (subprocess.Popen) Skripte: Hash-Checker, Backup, Bash- und PowerShell-Skripte
"type": "import" importiert die Klasse und öffnet sie im laufenden Programm kleine Dialoge: Kanshi, Info-Fenster

Beim Kanshi-Dialog sah ich den Unterschied sofort: Mit run_file erschien zusätzlich ein zweites Fenster, weil ein ganzes zweites Python-Programm startete. Mit dem Import öffnet sich nur der Dialog:

if app.get("type") == "import" and app["name"] == "Kanshi3":
    dialog = KanshiDialog()
    dialog.exec_()
    return

Faustregel: Oberfläche = importieren, Skripte = als Prozess starten.

33.7 Das Aussehen: Farben und Rundungen im Stylesheet

Die Oberfläche bekam eine Optik über Qt-Stylesheets (ähnlich CSS):

btn.setStyleSheet("""
    QPushButton {
        background-color: #1a73e8;
        border-radius: 12px;
        font-size: 14pt;
    }
""")

Fragen, die dabei aufkamen und beantwortet sind:

  • px oder pt? px sind Bildschirmpunkte, pt sind Schriftpunkte, die sich mit der Skalierung ändern. Schriftgrößen in pt, Abstände und Rundungen in px.
  • Doppelte Klammern {{ }} in einem f-String: Ein { im Text muss als {{ geschrieben werden, weil {...} sonst als Variable gilt. Zwischen den beiden Klammern steht kein Leerzeichen.
  • Zwei Zeilen mit background-color im Code: Die zweite überschreibt die erste. Beim Ändern immer die Stelle suchen, an der der Wert wirklich gesetzt wird.

Nach dem Löschen blieben leere Kästchen im Fenster. Ich hatte die Schaltflächen aus dem Code entfernt, aber der Rahmen (die Container-Widgets) stand weiter da. Ein Widget, das nicht mehr gebraucht wird, muss auch den Container verlieren: deleteLater() oder das Layout neu aufbauen.
