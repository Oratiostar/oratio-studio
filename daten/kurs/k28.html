Dieses Kapitel erzählt ein Projekt von Anfang bis Ende: Windows 11 läuft von einer SD-Karte im Steam Deck, das interne SteamOS bleibt unverändert. Es enthält jeden Befehl, jede Fehlermeldung und die Ursache dahinter. Wer es durcharbeitet, kann das Ganze später von null wiederholen und bei Problemen selbst die Ursache finden.

28.1 Ausgangslage und Ergebnis

Ausgangsproblem: Ein Xbox-Controller ließ sich nicht mit dem Steam Deck koppeln. Ich vermutete eine zu alte Firmware. Ein Firmware-Update gibt es nur über die App Xbox Zubehör, und die läuft nur unter Windows. Das Steam Deck läuft ab Werk mit SteamOS (Linux). Also brauchte ich Windows auf dem Deck – ohne das interne Laufwerk anzufassen, damit SteamOS und alle Spiele erhalten bleiben. Ich hatte keinen Laptop und keinen zweiten Windows-PC, nur das Deck, einen Raspberry Pi 5, ein iPhone, einen USB-Stick mit Windows-Installationsmedium, einen USB-C-Hub, eine externe SSD und eine SD-Karte.

Ergebnis:

  • Windows 11 läuft von einer SD-Karte im Steam Deck. Das interne SteamOS ist unverändert.
  • Der Controller wurde per USB-Kabel mit Xbox Zubehör aktualisiert.
  • WLAN, Grafik (APU), Ton und Kartenleser laufen mit den Valve-Treibern.
  • Die Windows-Installation lässt sich mit dd 1:1 auf weitere Karten klonen.

Der Weg in zehn Zeilen:

  1. Windows-11-Stick und Valve-Treiber vorbereiten.
  2. Deck vom Stick starten (Lautstärke leiser + Power).
  3. Versuch: direkt auf die SD-Karte installieren – scheitert (USB-Sperre).
  4. Versuch: auf eine externe SSD installieren – scheitert aus demselben Grund.
  5. Lösung: im Setup mit Umschalt + F10 das schwarze Fenster öffnen und Windows von Hand schreiben (diskpart, dism, bcdboot).
  6. Windows von der SSD starten, Einrichtung ohne Internet (oobe\bypassnro).
  7. Treiber nachinstallieren: WLAN, APU, drei Audiotreiber.
  8. Controller per USB mit Xbox Zubehör aktualisieren (vorher Gaming Services reparieren).
  9. Am Raspberry Pi die SSD mit dd auf die SD-Karte kopieren.
  10. Von der SD-Karte booten, Partition vergrößern oder zweites Laufwerk D: anlegen.

Wichtig vorab: Alle Befehle, die Laufwerke löschen oder überschreiben (clean, format, dd), verändern das Ziel unwiderruflich. Vor jedem Enter prüfen, ob das richtige Laufwerk gewählt ist. Das interne Laufwerk des Decks (953 GB, später nvme0n1 bzw. Laufwerk 0) wird nie angefasst.

28.2 Begriffe, die man braucht

Viele Fehler in diesem Projekt kamen daher, dass ein Begriff verwechselt wurde.

Steam Deck, SteamOS, UEFI. Das Deck ist ein normaler PC mit einem AMD-Chip (APU: Prozessor und Grafik in einem Chip). Es startet über UEFI, das moderne Gegenstück zum BIOS. Das Boot-Menü öffnet sich, wenn man Lautstärke leiser gedrückt hält und kurz Power drückt (erst loslassen, wenn das Menü erscheint). Dort stehen u. a. SteamOS, EFI USB Device (Stick oder SSD am Hub) und EFI SD/MMC Card (SD-Karte).

Laufwerk, Partition, Partitionstabelle.

MBR (alt) GPT (modern)
Maximalgröße 2 TB praktisch unbegrenzt
Partitionen 4 primäre bis zu 128
Start über altes BIOS UEFI
Beim Deck Windows installiert sich nicht darauf Pflicht für die Windows-Installation

Eine bootfähige Windows-Platte im UEFI-Modus braucht zwei Partitionen: eine kleine EFI-Partition (FAT32, ca. 260 MB, enthält die Startdateien) und die große Windows-Partition (NTFS).

Treiber und .inf-Dateien. Ein Treiber erklärt Windows, wie es ein Bauteil bedient. Das Deck hat Bauteile, die Windows nicht kennt: WLAN, Bluetooth, Grafik, Ton, Kartenleser. Valve stellt Treiber bereit (Support-Seite „Steam Deck – Windows Resources“, getrennte Abschnitte für LCD und OLED). Eine .inf-Datei wird installiert, indem man mit der rechten Maustaste darauf klickt und „Installieren“ wählt. Auf dem Touchscreen ersetzt ein langer Fingerdruck den Rechtsklick; unter Windows 11: lang drücken → „Weitere Optionen anzeigen“ → „Installieren“.

Windows-Image: Auf dem Stick liegt im Ordner sources die Datei install.wim: das komplette Windows als Archiv mit mehreren Editionen, jede mit einer Nummer, dem Index (hier: 1 = Home, 2 = Pro). dism entpackt eine Edition auf eine Partition; bcdboot erzeugt danach die Startdateien.

Wechselmedium und USB-Sperre. Das normale Windows-Setup weigert sich, auf Laufwerke zu installieren, die per USB angeschlossen sind oder als Wechselmedium erkannt werden. SD-Karten im Kartenleser des Decks zählen dazu. Das ist eine Sperre von Microsoft, nicht von Valve – deshalb scheiterten die ersten beiden Versuche.

Mounten. Unter Linux muss ein Dateisystem an einen Ordner „angehängt“ werden (mounten), damit man Dateien lesen kann; das Gegenteil ist umount. Schreibvorgänge landen zuerst im Arbeitsspeicher; wer ein eingehängtes Laufwerk abzieht, verliert eventuell Daten. In lsblk ist ein Laufwerk auch ohne Einhängen sichtbar; ob es eingehängt ist, zeigt die Spalte MOUNTPOINTS.

dd. Kopiert Byte für Byte von einer Quelle (if=, input file) zu einem Ziel (of=, output file), ohne etwas zu verstehen. Dadurch kopiert es auch Dateisysteme, die Linux nicht kennt, z. B. NTFS samt Partitionstabelle und Startdateien. Der Spitzname „Disk Destroyer“ kommt daher, dass dd nichts nachfragt.

Namen der Linux-Laufwerke: sda, sdb sind USB-Laufwerke und SSDs am Hub; mmcblk0 ist die SD-Karte; nvme0n1 ist ein NVMe-Laufwerk (beim Deck das interne, beim Pi die Systemplatte). sda1, sda2 sind Partitionen von sda. Merksatz: Zuerst fragen: In welchem Betriebssystem bin ich gerade? Dann passen die Befehle. Das Aussehen des schwarzen Fensters sagt darüber nichts. (Mehr zum Vergleich der Konsolen: Kapitel 25.)

Ein Stolperstein: Dateien vom iPhone auf den Stick

Das Kopieren der Treiber vom iPhone auf den Windows-Stick scheiterte: Die Dateien-App kann Treiberdateien oft nicht auf einen Windows-Stick kopieren, und ZIP-Dateien lassen sich auf dem Stick nicht entpacken. Lösung: das Steam Deck selbst nehmen. In SteamOS in den Desktop-Modus wechseln (Steam-Taste → Power → „Zum Desktop wechseln“), im Browser die Treiber laden, im Dateimanager per Rechtsklick „Hier entpacken“ und den fertigen Ordner auf die große Partition des Windows-Sticks ziehen (nicht auf die kleine UEFI-NTFS-Partition). Den Stick über den Dateimanager auswerfen. Der Ordnername darf kurz geändert werden; wichtig sind nur die Dateien darin, vor allem die .inf.

28.5 Versuch 1: direkt auf die SD-Karte installieren

Mein naheliegender Plan: Stick einstecken, Setup starten, SD-Karte als Ziel wählen.

  1. Deck ausschalten, SD-Karte eingesteckt lassen, Hub mit dem Windows-Stick anschließen.
  2. Lautstärke leiser halten, kurz Power drücken, im Boot-Menü EFI USB Device (den Stick) wählen.
  3. Das Setup erscheint. Der Bildschirm steht quer – normal, das Display ist hochkant eingebaut. Sprache wählen, „Jetzt installieren“.
  4. Installationsart Benutzerdefiniert: Nur Windows installieren. Es erscheint „Wo möchten Sie Windows installieren?“.

Problem: In der Laufwerkliste stand nur Laufwerk 0 – das interne Laufwerk des Decks. Die SD-Karte fehlte, auch nach Herausnehmen und Wiedereinstecken.

Erste Vermutung: fehlender Kartenleser-Treiber. Also: unten links „Treiber laden“ → „Durchsuchen“ → auf dem Stick BayHubTech > BH778 > Win11x64 (der Ordner Win10x64 ist für Windows 10) → OK → Eintrag „BayHub“/„SD Host Controller“ anhaken → Weiter → „Aktualisieren“.

Ergebnis: Das Treiberfenster zeigte einen Datenträger „bootfs (E:)“ – die Karte war also sichtbar (der Name stammte von früherer Pi-Nutzung) – aber als Installationsziel erschien sie weiterhin nicht.

Zweite Vermutung (half nicht): Karte zuerst in SteamOS formatieren (Steam-Taste → Einstellungen → System → SD-Karte formatieren). Das Dateisystem ist für das Setup egal, weil es die Partitionen selbst anlegt.

Das interne Laufwerk erkennt man an diesen Partitionen: esp, efi, 2 × 5 GB, 2 × 256 MB und eine große mit ca. 943 GB (Spielebibliothek). Nichts davon löschen, formatieren oder neu anlegen, sonst ist SteamOS weg.

Erkenntnis: Der Installer bietet Wechselmedien (USB-Sticks, SD-Karten im Kartenleser) grundsätzlich nicht als Ziel an. Dass auch ein zweiter USB-Stick am Hub nicht auftauchte, bestätigte das. Am Deck war nichts kaputt. Wer nur diese Methode kennt, bräuchte am Windows-PC Rufus mit der Option „Windows To Go“ – das stand nicht zur Verfügung.

28.6 Versuch 2: auf eine externe SSD installieren

Die externe SSD (120 GB) am Hub erschien als Laufwerk 1 mit zwei Partitionen („bootfs“ 512 MB und 111,3 GB), ebenfalls aus früherer Pi-Nutzung.

Problem 1: „Weiter“ ist grau. Beim Antippen der Zeile blieb „Weiter“ grau; auch „Löschen“, „Formatieren“, „Neu“ waren grau. Tipp: Diese Schaltflächen werden erst aktiv, wenn eine Zeile markiert (blau) ist.

Irrweg: MBR statt GPT. Mit Umschalt + F10 und diskpart zeigte list disk, dass Datenträger 1 in der Spalte „GPT“ kein Sternchen hatte (also MBR). Mit clean und convert gpt wurde daraus „Nicht zugewiesener Speicherplatz 111,8 GB“. „Weiter“ blieb trotzdem grau. MBR war nur eine Nebensache.

Die wirkliche Ursache: „Details anzeigen“. Unter der Laufwerkliste steht eine gelbe Warnung „Windows kann nicht auf diesem Laufwerk installiert werden. (Details anzeigen)“. Ein Tipp darauf nennt den Grund:

Windows kann auf dem Datenträger nicht installiert werden. Die Konfiguration oder Installation von Datenträgern, die über USB- oder IEEE 1394-Anschlüsse angeschlossen sind, wird nicht unterstützt.

Das ist dieselbe USB-Sperre wie bei der SD-Karte. Merke: Wenn „Weiter“ grau bleibt, zuerst auf „Details anzeigen“ tippen. Das hätte den Umweg über MBR und GPT gespart.

28.7 Die Lösung: Windows von Hand auf die SSD schreiben

Wenn der Installer das Laufwerk nicht nimmt, schreibt man Windows selbst darauf. Das braucht nur das Setup-Fenster, die USB-Tastatur und vier Werkzeuge: diskpart (Partitionen), dism (Windows entpacken), bcdboot (Startdateien) und dir (Dateien suchen).

Vorbereitung: Im Setup die USB-Meldung mit OK schließen (das Setup bleibt im Hintergrund offen). Umschalt + F10 drücken: Das schwarze Fenster öffnet sich mit X:\sources>. Jede Zeile genau so eintippen und mit Enter bestätigen.

Schritt 1: Die SSD partitionieren

diskpart
list disk
select disk 1
clean
convert gpt
create partition efi size=260
format quick fs=fat32 label=EFI
assign letter=S
create partition primary
format quick fs=ntfs label=Windows
assign letter=W
exit
Befehl Wirkung
diskpart startet das Partitionierungsprogramm (Prompt DISKPART>)
list disk zeigt alle Datenträger mit Größe: hier 0 = 953 GB (internes Deck, tabu), 1 = 111 GB (SSD), 3 = 58 GB (Windows-Stick). Die Nummer der SSD an der Größe erkennen!
select disk 1 wählt die SSD
clean löscht alle Partitionen und Daten des gewählten Datenträgers
convert gpt stellt auf das UEFI-taugliche GPT um
create partition efi size=260 legt die kleine EFI-Partition (260 MB) an
format quick fs=fat32 label=EFI Schnellformatierung als FAT32
assign letter=S gibt der EFI-Partition den Buchstaben S:
create partition primary legt die Windows-Partition über den Rest an
format quick fs=ntfs label=Windows formatiert sie als NTFS
assign letter=W gibt ihr den Buchstaben W:
exit verlässt diskpart; es erscheint wieder X:\sources>

Meldet clean einen Schreibschutz, vorher attributes disk clear readonly eingeben und clean wiederholen.

Schritt 2: Die Windows-Datei auf dem Stick finden

dir F:\sources\install.*

dir zeigt Dateien an; * steht für „beliebige Endung“. Hier war der Stick F:; gefunden wurde install.wim (ca. 6 GB). Steht dort install.esd, wird bei den späteren Befehlen nur der Dateiname ersetzt. Heißt es „Pfad nicht gefunden“, hat der Stick einen anderen Buchstaben: E:, G:, D: oder H: probieren und mit dir F:\ prüfen, dass die Ordner sources, boot und efi darauf liegen.

Schritt 3: Die Edition wählen

dism /get-wiminfo /wimfile:F:\sources\install.wim

Die Ausgabe listet die Editionen: Index 1 = Windows 11 Home, Index 2 = Windows 11 Pro. Ich wählte versehentlich Index 1 (Home), obwohl eine Pro-Lizenz geplant war; das lässt sich nachträglich ändern (28.9). Wer Pro will, nimmt in Schritt 4 /index:2.

Schritt 4: Windows auf die SSD schreiben

dism /apply-image /imagefile:F:\sources\install.wim /index:1 /applydir:W:\

Eine Prozentanzeige läuft mehrere Minuten. Das Deck währenddessen nicht ausschalten. Am Ende: „Der Vorgang wurde erfolgreich beendet.“

Schritt 5: Startdateien anlegen

bcdboot W:\Windows /s S: /f UEFI

Erwartet: „Die Startdateien wurden erfolgreich erstellt.“ Die Startdateien liegen nun auf der EFI-Partition S:, Windows ist auf W: vollständig.

Schritt 6: Neustart von der SSD

  1. exit eingeben, das schwarze Fenster und das Setup schließen (rotes X, Abbruch bestätigen), Deck ausschalten.
  2. Windows-Stick abziehen, die SSD bleibt am Hub.
  3. Lautstärke leiser halten, Power drücken, die SSD im Boot-Menü wählen („Windows Boot Manager“ oder „EFI USB Device“; nicht SteamOS).
  4. Windows richtet sich ein; ein bis zwei Neustarts sind normal. Dabei jedes Mal wieder die SSD wählen.

Typische Tippfehler

  • „Tipp das ein und drück Enter“ heißt: nur die Zeile aus dem Befehlskasten abtippen, nicht das Wort „ein“.
  • Zwischen dism, /get-wiminfo und /wimfile stehen Leerzeichen, innerhalb von /wimfile:F:\sources\install.wim keine.
  • Der Schrägstrich / leitet Optionen ein, der Backslash \ trennt Ordner – verschiedene Zeichen.
  • Im schwarzen Setup-Fenster gibt es kein Kopieren und Einfügen; alles wird von Hand getippt. Im Linux-Fenster geht Einfügen über Rechtsklick oder das Menü.

28.8 Der erste Windows-Start und die Treiber

Problem: „Lassen Sie sich mit einem Netzwerk verbinden“. Die Einrichtung verlangt Internet, aber ohne WLAN-Treiber gibt es keines. Zwei Wege:

  • Umgehung: Umschalt + F10, dann oobe\bypassnro (Backslash in der Mitte). Das Deck startet neu; die SSD im Boot-Menü wählen. Auf der Netzwerk-Seite erscheint unten „Ich habe kein Internet“ → „Mit eingeschränkter Einrichtung fortfahren“ → lokales Konto anlegen (Passwort darf leer bleiben).
  • Treiber vorab auf einen Stick legen und nach dem Start installieren.

Treiber installieren: WLAN (qcwlan64.inf) → APU (setup.exe, Neustart) → alle drei Audio-.inf → optional Bluetooth (qcbtuart.inf) → Neustart.

Problem: Kein Ton (chronologisch)

Das Lautsprecher-Symbol hatte ein x: „Es ist kein Audiogerät installiert“.

28.9 Home oder Pro? Nachträglich umstellen

Ein Wechsel auf Pro geht ohne Neuinstallation: Startmenü → Einstellungen → System → Aktivierung → „Product Key ändern“ → 25-stelligen Pro-Schlüssel eingeben → Weiter. Windows lädt Pro nach und startet neu. Ohne gültige Pro-Lizenz entsteht eine nicht aktivierte Pro-Version (Wasserzeichen, keine Personalisierung). Für Controller, Treiber und Spiele reicht Home. Pro bringt vor allem BitLocker, Remotedesktop als Host, Hyper-V und Gruppenrichtlinien. Microsoft stellt einen allgemeinen Installationsschlüssel bereit (VK7JG-NPHTM-C97JM-9MPGT-3V66T), der Home zu Pro umwandelt, aber nichts aktiviert.

28.10 Der Controller: Firmware-Update mit Xbox Zubehör

Das Update läuft über die App Xbox Zubehör (Microsoft Store) und nur per USB-Kabel, nicht per Bluetooth.

Ablauf:

  1. Startmenü → Microsoft Store → im Suchfeld „Xbox Zubehör“ → App installieren, öffnen.
  2. Controller mit einem Datenkabel am Hub anschließen.
  3. In der App erscheint der „XBOX Wireless Controller“: Knopf mit den drei Punkten (…) → „Firmware-Update“.
  4. Das Kabel nicht abziehen; der Controller schaltet sich zwischendurch kurz aus und wieder ein.
  5. Steht dort, dass der Controller aktuell ist, liegt das Koppelproblem nicht an der Firmware.

Fehler 1: „Fehler beim Anmelden mit Gaming Runtime Services“

Beim ersten Start meldete die App: „Fehler beim Anmelden bei Gaming-Runtime-Diensten …“ mit den Knöpfen XBOX App installieren, Ich benötige Hilfe, Abbrechen.

  • Ursache: Xbox Zubehör nutzt die Hintergrunddienste Gaming Services. Fehlen sie oder sind sie veraltet, bricht die Anmeldung ab.
  • Was nicht half: „XBOX App installieren“ (die App war schon da); die Store-Suche nach „gaming services“ zeigte oben nur Werbung (ein Casino-Spiel mit dem Zusatz „Anzeige“) – das wird nicht installiert.
  • Lösung: Die Store-Seite direkt per Link öffnen. Edge-Browser starten, in die Adresszeile ms-windows-store://pdp/?productid=9MWPM2CQNLHN eingeben, Enter, bei der Rückfrage „Öffnen“. Es erscheint die Seite Gaming Services. Der blaue Knopf kann Installieren, Abrufen oder Aktualisieren heißen; hier war die App veraltet, „Aktualisieren“ lud rund 59 MB. Xbox Zubehör schließen und neu öffnen.

Fehler 2: „Wird Ihr Gerät nicht angezeigt?“

Der Controller blinkte: Er sucht per Bluetooth. Für das Update muss er per Kabel verbunden sein. Xbox-Taste lange drücken (aus), per Datenkabel am Hub anschließen (leuchtet dauerhaft), Xbox Zubehör schließen und neu öffnen. Hilft das nicht: anderes Kabel oder anderer Anschluss; im Geräte-Manager (lang auf das Startmenü-Symbol drücken) nach gelben Warnzeichen sehen.

Meldung 3: „Holen Sie sich eine App, um diesen ms-gamebar-Link zu öffnen“

Ein Zusatzlink der Xbox Game Bar (vermutlich vom Reagenzglas-Symbol). Für das Update unwichtig: nicht „Store durchsuchen“, das Fenster schließen (auf eine freie Stelle tippen oder Esc), dann „…“ und „Firmware-Update“.

Nach dem Update

Zurück in SteamOS: Steam-Taste → Einstellungen → Bluetooth einschalten. Am Controller die Pairing-Taste (kleine runde Taste oben auf der Rückseite) drei Sekunden halten, bis die Xbox-Taste schnell blinkt; er erscheint in der Geräteliste. Geht es nicht, zuerst per USB testen. Ob das Koppeln nach dem Update tatsächlich funktioniert hat, ist in diesem Kapitel nicht bestätigt.

28.11 Windows auf eine SD-Karte klonen (`dd` am Raspberry Pi)

Die SSD ist praktisch, aber eine SD-Karte steckt dauerhaft im Deck. Weil das Setup die Karte nicht als Ziel annimmt, wurde die fertige Installation 1:1 von der SSD auf die Karte kopiert, am Raspberry Pi 5 mit SSD (USB) und SD-Karte (Kartenleser).

Erst die grafischen Wege – und warum sie scheiterten

Programm Meldung Ursache Folge
SD Card Copier (Raspberry-Menü → Zubehör) „Nicht-MSDOS-Partitionstabelle auf Quelle.“ Der Copier kennt nur MBR; die SSD hat GPT (UEFI-Windows) Kopieren nicht möglich; Formatieren der Karte ändert nichts, denn der Fehler liegt an der Quelle
Backup-Programm im Control Center „FEHLER: Auf /dev/sda wurde kein Systembereich (ext4) gefunden.“ Es ist für Linux-Systeme gebaut und sucht ein ext4-Rootsystem; Windows hat NTFS Abbruch bei Schritt 1 von 8, bevor etwas gelöscht wurde (Kapitel 39.2)

Immer vor dem Start prüfen: In solchen Programmen stehen Quelle und Ziel in Listen nebeneinander. Einmal war nvme0n1 als Quelle und sda (die Windows-SSD) als Ziel markiert, obwohl mmcblk0 gemeint war. Weil das Programm abbrach, passierte nichts. Vor jedem „Start“ Quelle und Ziel an der Größe kontrollieren.

Die Methode mit dd

Schritt 1: Laufwerke erkennen

lsblk
NAME          MAJ:MIN RM   SIZE RO TYPE MOUNTPOINTS
sda             8:0    0 111,8G  0 disk
├─sda1          8:1    0   260M  0 part
└─sda2          8:2    0 111,5G  0 part /media/oratio/Windows
mmcblk0       179:0    0 238,3G  0 disk
└─mmcblk0p1   179:1    0 238,3G  0 part
nvme0n1       259:0    0 223,6G  0 disk
├─nvme0n1p1   259:1    0   512M  0 part /boot/firmware
└─nvme0n1p2   259:2    0 223,1G  0 part /
Gerät Größe Rolle
sda 111,8 G (260 M + 111,5 G) Windows-SSD = Quelle
mmcblk0 238,3 G (alte Pi-Partition) SD-Karte = Ziel
nvme0n1 223,6 G (/ und /boot/firmware) System des Pi – nie anfassen

Schritt 2: Quelle aushängen

sudo umount /media/oratio/Windows

Aushängen verhindert, dass sich Daten während des Kopierens ändern.

Schritt 3: Kopieren

sudo dd if=/dev/sda of=/dev/mmcblk0 bs=4M status=progress conv=fsync
Teil Bedeutung
sudo mit Administratorrechten
if=/dev/sda Quelle: die ganze SSD (ohne Zahl = ganzes Laufwerk, nicht eine Partition)
of=/dev/mmcblk0 Ziel: die ganze SD-Karte – hier darf nie ein falsches Laufwerk stehen
bs=4M Blockgröße 4 MB, schneller als der kleine Standardwert
status=progress zeigt live den Fortschritt
conv=fsync schreibt am Ende wirklich alles auf die Karte, bevor dd fertig meldet

Die Anzeige läuft bis ca. 120 GB (SSD: 111,8 GiB = 120 034 123 776 Byte). Bei ca. 82 MB/s dauerte der Lauf rund 24 Minuten. Fertig ist es, wenn der Prompt wieder erscheint:

28618+1 Datensätze ein
28618+1 Datensätze aus
120034123776 Byte (120 GB, 112 GiB) kopiert, 1469,9 s, 81,7 MB/s

Währenddessen das Terminal nicht schließen und den Pi nicht ausschalten.

Schritt 4: Partitionstabelle neu einlesen

sudo partprobe /dev/mmcblk0

partprobe sagt Linux, die Tabelle neu zu lesen. Ohne das zeigt lsblk noch die alte einzelne Partition. Die Warnung „Not all of the space available to /dev/mmcblk0 appears to be used …“ ist in Ordnung: Die Karte (238 GB) ist größer als die SSD (111,8 GB), und die Kopie hat die Sicherungs-Partitionstabelle (Backup-GPT) an der Stelle der kleineren SSD abgelegt.

Schritt 5: Aushängen, Tabelle reparieren, abschließen

sudo umount /dev/mmcblk0p1 /dev/mmcblk0p2
sudo apt install -y gdisk
sudo sgdisk -e /dev/mmcblk0
sync
lsblk
Befehl Bedeutung / erwartete Meldung
umount …p1 …p2 „not mounted“ ist in Ordnung – nichts war eingehängt
apt install -y gdisk installiert sgdisk; „schon die neueste Version“ heißt: schon da
sgdisk -e /dev/mmcblk0 schiebt die Backup-Partitionstabelle ans echte Ende der Karte: „The operation has completed successfully.“
sync erzwingt, dass alle Schreibvorgänge ankommen
lsblk Kontrolle: mmcblk0p1 (260 M) und mmcblk0p2 (111,5 G); MOUNTPOINTS leer

„Sichtbar“ gegenüber „eingehängt“: Sichtbar heißt nur, dass Linux die Partitionen kennt (steht in lsblk). Eingehängt heißt, dass sie mit einem Ordner verbunden sind. Bei der fertigen Karte sind sie sichtbar, aber nicht eingehängt – der richtige Zustand zum Herausziehen.

Schritt 6: Abziehen und starten

  1. Karte aus dem Pi ziehen (Auswerfen nicht nötig, nichts ist eingehängt).
  2. Karte ins Deck, SSD vom Hub abziehen.
  3. Lautstärke leiser + Power, im Boot-Menü EFI SD/MMC Card wählen.
  4. Windows startete ohne Fehler, mit allen Einstellungen, Treibern, flüssig.

Nicht im Dateimanager anklicken: Am Pi erschienen links zwei Einträge „Windows“ (SSD und Karte haben dieselbe Bezeichnung, weil dd sie mitkopiert hat). Anklicken würde die Partition einhängen, und Linux könnte etwas hineinschreiben; Windows meldet danach eventuell „nicht sauber getrennt“.

Regeln für dd

  1. Das ganze Laufwerk kopieren (sda, nicht sda2), sonst fehlen Partitionstabelle und Startdateien.
  2. Das Ziel muss mindestens so groß sein wie die Quelle; sonst bricht dd ab oder schneidet das Ende ab (dann Clonezilla oder Macrium Reflect Free).
  3. Ist das Ziel größer, bleibt der Rest ungenutzt, bis man die Partition vergrößert (28.12).
  4. Das Ziel wird komplett überschrieben. Ein Fehler bei of= ist nicht rückgängig zu machen.
  5. Die Quelle nicht in Benutzung (ausgehängt); nie von der laufenden Systemplatte kopieren.
  6. Original und Kopie nie gleichzeitig an denselben Windows-Rechner (gleiche Kennungen).
  7. Linux klont fast immer problemlos. Windows startet auf derselben Hardware meist problemlos; auf anderer Hardware kann es bei „Inaccessible Boot Device“ hängen bleiben oder bei BitLocker den Wiederherstellungsschlüssel verlangen.

Alternativen zu dd

Programm Eignung hier
Rufus (Windows To Go) läuft nur unter Windows; schreibt ein fertiges Windows direkt auf Stick oder Karte – am PC der kürzeste Weg
Balena Etcher, Raspberry Pi Imager schreiben nur fertige Image-Dateien, kopieren nicht von Laufwerk zu Laufwerk (erst ein 111-GB-Image nötig)
Clonezilla kann GPT und NTFS und verkleinert beim Klonen; muss erst auf einen Stick geschrieben werden – mehr Aufwand
Macrium Reflect Free Klonprogramm unter Windows, geeignet für kleinere Ziele

Eigene Sicherung als Datei

Ein funktionierendes Windows ist die Vorlage. Statt neu zu installieren, kann man es als gepackte Datei sichern (Standardverfahren; die Rückspielzeile wurde in diesem Projekt nicht getestet):

sudo dd if=/dev/mmcblk0 bs=4M status=progress | gzip > windows-backup.img.gz
gzip -dc windows-backup.img.gz | sudo dd of=/dev/mmcblk0 bs=4M status=progress conv=fsync

Die Sicherungsdatei muss auf einem anderen Laufwerk liegen.

28.12 Nach dem Klon: Platz nutzen, doppelte Kennungen

Warum die Karte nur 111 GB zeigt: dd kopiert genau die Größe der Quelle. Auf der 256-GB-Karte hat die Windows-Partition deshalb nur ca. 111 GB; die restlichen ca. 126 GB sind „nicht zugeordnet“.

Möglichkeit A: C: vergrößern. Lang auf das Startmenü-Symbol → Datenträgerverwaltung → lang auf C: → Volume erweitern → Weiter, Weiter, Fertig stellen. Ist „Volume erweitern“ grau, liegt eine andere Partition (etwa eine Wiederherstellungspartition) zwischen C: und dem freien Platz; dann die Datenträgerverwaltung genau ansehen. Das Erweitern löscht keine Daten.

Möglichkeit B: zweites Laufwerk D: anlegen. In der Datenträgerverwaltung lang auf den schwarzen Block Nicht zugeordnet → Neues einfaches Volume → Weiter, Weiter (volle Größe), Buchstabe D, Weiter → NTFS, Bezeichnung z. B. „Daten“ → Fertig stellen.

D: als zweites Laufwerk C: erweitern
Vorteil Windows und Daten getrennt; Windows lässt sich neu aufsetzen, ohne Daten zu berühren ein großer Block
Nachteil C: nur 111 GB; Windows, Treiber, Updates brauchen etwa 30–40 GB und wachsen alles in einem Topf
Tipp Spiele und eigene Dateien auf D: später bleibt D: löschen und C: erweitern

Ein späteres dd der ganzen Karte kopiert D: mit (dann 238 GB). Doppelte Kennungen: SSD und Karte sind Zwillinge mit denselben internen IDs. Unter Windows nie beide gleichzeitig anschließen; Windows kann sonst eines wegen doppelter ID offline schalten. Die SSD ist jetzt das Backup. Die Treiberordner am besten auf D: behalten.

28.16 Hintergrund und Alternativen

Windows von der SteamOS-Konsole aus installieren? Teilweise. Im Desktop-Modus gibt es die Konsole (bash). Dort lassen sich Laufwerke mit sgdisk und mkfs.ntfs vorbereiten, und das Windows-Image könnte mit dem Programm wimlib auf die Platte geschrieben werden. wimlib ist nicht vorinstalliert, braucht abgeschalteten Schreibschutz und kann nach einem SteamOS-Update verschwinden. Die Startdateien erzeugt nur bcdboot, das es nur unter Windows gibt; das Windows-Setup mit Umschalt + F10 bleibt also für diesen einen Befehl nötig. Vorteil in SteamOS: Befehle lassen sich aus dem Browser einfügen, im Windows-Setup muss man alles tippen.

dd im SteamOS-Desktop funktioniert wie am Pi, ohne Einschränkung. Am Deck: nvme0n1 = internes Laufwerk (nie als Ziel), sda = externe SSD, mmcblk0 = SD-Karte; trotzdem immer mit lsblk an den Größen prüfen. Ob sgdisk vorinstalliert ist, wurde nicht geprüft (sgdisk --version); sonst hilft sudo parted /dev/mmcblk0 print. Vorher einmal passwd für das sudo-Passwort.

Ist SteamOS eingeschränkt?

Updates können Änderungen am Systemlaufwerk löschen ändern nur, was man erlaubt
dd, lsblk, sudo ohne Einschränkung (sudo-Passwort vorher setzen) ohne Einschränkung

Die USB-Sperre beim Windows-Setup (28.5 und 28.6) kommt von Microsoft, nicht von Valve. Der fehlende Kartenleser im Installer war ein fehlender Treiber.
