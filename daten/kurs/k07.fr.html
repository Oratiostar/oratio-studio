Ma question était : qu’est-ce que mkfs ? Je veux tout savoir sur le formatage, les partitions et les commandes. Voici la réponse, dans l’ordre.

7.1 Que se passe-t-il lors d’un formatage ?

Un SSD neuf est comme un terrain vide. Il a de l’espace de stockage, mais Linux ne sait pas encore où se trouvent les fichiers et les dossiers. Lors du formatage, cette structure est créée : répertoires, table des fichiers, gestion de l’espace libre.

7.2 Les noms des disques

Linux traite les appareils comme des fichiers. Ils se trouvent sous /dev :

Nom Signification
/dev/mmcblk0 carte microSD
/dev/sda, /dev/sdb disques USB ou SATA
/dev/nvme0n1 SSD NVMe
/dev/sda1 première partition de sda
/dev/nvme0n1p1 première partition du NVMe
/dev/ttyUSB0 un appareil série USB (par exemple Arduino Nano)

Règle : on ne formate pas le disque entier (/dev/sda), mais une partition (/dev/sda1).

7.3 Partitions et table de partitions

Une partition est une section d’un disque. Un SSD de 1 To peut par exemple être divisé en 500 Go pour Linux et 500 Go pour les données. Il existe deux types de table de partitions :

  • MBR – ancien, 2 To et 4 partitions au maximum
  • GPT – moderne, pour les gros disques et de nombreuses partitions. Aujourd’hui presque toujours le bon choix.

7.4 Le déroulement complet : installer un nouveau SSD

Étape 1 : trouver le disque (toujours en premier !)

lsblk

Exemple de sortie :

nvme0n1   1TB   ← System
sda       1TB   ← Backup-SSD

Il faut savoir exactement quel disque est lequel. Celui qui se trompe ici formate le système.

Étape 2 : créer la table de partitions et la partition

sudo parted -s /dev/sda mklabel gpt
sudo parted -s /dev/sda mkpart primary ext4 0% 100%

La première commande crée une table GPT, la deuxième crée une partition sur toute la taille. On peut aussi procéder en interactif avec sudo fdisk /dev/sda. Là : p affiche, n nouvelle partition, d supprime, w enregistre, q quitte sans enregistrer.

Étape 3 : créer le système de fichiers

sudo mkfs.ext4 -L BACKUP /dev/sda1
  • mkfs = « make file system », créer un système de fichiers
  • ext4 = type, le standard pour Linux (rapide, stable)
  • -L BACKUP = un nom pour le disque
  • /dev/sda1 = la partition

Autres systèmes de fichiers : exFAT (échange avec Windows et Mac), FAT32 (ancien, limite de fichier à 4 Go), NTFS (Windows).

Étape 4 : monter

sudo mkdir /backup
sudo mount /dev/sda1 /backup
df -h

Sous Linux, un disque n’est utilisable qu’une fois monté sur un dossier. Ensuite il apparaît sous /backup.

Étape 5 : définir les droits

sudo chown oratio:oratio /backup

Sinon le dossier appartient à root, et l’utilisateur ne peut rien y enregistrer.

Étape 6 : démonter avant de débrancher le disque

sudo umount /backup

7.5 Monter durablement : fstab

Un mount normal ne vaut que jusqu’au redémarrage. Pour que le SSD soit toujours monté au démarrage, on l’inscrit dans /etc/fstab :

cat /etc/fstab
sudo blkid                # zeigt die UUID jedes Laufwerks
sudo nano /etc/fstab

Exemple de ligne (utiliser l’UUID donné par blkid, pas /dev/sda1, car ces noms peuvent changer) :

UUID=<UUID-AUS-BLKID>  /backup  ext4  defaults  0  2

Ensuite sudo mount -a pour tester. Une erreur dans /etc/fstab peut empêcher le Pi de démarrer : il faut donc modifier ce fichier avec une prudence particulière.

7.6 Autres commandes utiles

lsblk -f                     # mit Dateisystem
findmnt                      # alle eingehängten Laufwerke als Baum
findmnt /                    # von welchem Laufwerk läuft das System?
sudo blkid                   # UUID und Typ

7.7 Mesurer la vitesse

Mon objectif était de comparer la vitesse de la carte SD, du SSD USB et du NVMe.

sudo hdparm -Tt /dev/sda             # USB-SSD
sudo hdparm -Tt /dev/nvme0n1         # NVMe
sudo hdparm -Tt /dev/mmcblk0         # SD-Karte

-T mesure le cache, -t la vraie vitesse de lecture. fio est plus précis :

sudo apt install fio
sudo fio --name=USB-Read-Test --filename=/dev/sda --rw=read --bs=1M --size=2G --direct=1

Et le test d’écriture le plus simple, sans logiciel supplémentaire :

dd if=/dev/zero of=test.img bs=1M count=1024 conv=fdatasync
rm test.img

À la fin, on obtient une ligne comme 1073741824 bytes copied, 2.5 s, 430 MB/s. Supprimer ensuite le fichier de test. Le test avec fio sur --filename=/dev/... lit directement depuis le disque, c’est en lecture seule et donc sûr. Ne jamais diriger de test d’écriture vers un disque contenant des données importantes.

7.8 Ordre de démarrage sur le Pi 5

Je voulais « carte SD comme système d’exploitation, NVMe seulement pour tester ». L’ordre de démarrage est dans l’EEPROM du Pi :

sudo rpi-eeprom-config | grep BOOT_ORDER

Avec sudo raspi-config (Advanced Options, Boot Order), on change l’ordre. Ensuite on vérifie avec lsblk et findmnt / depuis quel disque le système démarre réellement.
