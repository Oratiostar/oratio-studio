26.1 Ce qu’est Batocera

Batocera est un système d'exploitation complet et autonome pour les jeux rétro. Ce n'est pas une application que l'on lance sous Raspberry Pi OS. On l'écrit sur une carte SD, un SSD ou une clé USB et l'on démarre l'ordinateur dessus. Il prend en charge plus de 100 systèmes et émulateurs.

Où le trouver ?

  • Site officiel de Batocera : on y télécharge l'image correspondant au matériel. Elle ne contient aucun jeu.
  • Images toutes prêtes avec jeux : il existe de grandes images préparées (128 Go à 1 To) qui contiennent déjà jeux, thèmes et BIOS (par exemple chez ArcadePunks, Retro Lunatics ou Batocera Nation). Ces collections contiennent souvent des jeux protégés par le droit d'auteur. Seuls les jeux que l'on possède et les fichiers BIOS de ses propres appareils sont juridiquement sûrs.

26.2 La bonne image pour le bon appareil

Batocera existe en image distincte pour chaque matériel. Une image Pi 4 ne démarre pas sur le Pi 5. C'est la cause la plus fréquente des problèmes de démarrage.

Appareil Puce Nom de fichier dans la zone de démarrage
Raspberry Pi 4 BCM2711 bcm2711-rpi-4-b.dtb, bcm2711-rpi-400.dtb
Raspberry Pi 5 BCM2712 bcm2712-rpi-5-b.dtb
PC, Steam Deck, mini-PC x86-64 image x86-64 dédiée

26.3 Erreur 1 : « Device-tree file bcm2712-rpi-5-b.dtb not found »

Ce qui s'est passé : le Pi 5 a affiché deux messages à l'écran :

The installed operating system (OS) does not indicate support for Raspberry Pi 5
Device-tree file 'bcm2712-rpi-5-b.dtb' not found.

L'appareil voyait la partition BATOCERA, mais ne démarrait pas. L'erreur était identique sur carte SD et sur SSD.

Pourquoi ce diagnostic ? Comme la même erreur apparaissait sur deux supports différents, une carte SD ou un SSD défectueux était exclu. Cela devait venir du contenu. Au démarrage, le Pi 5 cherche le fichier de sa puce (bcm2712-...). S'il manque, le système n'est pas conçu pour le Pi 5.

La vérification : ouvrir la première partition (BATOCERA) sur le PC et regarder les fichiers. Si l'on y trouve bcm2711-rpi-4-b.dtb et bcm2711-rpi-400.dtb, ce ne sont que des fichiers pour le Pi 4. La mauvaise image a donc été téléchargée, même si la page de téléchargement indiquait « Raspberry Pi 5B ».

Solution : télécharger la bonne image (BCM2712) et la réécrire. Ensuite l'écran affichait Read bcm2712-rpi-5-b.dtb bytes 78744 : le fichier était désormais trouvé.

À retenir : quand la même erreur de démarrage apparaît sur plusieurs supports, ce n'est pas le support qui est en cause mais ce qui y a été écrit. On le vérifie avec ls sur la partition de démarrage.

26.4 Erreur 2 : « USB boot requires high current (5 volt 5 amp) power supply »

Juste après la correction, le message suivant peut apparaître. Pour démarrer depuis un SSD USB, le Pi 5 exige une alimentation capable de fournir 5 V et 5 A, et limite sinon le courant USB. Souvent, on peut quand même débloquer le démarrage en appuyant sur le bouton d'alimentation, et Batocera fonctionne.

À retenir : ce message est un avertissement du Pi 5, pas une panne. Solution durable : utiliser l'alimentation officielle de 27 watts (5 V / 5 A). Voir à ce sujet le chapitre 6 (sous-tension et vcgencmd get_throttled).

26.5 Erreur 3 : ROM et BIOS invisibles

Ce qui s'est passé : la carte SD Batocera est insérée sous Raspberry Pi OS. On ne voit que config.txt, cmdline.txt, start.elf et batocera-boot.conf, mais pas de dossiers roms ou bios.

Cause : Batocera crée deux partitions :

Partition Système de fichiers Contenu
BATOCERA FAT32, petite (environ 6 Go) fichiers de démarrage (config.txt, cmdline.txt, ...)
SHARE ext4, tout le reste roms, bios, saves, screenshots, themes

Je n'avais ouvert que la première partition. La seconde (SHARE) apparaît à gauche dans le gestionnaire de fichiers comme un lecteur à part.

26.6 Erreur 4 : « Permission refusée » lors de la copie des jeux

Ce qui s'est passé : dans le dossier /media/oratio/SHARE/roms/psx, un jeu (par exemple Bowling.PBP) doit être copié depuis la clé USB. Le fichier est presque entièrement copié, puis une erreur d'écriture apparaît à la fin.

Diagnostic en deux étapes :

touch /media/oratio/SHARE/test.txt

Réponse : Permission refusée. Il est donc clair que le problème n'est ni le fichier ni la clé USB, mais les droits d'écriture sur la partition ext4. Sur Batocera, elle appartient à l'utilisateur root, et l'utilisateur normal n'a que la lecture sous Raspberry Pi OS.

Solution :

sudo chmod -R 777 /media/oratio/SHARE
touch /media/oratio/SHARE/test.txt

Ensuite, plus aucun message d'erreur. Les jeux ont pu être copiés.

Ce que signifie la commande (décomposée, voir aussi le chapitre 2.10) :

Élément Signification
sudo exécuter en administrateur
chmod modifier les droits (change mode)
-R récursif, donc aussi pour tous les sous-dossiers et fichiers
777 propriétaire 7 (rwx), groupe 7 (rwx), tous les autres 7 (rwx) : chacun peut tout faire
/media/oratio/SHARE la cible

À retenir : 777 est un marteau. Il résout vite le problème, mais ensuite tout le monde peut tout faire. Pour un lecteur de jeux privé, c'est acceptable.

Deux partitions SHARE : SHARE et SHARE1

Plus tard, j'ai branché Batocera deux fois : une fois sur la carte SD et une fois sur un disque dur externe. Le gestionnaire de fichiers montrait à gauche deux fois BATOCERA et deux fois SHARE. Linux numérote les noms identiques :

Lecteur Partition de démarrage Partition de données Appareil
Carte SD BATOCERA1 SHARE /dev/mmcblk0p2
Disque dur externe BATOCERA2 SHARE1 /dev/sda2

La commande chmod n'avait d'abord été exécutée que sur SHARE, donc seulement sur la carte SD. Sur le disque dur, il fallait refaire la même chose avec SHARE1 :

touch /media/oratio/SHARE1/test.txt
sudo chmod -R 777 /media/oratio/SHARE1

Question : si je donne le disque dur à quelqu'un d'autre, la modification est-elle incluse ? Oui. Les droits sont enregistrés sur le lecteur dans le système de fichiers, pas dans le Pi. Pour les rétablir, on prend une valeur raisonnable comme 755 :

sudo chmod -R 755 /media/oratio/SHARE1

On ne peut pas retrouver exactement la valeur d'origine, car elle n'a pas été consultée avant. C'est pourquoi : avant de changer des droits, regarder ls -l et noter le résultat.

26.7 Choix du démarrage : SD, NVMe et USB

Situation de départ : Batocera sur carte SD, Raspberry Pi OS sur le SSD NVMe dans l'emplacement PCIe du Pi 5. À l'allumage, Batocera démarrait toujours. Je voulais pouvoir choisir.

Étape 1 : où suis-je exactement ? Par SSH, l'invite affichait root@BATOCERA. J'étais donc dans Batocera, pas dans Raspberry Pi OS. C'est pourquoi sudo raspi-config n'y fonctionnait pas.

Étape 2 : Batocera voit-il le SSD ?

lsblk

Résultat : nvme0n1 avec nvme0n1p1 (512 Mo) et nvme0n1p2 (223 Go). Les points de montage /media/bootfs et /media/rootfs révélaient la présence d'une disposition de Raspberry Pi OS. La vérification du fichier /etc/os-release indiquait Debian GNU/Linux 13 (trixie) : c'est Raspberry Pi OS. Le SSD était en ordre.

Étape 3 : lire l'ordre de démarrage

rpi-eeprom-config

Sortie : BOOT_ORDER=0xf461.

Chiffre Appareil
1 Carte SD
4 Stockage de masse USB
6 NVMe
f Fin (recommencer / arrêt)

Comment lire ce nombre ? Les chiffres se lisent de droite à gauche. Le test pratique le confirme : carte SD insérée, Batocera démarre. Carte SD retirée, la NVMe démarre. La SD est donc essayée en premier. 0xf461 signifie : SD, puis NVMe, puis USB.

Les chiffres se lisent de droite à gauche (le chiffre le plus à droite est essayé en premier). Qui veut d'abord la NVMe, puis la carte SD, puis USB écrit 0xf416. 0xf164 serait en revanche USB, puis NVMe, puis SD. À retenir : avec ce nombre, ne pas deviner mais tester, et régler de préférence via raspi-config, c'est plus sûr.

Étape 4 : modifier depuis Batocera ? La commande rpi-eeprom-update a indiqué EEPROM updates directory ... not found. Batocera peut lire la configuration, mais pas l'écrire de façon sûre. La modification devait donc se faire sous Raspberry Pi OS.

Étape 5 : solution via raspi-config (retirer la carte SD, démarrer depuis la NVMe) :

sudo raspi-config

Puis : Advanced Options → Boot Order → B2 NVMe/USB Boot (au lieu de B1 SD Card Boot) → OK → Finish → redémarrage.

Priorité avec B2 : NVMe, puis USB, puis SD.

26.8 Le vrai menu de démarrage : la barre d’espace

Qui veut non seulement un ordre fixe mais choisir au démarrage a besoin du menu de démarrage :

Touche à l'allumage Effet sur le Pi 5
Maj rien d'utilisable (une fois, l'écran de configuration « Configure this Raspberry Pi 5 » est apparu, quitter avec Esc)
Échap n'affiche que l'affichage détaillé du bootloader (boot mode NVME (06), order f14...)
Barre d'espace ouvre le vrai menu de démarrage

Dans le menu, on choisit avec le chiffre : 1 = SD (Batocera), 4 = USB, 6 = NVMe (Raspberry Pi OS).

Condition : un clavier branché directement sur le Pi (USB ou clavier sans fil avec récepteur USB). Un clavier via SSH ou un clavier à l'écran ne réagit pas à ce moment-là, car aucun système d'exploitation ne tourne encore.

À retenir : Échap n'affiche que l'affichage détaillé du bootloader, Maj ne déclenche rien d'utilisable sur le Pi 5. Le menu de démarrage s'ouvre avec la barre d'espace.

26.9 Éteindre Batocera

Ne pas simplement débrancher le courant, car des fichiers peuvent être endommagés. Possibilités :

  • Sur la manette : Start → Quit → Shutdown System.
  • Maintenir le bouton d'alimentation du Pi 5 enfoncé environ 3 secondes (arrêt ordonné).
  • Par SSH : shutdown -h now.

26.10 Batocera et le ventilateur Freenove

La tour Freenove (chapitre 11) règle ventilateur et LED via un programme Python sous Raspberry Pi OS. Il n'y a pas de puce de ventilateur propre avec profil enregistré. En passant de Raspberry Pi OS à Batocera, le programme ne tourne plus et le ventilateur ne reçoit plus de commandes.

Résultat : Batocera ne se lance pas de façon utile comme programme sous Raspberry Pi OS, car c'est un système complet à part. La solution est le double démarrage (deux supports, choix au démarrage, voir 24.7 et 24.8). Configurer la commande du ventilateur sous Batocera même est un projet à part.

26.11 Quels systèmes Batocera gère-t-il sur le Pi 5 ?

Classe Exemples Sur le Pi 5
8 bits et 16 bits Atari 2600, NES, SNES, Game Boy, Master System, Mega Drive, PC Engine, Neo Geo fonctionne sans problème
32 bits et 64 bits PlayStation 1, Nintendo 64, Dreamcast fonctionne bien
Plus lourd PSP, GameCube, Wii selon le jeu
Trop lourd PS2, Wii U, PS3 non (Steam Deck ou PC x86 plus puissant nécessaire)

Ces indications sont des estimations approximatives, pas des mesures. Des plateformes plus puissantes sont le Steam Deck, le ROG Ally X, le Lenovo Legion Go et les mini-PC avec Ryzen 7 8845HS ou Ryzen AI Max+ 395.

26.12 Liste de contrôle pour Batocera

  1. Télécharger l'image adaptée à l'appareil (Pi 4 ≠ Pi 5 ≠ PC).
  2. Écrire avec Raspberry Pi Imager (sudo apt install rpi-imager) ou Etcher.
  3. Vérifier sur la partition de démarrage : le fichier .dtb adapté s'y trouve-t-il ?
  4. Utiliser une alimentation 5 V / 5 A.
  5. Copier les jeux sur la partition SHARE dans roms/<système>/, le BIOS dans bios/.
  6. En cas de « Permission refusée » : tester avec touch, puis sudo chmod -R 777 sur la bonne partition SHARE.
  7. Ordre de démarrage via raspi-config sous Raspberry Pi OS, menu de démarrage avec la barre d'espace.
