Ce chapitre raconte un projet du début à la fin : Windows 11 tourne depuis une carte SD dans le Steam Deck, le SteamOS interne reste inchangé. Il contient chaque commande, chaque message d'erreur et la cause qui se cache derrière. Qui le travaille peut plus tard tout refaire de zéro et trouver lui-même la cause en cas de problème.

28.1 Situation de départ et résultat

Problème de départ : une manette Xbox ne s'appairait pas avec le Steam Deck. Je supposais un firmware trop ancien. Une mise à jour du firmware n'existe que via l'application Accessoires Xbox, et celle-ci ne fonctionne que sous Windows. Le Steam Deck tourne d'usine avec SteamOS (Linux). J'avais donc besoin de Windows sur le Deck – sans toucher au lecteur interne, pour que SteamOS et tous les jeux soient conservés. Je n'avais ni ordinateur portable ni second PC Windows, seulement le Deck, un Raspberry Pi 5, un iPhone, une clé USB avec le support d'installation de Windows, un hub USB-C, un SSD externe et une carte SD.

Résultat :

  • Windows 11 tourne depuis une carte SD dans le Steam Deck. Le SteamOS interne est inchangé.
  • La manette a été mise à jour par câble USB avec Accessoires Xbox.
  • Wi-Fi, graphisme (APU), son et lecteur de cartes fonctionnent avec les pilotes de Valve.
  • L'installation de Windows peut être clonée à l'identique sur d'autres cartes avec dd.

Le chemin en dix lignes :

  1. Préparer la clé Windows 11 et les pilotes Valve.
  2. Démarrer le Deck depuis la clé (volume moins + Power).
  3. Essai : installer directement sur la carte SD – échoue (blocage USB).
  4. Essai : installer sur un SSD externe – échoue pour la même raison.
  5. Solution : dans le programme d'installation, ouvrir la fenêtre noire avec Maj + F10 et écrire Windows à la main (diskpart, dism, bcdboot).
  6. Démarrer Windows depuis le SSD, configuration sans Internet (oobe\bypassnro).
  7. Installer ensuite les pilotes : Wi-Fi, APU, trois pilotes audio.
  8. Mettre à jour la manette par USB avec Accessoires Xbox (réparer d'abord Gaming Services).
  9. Sur le Raspberry Pi, copier le SSD sur la carte SD avec dd.
  10. Démarrer depuis la carte SD, agrandir la partition ou créer un second lecteur D:.

Important au préalable : toutes les commandes qui effacent ou écrasent des lecteurs (clean, format, dd) modifient la cible de façon irréversible. Avant chaque Entrée, vérifier que le bon lecteur est sélectionné. Le lecteur interne du Deck (953 Go, plus tard nvme0n1 ou lecteur 0) n'est jamais touché.

28.2 Notions nécessaires

Beaucoup d'erreurs de ce projet venaient d'une confusion de termes.

Steam Deck, SteamOS, UEFI. Le Deck est un PC normal avec une puce AMD (APU : processeur et graphisme dans une même puce). Il démarre via UEFI, le pendant moderne du BIOS. Le menu de démarrage s'ouvre quand on maintient volume moins et qu'on appuie brièvement sur Power (ne relâcher que lorsque le menu apparaît). On y trouve entre autres SteamOS, EFI USB Device (clé ou SSD sur le hub) et EFI SD/MMC Card (carte SD).

Lecteur, partition, table de partitions.

MBR (ancien) GPT (moderne)
Taille maximale 2 TB pratiquement illimitée
Partitions 4 primaires jusqu'à 128
Démarrage via ancien BIOS UEFI
Sur le Deck Windows ne s'y installe pas Obligatoire pour l'installation de Windows

Un disque Windows amorçable en mode UEFI a besoin de deux partitions : une petite partition EFI (FAT32, env. 260 Mo, contient les fichiers de démarrage) et la grande partition Windows (NTFS).

Pilotes et fichiers .inf. Un pilote explique à Windows comment utiliser un composant. Le Deck a des composants que Windows ne connaît pas : Wi-Fi, Bluetooth, graphisme, son, lecteur de cartes. Valve fournit des pilotes (page d'assistance « Steam Deck – Windows Resources », sections séparées pour LCD et OLED). Un fichier .inf s'installe en faisant un clic droit dessus et en choisissant « Installer ». Sur l'écran tactile, un appui long remplace le clic droit ; sous Windows 11 : appui long → « Afficher plus d'options » → « Installer ».

Image Windows : sur la clé, dans le dossier sources, se trouve le fichier install.wim : tout Windows sous forme d'archive avec plusieurs éditions, chacune avec un numéro, l'index (ici : 1 = Famille, 2 = Pro). dism extrait une édition sur une partition ; bcdboot crée ensuite les fichiers de démarrage.

Support amovible et blocage USB. Le programme d'installation normal de Windows refuse d'installer sur des lecteurs branchés en USB ou reconnus comme supports amovibles. Les cartes SD dans le lecteur de cartes du Deck en font partie. C'est un blocage de Microsoft, pas de Valve – c'est pourquoi les deux premiers essais ont échoué.

Monter. Sous Linux, un système de fichiers doit être « accroché » à un dossier (monter) pour qu'on puisse lire des fichiers ; l'inverse est umount. Les écritures vont d'abord en mémoire vive ; en débranchant un lecteur monté, on risque de perdre des données. Dans lsblk, un lecteur est visible même sans être monté ; la colonne MOUNTPOINTS indique s'il l'est.

dd. Copie octet par octet d'une source (if=, input file) vers une cible (of=, output file), sans rien comprendre. Il copie ainsi aussi des systèmes de fichiers que Linux ne connaît pas, par ex. NTFS avec table de partitions et fichiers de démarrage. Le surnom « Disk Destroyer » vient de ce que dd ne demande aucune confirmation.

28.5 Essai 1 : installer directement sur la carte SD

Mon plan évident : brancher la clé, lancer l'installation, choisir la carte SD comme cible.

  1. Éteindre le Deck, laisser la carte SD insérée, brancher le hub avec la clé Windows.
  2. Maintenir volume moins, appuyer brièvement sur Power, choisir EFI USB Device (la clé) dans le menu de démarrage.
  3. Le programme d'installation apparaît. L'écran est en mode paysage tourné – normal, l'écran est monté en portrait. Choisir la langue, « Installer maintenant ».
  4. Type d'installation Personnalisé : installer uniquement Windows. « Où voulez-vous installer Windows ? » apparaît.

Problème : dans la liste des lecteurs, il n'y avait que le lecteur 0 – le lecteur interne du Deck. La carte SD manquait, même après l'avoir retirée et réinsérée.

Première hypothèse : pilote du lecteur de cartes manquant. Donc : en bas à gauche « Charger un pilote » → « Parcourir » → sur la clé BayHubTech > BH778 > Win11x64 (le dossier Win10x64 est pour Windows 10) → OK → cocher l'entrée « BayHub »/« SD Host Controller » → Suivant → « Actualiser ».

Résultat : la fenêtre des pilotes montrait un support « bootfs (E:) » – la carte était donc visible (le nom venait d'une utilisation antérieure sur Pi) – mais elle n'apparaissait toujours pas comme cible d'installation.

Deuxième hypothèse (n'a pas aidé) : formater d'abord la carte dans SteamOS (touche Steam → Paramètres → Système → Formater la carte SD). Le système de fichiers est sans importance pour l'installation, car elle crée elle-même les partitions.

On reconnaît le lecteur interne à ces partitions : esp, efi, 2 × 5 Go, 2 × 256 Mo et une grande d'environ 943 Go (bibliothèque de jeux). N'en supprimer, formater ou recréer aucune, sinon SteamOS disparaît.

Constat : le programme d'installation ne propose en principe jamais les supports amovibles (clés USB, cartes SD dans le lecteur de cartes) comme cible. Qu'une seconde clé USB sur le hub n'apparaisse pas non plus l'a confirmé. Rien n'était cassé sur le Deck. Qui ne connaît que cette méthode aurait besoin, sur un PC Windows, de Rufus avec l'option « Windows To Go » – ce qui n'était pas disponible.

28.6 Essai 2 : installer sur un SSD externe

Le SSD externe (120 Go) sur le hub est apparu comme lecteur 1 avec deux partitions (« bootfs » 512 Mo et 111,3 Go), également issues d'une utilisation antérieure sur Pi.

Problème 1 : « Suivant » est grisé. En touchant la ligne, « Suivant » restait grisé ; « Supprimer », « Formater », « Nouveau » aussi. Astuce : ces boutons ne deviennent actifs que lorsqu'une ligne est sélectionnée (bleue).

Fausse piste : MBR au lieu de GPT. Avec Maj + F10 et diskpart, list disk montrait que le disque 1 n'avait pas d'astérisque dans la colonne « GPT » (donc MBR). Avec clean et convert gpt, on a obtenu « Espace non alloué 111,8 Go ». « Suivant » restait pourtant grisé. MBR n'était qu'un détail.

La vraie cause : « Afficher les détails ». Sous la liste des lecteurs figure un avertissement jaune « Windows ne peut pas être installé sur ce lecteur. (Afficher les détails) ». Un appui indique la raison :

Windows ne peut pas être installé sur ce disque. La configuration ou l'installation de disques connectés via des ports USB ou IEEE 1394 n'est pas prise en charge.

C'est le même blocage USB que pour la carte SD. À retenir : si « Suivant » reste grisé, toucher d'abord « Afficher les détails ». Cela aurait évité le détour par MBR et GPT.

28.7 La solution : écrire Windows à la main sur le SSD

Quand le programme d'installation refuse le lecteur, on écrit soi-même Windows dessus. Il ne faut pour cela que la fenêtre d'installation, le clavier USB et quatre outils : diskpart (partitions), dism (extraire Windows), bcdboot (fichiers de démarrage) et dir (chercher des fichiers).

Préparation : dans l'installation, fermer le message USB avec OK (l'installation reste ouverte à l'arrière-plan). Appuyer sur Maj + F10 : la fenêtre noire s'ouvre avec X:\sources>. Taper chaque ligne exactement ainsi et valider avec Entrée.

Étape 1 : partitionner le SSD

diskpart
list disk
select disk 1
clean
convert gpt
create partition efi size=260
format quick fs=fat32 label=EFI
assign letter=S
create partition primary
format quick fs=ntfs label=Windows
assign letter=W
exit
Commande Effet
diskpart lance le programme de partitionnement (invite DISKPART>)
list disk affiche tous les disques avec leur taille : ici 0 = 953 Go (Deck interne, tabou), 1 = 111 Go (SSD), 3 = 58 Go (clé Windows). Reconnaître le numéro du SSD à sa taille !
select disk 1 sélectionne le SSD
clean supprime toutes les partitions et données du disque sélectionné
convert gpt passe en GPT, compatible UEFI
create partition efi size=260 crée la petite partition EFI (260 Mo)
format quick fs=fat32 label=EFI formatage rapide en FAT32
assign letter=S attribue à la partition EFI la lettre S:
create partition primary crée la partition Windows sur le reste
format quick fs=ntfs label=Windows la formate en NTFS
assign letter=W lui attribue la lettre W:
exit quitte diskpart ; X:\sources> réapparaît

Si clean signale une protection en écriture, saisir avant attributes disk clear readonly et répéter clean.

Étape 2 : trouver le fichier Windows sur la clé

dir F:\sources\install.*

dir affiche des fichiers ; * signifie « n'importe quelle extension ». Ici la clé était F: ; on a trouvé install.wim (env. 6 Go). S'il y a install.esd, seul le nom du fichier change dans les commandes suivantes. Si « chemin introuvable », la clé a une autre lettre : essayer E:, G:, D: ou H: et vérifier avec dir F:\ que les dossiers sources, boot et efi s'y trouvent.

Étape 3 : choisir l'édition

dism /get-wiminfo /wimfile:F:\sources\install.wim

La sortie liste les éditions : index 1 = Windows 11 Famille, index 2 = Windows 11 Pro. J'ai choisi par erreur l'index 1 (Famille), alors qu'une licence Pro était prévue ; cela peut se changer après coup (28.9). Qui veut Pro prend /index:2 à l'étape 4.

Étape 4 : écrire Windows sur le SSD

dism /apply-image /imagefile:F:\sources\install.wim /index:1 /applydir:W:\

Un pourcentage défile pendant plusieurs minutes. Ne pas éteindre le Deck pendant ce temps. À la fin : « L'opération a réussi. »

Étape 5 : créer les fichiers de démarrage

bcdboot W:\Windows /s S: /f UEFI

Attendu : « Les fichiers de démarrage ont été créés avec succès. » Les fichiers de démarrage sont maintenant sur la partition EFI S:, Windows est complet sur W:.

Étape 6 : redémarrage depuis le SSD

  1. Saisir exit, fermer la fenêtre noire et l'installation (croix rouge, confirmer l'abandon), éteindre le Deck.
  2. Retirer la clé Windows, le SSD reste sur le hub.
  3. Maintenir volume moins, appuyer sur Power, choisir le SSD dans le menu de démarrage (« Windows Boot Manager » ou « EFI USB Device » ; pas SteamOS).
  4. Windows se configure ; un à deux redémarrages sont normaux. À chaque fois, choisir de nouveau le SSD.

Fautes de frappe typiques

  • « Tape ça et appuie sur Entrée » signifie : taper seulement la ligne de la case de commande, pas le mot « ça ».
  • Entre dism, /get-wiminfo et /wimfile il y a des espaces, dans /wimfile:F:\sources\install.wim aucun.
  • La barre oblique / introduit des options, la barre oblique inverse \ sépare les dossiers – ce sont des caractères différents.
  • Dans la fenêtre noire de l'installation, il n'y a pas de copier-coller ; tout se tape à la main. Dans la fenêtre Linux, coller se fait par clic droit ou via le menu.

28.8 Le premier démarrage de Windows et les pilotes

Problème : « Connectons-vous à un réseau ». La configuration exige Internet, mais sans pilote Wi-Fi il n'y en a pas. Deux voies :

  • Contournement : Maj + F10, puis oobe\bypassnro (barre oblique inverse au milieu). Le Deck redémarre ; choisir le SSD dans le menu de démarrage. Sur la page du réseau apparaît en bas « Je n'ai pas Internet » → « Continuer avec une configuration limitée » → créer un compte local (le mot de passe peut rester vide).
  • Placer les pilotes à l'avance sur une clé et les installer après le démarrage.

Installer les pilotes : Wi-Fi (qcwlan64.inf) → APU (setup.exe, redémarrage) → les trois .inf audio → en option Bluetooth (qcbtuart.inf) → redémarrage.

Problème : pas de son (chronologique)

Observation Cause Solution

Seulement deux pilotes audio installés la page Valve en liste désormais trois (en plus amdi2scodec.inf) installer les trois

28.9 Famille ou Pro ? Changer après coup

Passer à Pro est possible sans réinstallation : menu Démarrer → Paramètres → Système → Activation → « Modifier la clé de produit » → saisir la clé Pro de 25 caractères → Suivant. Windows télécharge Pro et redémarre. Sans licence Pro valide, on obtient une version Pro non activée (filigrane, pas de personnalisation). Pour la manette, les pilotes et les jeux, Famille suffit. Pro apporte surtout BitLocker, le Bureau à distance comme hôte, Hyper-V et les stratégies de groupe. Microsoft fournit une clé d'installation générique (VK7JG-NPHTM-C97JM-9MPGT-3V66T) qui convertit Famille en Pro, mais n'active rien.

28.10 La manette : mise à jour du firmware avec Accessoires Xbox

La mise à jour passe par l'application Accessoires Xbox (Microsoft Store) et seulement par câble USB, pas par Bluetooth.

Déroulement :

  1. Menu Démarrer → Microsoft Store → dans le champ de recherche « Accessoires Xbox » → installer l'application, l'ouvrir.
  2. Brancher la manette avec un câble de données sur le hub.
  3. Dans l'application apparaît la « XBOX Wireless Controller » : bouton aux trois points (…) → « Mise à jour du firmware ».
  4. Ne pas débrancher le câble ; la manette s'éteint brièvement et se rallume entre-temps.
  5. S'il est indiqué que la manette est à jour, le problème d'appairage ne vient pas du firmware.

Erreur 1 : « Erreur de connexion aux Gaming Runtime Services »

Au premier lancement, l'application a signalé : « Erreur de connexion aux services d'exécution de jeux … » avec les boutons Installer l'application XBOX, J'ai besoin d'aide, Annuler.

  • Cause : Accessoires Xbox utilise les services d'arrière-plan Gaming Services. S'ils manquent ou sont périmés, la connexion échoue.
  • Ce qui n'a pas aidé : « Installer l'application XBOX » (l'application était déjà là) ; la recherche « gaming services » dans le Store n'affichait en haut que de la publicité (un jeu de casino avec la mention « Annonce ») – on ne l'installe pas.
  • Solution : ouvrir directement la page du Store par lien. Lancer le navigateur Edge, saisir dans la barre d'adresse ms-windows-store://pdp/?productid=9MWPM2CQNLHN, Entrée, répondre « Ouvrir » à la question. La page Gaming Services apparaît. Le bouton bleu peut s'appeler Installer, Obtenir ou Mettre à jour ; ici l'application était périmée, « Mettre à jour » a téléchargé environ 59 Mo. Fermer Accessoires Xbox et le rouvrir.

Erreur 2 : « Votre appareil n'apparaît pas ? »

La manette clignotait : elle cherche en Bluetooth. Pour la mise à jour, elle doit être reliée par câble. Appui long sur la touche Xbox (éteindre), brancher par câble de données sur le hub (allumée en continu), fermer Accessoires Xbox et le rouvrir. Si cela n'aide pas : autre câble ou autre port ; dans le Gestionnaire de périphériques (appui long sur l'icône du menu Démarrer), chercher des signes d'avertissement jaunes.

Message 3 : « Obtenez une application pour ouvrir ce lien ms-gamebar »

Un lien supplémentaire de la Xbox Game Bar (vraisemblablement depuis l'icône en forme d'éprouvette). Sans importance pour la mise à jour : ne pas choisir « Rechercher dans le Store », fermer la fenêtre (toucher un endroit libre ou Échap), puis « … » et « Mise à jour du firmware ».

Après la mise à jour

De retour dans SteamOS : touche Steam → Paramètres → activer le Bluetooth. Sur la manette, maintenir le bouton d'appairage (petit bouton rond en haut à l'arrière) trois secondes, jusqu'à ce que la touche Xbox clignote rapidement ; elle apparaît dans la liste des appareils. Si cela ne marche pas, tester d'abord par USB. Que l'appairage ait réellement fonctionné après la mise à jour n'est pas confirmé dans ce chapitre.

28.11 Cloner Windows sur une carte SD (`dd` sur le Raspberry Pi)

Le SSD est pratique, mais une carte SD reste en permanence dans le Deck. Comme l'installation n'accepte pas la carte comme cible, l'installation terminée a été copiée à l'identique du SSD vers la carte, sur le Raspberry Pi 5 avec SSD (USB) et carte SD (lecteur de cartes).

D'abord les voies graphiques – et pourquoi elles ont échoué

Programme Message Cause Conséquence
SD Card Copier (menu Raspberry → Accessoires) « Table de partitions non MSDOS sur la source. » Le Copier ne connaît que MBR ; le SSD a GPT (Windows UEFI) Copie impossible ; formater la carte ne change rien, car l'erreur vient de la source
Programme de sauvegarde du Control Center « ERREUR : aucune zone système (ext4) trouvée sur /dev/sda. » Il est conçu pour les systèmes Linux et cherche un système racine ext4 ; Windows a NTFS Arrêt à l'étape 1 sur 8, avant que quoi que ce soit soit effacé (chapitre 39.2)

sudo umount /media/oratio/Windows

Démonter empêche les données de changer pendant la copie.

Étape 3 : copier

sudo dd if=/dev/sda of=/dev/mmcblk0 bs=4M status=progress conv=fsync
Élément Signification
sudo avec les droits d'administrateur
if=/dev/sda Source : tout le SSD (sans chiffre = tout le lecteur, pas une partition)
of=/dev/mmcblk0 Cible : toute la carte SD – il ne doit jamais y avoir ici un mauvais lecteur
bs=4M Taille de bloc 4 Mo, plus rapide que la petite valeur par défaut
status=progress affiche la progression en direct
conv=fsync écrit vraiment tout sur la carte à la fin, avant que dd annonce qu'il a terminé

L'affichage va jusqu'à environ 120 Go (SSD : 111,8 GiB = 120 034 123 776 octets). À environ 82 Mo/s, l'exécution a duré environ 24 minutes. C'est terminé quand l'invite réapparaît :

28618+1 Datensätze ein
28618+1 Datensätze aus
120034123776 Byte (120 GB, 112 GiB) kopiert, 1469,9 s, 81,7 MB/s

Pendant ce temps, ne pas fermer le terminal et ne pas éteindre le Pi.

Étape 4 : relire la table de partitions

sudo partprobe /dev/mmcblk0

partprobe dit à Linux de relire la table. Sans cela, lsblk montre encore l'ancienne partition unique. L'avertissement « Not all of the space available to /dev/mmcblk0 appears to be used … » est normal : la carte (238 Go) est plus grande que le SSD (111,8 Go), et la copie a placé la table de partitions de secours (backup GPT) à l'emplacement du plus petit SSD.

Étape 5 : démonter, réparer la table, terminer

sudo umount /dev/mmcblk0p1 /dev/mmcblk0p2
sudo apt install -y gdisk
sudo sgdisk -e /dev/mmcblk0
sync
lsblk
Commande Signification / message attendu
umount …p1 …p2 « not mounted » est normal – rien n'était monté
apt install -y gdisk installe sgdisk ; « déjà la dernière version » signifie : déjà présent
sgdisk -e /dev/mmcblk0 déplace la table de partitions de secours à la vraie fin de la carte : « The operation has completed successfully. »
sync force l'arrivée de toutes les écritures
lsblk Contrôle : mmcblk0p1 (260 M) et mmcblk0p2 (111,5 G) ; MOUNTPOINTS vide

« Visible » contre « monté » : visible signifie seulement que Linux connaît les partitions (apparaît dans lsblk). Monté signifie qu'elles sont reliées à un dossier. Sur la carte terminée, elles sont visibles mais pas montées – le bon état pour la retirer.

Étape 6 : retirer et démarrer

  1. Retirer la carte du Pi (l'éjection n'est pas nécessaire, rien n'est monté).
  2. Mettre la carte dans le Deck, débrancher le SSD du hub.
  3. Volume moins + Power, choisir EFI SD/MMC Card dans le menu de démarrage.
  4. Windows a démarré sans erreur, avec tous les réglages, les pilotes, de façon fluide.

Ne pas cliquer dans le gestionnaire de fichiers : sur le Pi, deux entrées « Windows » sont apparues à gauche (le SSD et la carte portent le même nom, car dd l'a copié aussi). Cliquer monterait la partition et Linux pourrait y écrire quelque chose ; Windows signale ensuite éventuellement « non déconnecté proprement ».

Règles pour dd

  1. Copier le lecteur entier (sda, pas sda2), sinon la table de partitions et les fichiers de démarrage manquent.
  2. La cible doit être au moins aussi grande que la source ; sinon dd s'arrête ou coupe la fin (alors Clonezilla ou Macrium Reflect Free).
  3. Si la cible est plus grande, le reste reste inutilisé tant qu'on n'agrandit pas la partition (28.12).
  4. La cible est entièrement écrasée. Une erreur à of= est irréversible.
  5. La source ne doit pas être utilisée (démontée) ; ne jamais copier depuis le disque système en cours d'utilisation.
  6. Ne jamais brancher en même temps l'original et la copie sur le même ordinateur Windows (mêmes identifiants).
  7. Linux clone presque toujours sans problème. Windows démarre le plus souvent sans problème sur le même matériel ; sur un autre matériel, il peut rester bloqué sur « Inaccessible Boot Device » ou demander la clé de récupération BitLocker.

Sauvegarde personnelle sous forme de fichier

Un Windows qui fonctionne sert de modèle. Au lieu de réinstaller, on peut le sauvegarder sous forme de fichier compressé (méthode standard ; la ligne de restauration n'a pas été testée dans ce projet) :

sudo dd if=/dev/mmcblk0 bs=4M status=progress | gzip > windows-backup.img.gz
gzip -dc windows-backup.img.gz | sudo dd of=/dev/mmcblk0 bs=4M status=progress conv=fsync

Le fichier de sauvegarde doit se trouver sur un autre lecteur.

28.12 Après le clonage : utiliser l’espace, identifiants en double

Pourquoi la carte n'affiche que 111 Go : dd copie exactement la taille de la source. Sur la carte de 256 Go, la partition Windows ne fait donc qu'environ 111 Go ; les quelque 126 Go restants sont « non alloués ».

Possibilité A : agrandir C:. Appui long sur l'icône du menu Démarrer → Gestion des disques → appui long sur C: → Étendre le volume → Suivant, Suivant, Terminer. Si « Étendre le volume » est grisé, une autre partition (par exemple une partition de récupération) se trouve entre C: et l'espace libre ; examiner alors précisément la gestion des disques. Étendre n'efface aucune donnée.

Possibilité B : créer un second lecteur D:. Dans la gestion des disques, appui long sur le bloc noir Non alloué → Nouveau volume simple → Suivant, Suivant (taille complète), lettre D, Suivant → NTFS, nom par ex. « Daten » → Terminer.

D: comme second lecteur Étendre C:
Avantage Windows et données séparés ; on peut réinstaller Windows sans toucher aux données un grand bloc
Inconvénient C: seulement 111 Go ; Windows, pilotes et mises à jour demandent environ 30–40 Go et grandissent tout dans un seul pot
Conseil jeux et fichiers personnels sur D: plus tard, supprimer D: et étendre C: reste possible

Un dd ultérieur de toute la carte copie aussi D: (alors 238 Go). Identifiants en double : le SSD et la carte sont des jumeaux avec les mêmes ID internes. Sous Windows, ne jamais brancher les deux en même temps ; Windows peut sinon mettre l'un hors ligne à cause de l'ID en double. Le SSD est maintenant la sauvegarde. Le mieux est de garder les dossiers de pilotes sur D:.

28.16 Contexte et alternatives

Installer Windows depuis la console de SteamOS ? En partie. En mode Bureau, il y a la console (bash). On peut y préparer des lecteurs avec sgdisk et mkfs.ntfs, et l'image Windows pourrait être écrite sur le disque avec le programme wimlib. wimlib n'est pas préinstallé, nécessite que la protection en écriture soit désactivée et peut disparaître après une mise à jour de SteamOS. Les fichiers de démarrage ne sont créés que par bcdboot, qui n'existe que sous Windows ; l'installation de Windows avec Maj + F10 reste donc nécessaire pour cette seule commande. Avantage dans SteamOS : on peut coller des commandes depuis le navigateur, alors que dans l'installation de Windows il faut tout taper.

dd dans le Bureau SteamOS fonctionne comme sur le Pi, sans restriction. Sur le Deck : nvme0n1 = lecteur interne (jamais comme cible), sda = SSD externe, mmcblk0 = carte SD ; vérifier tout de même toujours les tailles avec lsblk. Si sgdisk est préinstallé n'a pas été vérifié (sgdisk --version) ; sinon sudo parted /dev/mmcblk0 print aide. Avant cela, une fois passwd pour le mot de passe sudo.
