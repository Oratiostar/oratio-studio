Ce chapitre décrit comment le projet B (chapitres 36–39) a été porté du Raspberry Pi 5 vers le Steam Deck : ce qui est différent, ce qui s'est cassé, pourquoi, et comment le réparer. Il vaut aussi pour tout autre ordinateur x86 sous Linux (par ex. un portable). Les projets annexes nés au passage ont leurs propres chapitres (cadran : chapitre 25, site web : chapitre 44).

43.1 Le projet et l’idée derrière

43.1.1 Ce qu'est l'Oratio Control Center

L'Oratio Control Center (OCC en abrégé) est une interface que j'ai écrite en Python avec PyQt5. Elle rassemble en un seul endroit tout ce dont j'ai besoin chaque jour sur un petit ordinateur : un menu avec des applications (fichiers, navigateur, notes, calendrier, calculatrice, terminal, mise à jour, sauvegarde, connexions, Oratio AI et plus), des widgets comme l'horloge et la météo, des interrupteurs rapides pour le WLAN et le Bluetooth et – uniquement sur le Raspberry Pi – la commande du ventilateur, du ruban de LED et de l'écran OLED de la tour Freenove.

Le programme est né sur le Raspberry Pi 5. Ce cours explique comment je l'ai porté ensuite sur le Steam Deck, ce qui s'est cassé, pourquoi, et comment le réparer. S'y ajoutent trois projets annexes du même environnement : un assistant IA local avec la voix, un cadran pour un écran AMOLED rond avec ESP32-S3 et le site web « Oratio Place ».

43.1.2 Les trois appareils en un coup d'œil

Raspberry Pi 5 Steam Deck (LCD/OLED) Portable (par ex. Zenbook 14, Ryzen AI 7)
Architecture du processeur ARM (aarch64) x86_64 (AMD Zen 2) x86_64 (AMD Zen 5)
Système d'exploitation Raspberry Pi OS (Debian), labwc/Wayland SteamOS (basé sur Arch, protégé en écriture), KDE Plasma Windows (ou Linux)
Gestion des paquets apt, avec sudo pas d'apt ; pip dans un venv, Flatpak selon le système
Broches GPIO (ventilateur, LED, OLED) ja non non
Graphismes faibles, mais suffisants pour des interfaces nettement plus puissants, adaptés aux jeux puissants, adaptés aux jeux
Point fort bricolage, matériel, fonctionnement 24 h/24, faible consommation console portable, jeux, mobilité, écran tactile, batterie travail, mobilité, batterie, silence

Appréciation honnête : sur le Steam Deck, l'OCC tourne nettement plus fluide que sur le Pi, parce que le processeur et le graphisme offrent bien plus. Mais le Pi reste le bon appareil dès que du matériel doit aller sur les broches. Un portable moderne est en tête pour la puissance de calcul pure et la batterie ; pour les modèles d'IA locaux, c'est surtout la mémoire vive qui compte. Les chiffres de benchmark exacts et les prix actuels changent sans cesse – avant un achat, mieux vaut les chercher à jour.

43.2 Préparer le Steam Deck

43.2.1 Mode bureau et console

Le Steam Deck a deux mondes. Le mode jeu est l'interface Steam. Le mode bureau est un bureau KDE Plasma normal. L'OCC tourne en mode bureau ; le mode jeu a été abandonné dans le projet après des essais, parce que les fenêtres et les entrées y sont traitées autrement (le doigt y arrive comme une souris, pas comme du tactile).

  1. Appuyer sur la touche Steam, puis choisir « Alimentation ».

  2. Toucher « Passer au bureau ». Au bout de quelques secondes, le bureau apparaît.

  3. En bas à gauche dans le menu de démarrage (symbole à gauche dans la barre), ouvrir l'entrée « Système » et y lancer « Konsole ».

43.2.2 Pourquoi le Deck est différent du Pi

SteamOS est protégé en écriture. Le disque système ne se modifie pas simplement, et il n'y a pas d'apt. Cela a des conséquences pour tout ce que j'aurais résolu sur le Pi avec « sudo apt install … » :

  • Les paquets Python vont dans un environnement à part (venv) dans le dossier personnel.

  • Les programmes qui ne sont pas écrits en Python se téléchargent dans le dossier personnel (exemple : Ollama dans ~/ollama, Piper dans Oratio_Menu/Modelle).

  • Les programmes graphiques supplémentaires s'installent via Flatpak (Discover) – c'est la voie autorisée sous SteamOS.

  • Après de grosses mises à jour de SteamOS, tout ce qui se trouve en dehors du dossier personnel peut disparaître. Tout ce qui est dans le dossier personnel reste.

43.2.3 Créer le venv

python -m venv ~/oratio-venv
source ~/oratio-venv/bin/activate
pip install PyQt5

La première commande crée l'environnement, la deuxième l'active dans cette fenêtre de console (la ligne de saisie commence alors par « (oratio-venv) »), la troisième y charge PyQt5. Si pip signale « externally managed environment », le venv n'a pas été activé – répéter la deuxième commande.

43.2.4 Lancer le programme

cd ~/Downloads/Oratio_Control_Center
bash deck_start.sh

deck_start.sh fait trois choses : il active le venv, désactive la mise à l'échelle automatique de Qt et calcule un facteur d'échelle propre à partir de la hauteur de l'écran. 1080 pixels de hauteur correspondent au facteur 1,0, un téléviseur 4K (2160 pixels) au facteur 2,0. L'écran du Deck (800 pixels de haut) reste à 1,0. Ainsi l'interface ne paraît pas minuscule sur le téléviseur.

À retenir : F11 active et désactive le plein écran. Un programme redémarré masque brièvement le plein écran ; on y revient par la barre des tâches en bas.

43.2.5 Comme icône dans le mode jeu

Qui veut quand même un bouton de démarrage dans le mode jeu : en mode bureau, ouvrir Steam, « Jeux » → « Ajouter un jeu non-Steam », « Parcourir », choisir le type de fichier « Tous les fichiers » et sélectionner deck_start.sh. À cause des différences d'entrée, cela reste une solution de secours.

43.3 plattform.py : un dossier pour deux appareils

Au lieu d'entretenir deux programmes séparés, il y a un fichier qui détecte où le programme tourne. Sur le Pi, rien ne change ; sur d'autres appareils, les parties Pi sont masquées. Dans les fichiers JSON, les entrées sont conservées – elles ne sont simplement pas affichées.

43.3.1 Comment le Pi est reconnu

with open("/proc/device-tree/model", "rb") as f:
IST_PI = b"raspberry" in f.read().lower()

Sur le Pi, ce fichier contient le nom de la carte (« Raspberry Pi 5 Model B … »). Sur le Deck, le fichier n'existe pas, le programme intercepte l'erreur et met IST_PI à faux. On peut le forcer avec une variable d'environnement : ORATIO_PI=1 (faire comme si c'était un Pi) ou ORATIO_PI=0 (faire comme si ce n'était pas un Pi). C'est pratique pour tester.

43.3.2 Ce qui est masqué sur le Deck

Entrée Pourquoi seulement Pi
Onglet Tower, LED, ventilateur, OLED nécessitent le GPIO/I²C de la tour Freenove
Raspi Config, SD Card Copier, Pi Imager outils de Raspberry Pi OS
Oratio Backup clone le système du Pi avec rsync et /boot/firmware
Oratio Labor travaille avec les broches du Pi
Kanshi disposition des écrans sous labwc (wlr-randr), KDE a ses propres réglages
Oratio Update appelle apt – SteamOS n'a pas d'apt
Oratio Control Center (comme application) se lançait via run_app.sh avec un chemin Pi fixe

43.3.3 Autres caractéristiques

  • IM_SPIELEMODUS : détecte Gamescope via les variables d'environnement SteamGameId, GAMESCOPE_WAYLAND_DISPLAY ou le nom du bureau.

  • KANN_APT : vrai seulement si apt-get et pkexec sont présents. De cela dépend si un bouton « Installer » peut travailler via une fenêtre de mot de passe ou doit prendre une autre voie.

  • Choix du terminal : le programme cherche lxterminal (Pi), konsole (Deck/KDE), x-terminal-emulator ou xterm – dans cet ordre.

$(command -v lxterminal || command -v konsole || echo xterm)

Cette expression est une technique de shell typique : « command -v » affiche le chemin d'un programme s'il existe, et « || » passe à la possibilité suivante sinon. Le code n'a ainsi besoin d'aucune connaissance de l'appareil.

43.4 Installer d’un clic

Sur le Deck manquaient au départ des choses déjà installées sur le Pi : le serveur d'IA Ollama, le modèle de langage, la reconnaissance vocale et la synthèse vocale. L'exigence était : l'utilisateur ne doit rien installer à la main, mais trouver partout où quelque chose manque un bouton « Installer ». Cette partie explique comment cela est construit.

43.4.1 Le principe

  1. Le programme vérifie si le composant est présent (fichier, module, serveur joignable).

  2. S'il manque, un bouton « Installer » apparaît (invisible auparavant).

  3. Un clic lance un thread de travail (QThread) ou une fenêtre de terminal avec le script d'installation.

  4. Les messages de progression circulent comme signaux vers l'interface ; à la fin, on revérifie et le bouton disparaît.

À retenir : le thread est important : si le téléchargement tournait dans le programme principal, la fenêtre gèlerait jusqu'à sa fin.

43.4.2 Ollama sans droits d'administrateur

Ollama est un programme qui exécute des modèles d'IA en local et fournit un petit serveur web (port 11434). Sur un Linux normal, on l'installe avec un script qui touche aux fichiers système. Sous SteamOS, ce n'est pas possible. La solution (fonction ollama_installieren dans Oratio_AI.py) :

  1. Télécharger l'archive (tar.zst ou tgz) depuis ollama.com dans le dossier ~/ollama et la décompresser.

  2. Démarrer le serveur avec « ollama serve » en arrière-plan.

  3. Attendre que http://127.0.0.1:11434/api/tags réponde.

  4. Charger le modèle via l'interface /api/pull – le serveur envoie alors la progression en continu, qui s'affiche en pourcentage.

curl http://127.0.0.1:11434/api/tags # quels modèles sont là ?
~/ollama/bin/ollama list # la même chose dans la console
~/ollama/bin/ollama pull gemma3:1b # charger un modèle

43.4.3 Quel modèle ?

Une erreur que j'avais faite : dans le code figurait en dur « gemma3:4b », mais seul « gemma3:1b » était installé. Résultat dans la fenêtre : « Modell gemma3:4b ist nicht installiert ». La solution est une fonction ki_modell() qui lit le nom dans le fichier Apps/Oratio_AI/ai_einstellungen.json (par défaut gemma3:1b). Maxime : les noms de modèles ne vont jamais en dur dans le code.

Modèle Taille approximative Caractéristique
gemma3:1b ca. 0,8 GB rapide, tourne partout, mais comprend peu le contexte
gemma3:4b ca. 3 GB nettement meilleur en compréhension, plus lent, demande plus de RAM

43.4.4 L'installateur vocal install_sprache.sh

Le script a six étapes, tient compte du Deck (pas d'apt sous SteamOS) et utilise le Python du programme en cours. Le programme transmet ce Python via la variable d'environnement OCC_PYTHON, pour que pip installe dans le bon venv.

  1. Préparation et détection du système.

  2. Installer Vosk (paquet Python).

  3. Charger le petit modèle allemand de Vosk.

  4. Installer faster-whisper (taille de modèle tiny, base, small ou medium).

  5. Télécharger Piper (bonne architecture !) et charger la voix « Thorsten » ; Piper est testé avec « --help ».

  6. Mettre en place Ollama et le modèle d'IA.

43.4.5 Le navigateur : QtWebEngine

L'Oratio Browser a besoin de QtWebEngine. S'il manque, un bouton « Installer » apparaît, qui exécute « pip install PyQtWebEngine » (nom du paquet selon la version : PyQt5-WebEngine) dans le venv. Un QTimer vérifie toutes les quelques secondes si l'import fonctionne maintenant, et relance alors le navigateur.

python -c "from PyQt5.QtWebEngineWidgets import QWebEngineView; print('ok')"

43.5 Oratio AI : un assistant local

43.5.1 Structure

Oratio AI est une fenêtre de discussion. La question part vers un serveur Ollama local (Gemma), la réponse apparaît dans l'historique. Tout reste sur l'appareil, il n'y a ni accès au cloud ni compte.

Élément Rôle
send() prend le texte, lance CmdWorker
CmdWorker vérifie d'abord s'il s'agit d'une commande locale (sprachsteuerung.befehl)
_cmd_fertig affiche la réponse locale et la prononce au besoin
_gemma(text) si aucune commande ne correspondait : question au modèle de langage
InstallWorker exécute les installations en arrière-plan
btn_mic (« Sprechen ») dicte la question avec le microphone

43.5.2 Pourquoi les commandes sont d'abord traitées en local

Gemma 1B ne connaît ni l'heure, ni la date, ni la météo. Interrogé sur l'heure, le modèle a inventé « 17:22 ». Un modèle de langage devine des probabilités, il ne lit pas une horloge. C'est pourquoi le programme vérifie avant chaque requête, par des règles (simples comparaisons de texte), si une question relève d'une fonction fixe :

Question La réponse vient de
« Wie spät ist es ? » horloge système de l'appareil
« Welcher Tag ist heute ? » date du système
« Wie wird das Wetter morgen ? » Open-Meteo (gratuit, sans clé)
tout le reste Gemma via Ollama

Pour la météo, il faut un lieu. Le programme prend la valeur du réglage « ort » ; s'il manque, il estime le lieu à partir de l'adresse IP (ip-api). Le lieu est ensuite converti en coordonnées (géocodage) et la prévision est demandée.

À retenir : règle générale : tout ce qui doit être exact (heure, calcul, météo) relève du code ou d'une source de données – jamais du modèle de langage.

43.5.3 La disposition de la fenêtre et la marge

Un défaut visible : les boutons « Kurz/Normal/Lang », « Neu », la barre de saisie et « Senden » dépassaient de la fenêtre bleue sur le fond violet. Cause : la disposition avait 4 pixels de marge, mais la surface bleue (fonction sims_look) a 12 pixels de remplissage intérieur. Les éléments commençaient donc avant la surface. Solution : marge = 12 + S(8), où S() applique le facteur d'échelle, plus des largeurs flexibles et minimumSizeHint, pour que rien ne soit forcé plus large que la fenêtre.

À retenir : maxime : la marge de la disposition doit être au moins aussi grande que le remplissage intérieur de la surface dessinée.

43.6 Langue : écouter et parler

43.6.1 Trois parties, trois rôles

Rôle Outil Caractéristique
Écouter (commandes, rapide) Vosk petit, hors ligne, ne reconnaît que des phrases simples
Écouter (dictée, plus précise) faster-whisper modèles tiny/base/small/medium : plus grand = meilleur et plus lent
Parler Piper voix neuronale, hors ligne (de_DE Thorsten, qualité medium/high)
Lecture audio paplay / aplay lisent le fichier WAV produit
Enregistrement pw-record / parecord enregistrent depuis le microphone

43.6.2 Le microphone du Steam Deck

Le Deck a ses propres microphones intégrés, qui apparaissent sous Linux comme un périphérique d'entrée audio normal. La console montre quelle source d'enregistrement est active :

pactl list short sources # alle Aufnahmequellen
pactl get-default-source # Standardquelle
parecord --channels=1 --rate=16000 test.wav # aufnehmen (Strg+C beendet)
paplay test.wav # abspielen

Si l'enregistrement est faible ou vide, choisir le bon périphérique d'entrée dans les réglages audio de KDE (symbole du haut-parleur en bas à droite) et vérifier le volume.

43.6.3 Qualité de la reconnaissance – un bilan honnête

Le microphone fonctionnait, mais la reconnaissance était mauvaise : des phrases devenaient des mots étrangers. Cela ne tient pas à une erreur du programme, mais à la taille des modèles. Vosk-small a peu de mots et presque aucune compréhension de phrase. Whisper tiny et base sont trop faibles pour l'allemand. C'est pourquoi la valeur par défaut a été relevée à « small » et « medium » ajouté, avec beam_size=5 (la largeur de recherche au décodage) et vad_filter=True (supprime le silence, pour que Whisper n'invente pas de mots dans les pauses).

Modèle Whisper Qualité en allemand Téléchargement Vitesse sur le Deck
tiny mauvaise ca. 75 MB très rapide
base moyenne ca. 150 MB rapide
small utilisable ca. 500 MB bon
medium bonne ca. 1,5 GB nettement plus lent

La comparaison avec l'assistant de l'iPhone ou les grands assistants cloud est boiteuse : ils tournent dans des centres de calcul avec d'énormes modèles. Hors ligne sur une console portable avec un modèle d'un milliard de paramètres, Gemma 1B comprend tout simplement moins. Deux voies ont été nommées : (1) une reconnaissance cloud comme Whisper large via une clé Groq – nettement meilleure, mais l'audio quitte l'appareil ; (2) laisser la commande vocale aux commandes simples. Cette décision est encore ouverte.

Attention : reconnaissance cloud signifie que l'enregistrement part vers un serveur étranger. C'est un compromis sur la protection des données, qu'il faut choisir consciemment.

43.6.4 L'erreur « Exec format error »

Piper ne disait rien. Le journal ~/oratio_sprechen.log montrait « Exec format error ». Cela signifie : le système d'exploitation ne peut pas exécuter le fichier, parce qu'il est construit pour une autre architecture de processeur. Le fichier Piper avait été copié depuis le Pi (aarch64/ARM), le Deck est en x86_64. Un binaire ARM ne tourne jamais sur x86.

file ~/Downloads/Oratio_Control_Center/Oratio_Menu/Modelle/piper/piper/piper
uname -m # x86_64 = Deck, aarch64 = Pi
cat ~/oratio_sprechen.log # Log LESEN, nicht ausführen

La réparation est dans l'installateur : il appelle « piper --help ». Si cela échoue, le dossier est supprimé et la version x86_64 est rechargée. De plus, la lecture a été modifiée : d'abord le fichier audio complet est produit, puis paplay le joue. Le streaming direct vers le lecteur bégayait et s'interrompait.

À retenir : leçon : ne jamais copier entre le Pi et le PC/Deck des dossiers contenant des programmes compilés sans vérifier l'architecture. Les scripts (Python, Bash) ne posent pas de problème, les binaires oui.

43.6.5 Les fenêtres de terminal de la mise en place

Le bouton « Sprache einrichten » ouvre un terminal pour qu'on voie la progression. L'ordre de recherche est lxterminal, konsole, x-terminal-emulator, xterm. Le terminal reçoit OCC_PYTHON pour que le script prenne le bon Python. Le bouton « Stimme testen » produit une phrase d'exemple et la joue ; les erreurs vont dans le journal.

43.6.6 Une voix qui sonne mieux

La première voix (Thorsten medium) sonnait métallique. La variante thorsten-high est plus grande et plus naturelle ; stimme_modell() la préfère quand elle est présente. Plus de naturel n'existe actuellement pas hors ligne sans nettement plus de calcul.

43.7 Le grand audit Pi→Deck

Après les erreurs est venue la consigne : tout ce qui a été écrit à l'origine pour le Pi doit être examiné systématiquement. Méthode : chercher les commandes qui n'existent pas sur le Deck et décider pour chacune – remplacer, masquer ou expliquer.

cd ~/Downloads/Oratio_Control_Center
grep -rn "apt\sudo\lxterminal\wlr-randr\grim\slurp" --include=*.py --include=*.sh .

grep -rn parcourt tous les fichiers sous le dossier et indique le fichier et le numéro de ligne. Avec --include, on se limite à certains types de fichiers.

43.8.1 Marche à suivre pour une erreur inconnue

  1. Lire précisément : la dernière ligne d'un message d'erreur Python nomme le type, les lignes au-dessus le chemin.

  2. Lancer depuis la console, pas par l'icône – sinon on ne voit pas le message.

  3. Vérifier Logs/ et les fichiers journaux dans le dossier personnel.

  4. Changer une seule chose, retester. Jamais cinq choses à la fois.

  5. Si cela marche sur le Pi et pas sur le Deck : chercher les différences (architecture, apt, terminal, chemins).

43.9 Le Deck sur la télévision : overscan

J'utilise parfois le Deck uniquement avec le moniteur externe (téléviseur), son propre écran est éteint. Problème : le texte au bord était coupé. Cause : beaucoup de téléviseurs agrandissent légèrement l'image au-delà du bord (overscan), pour masquer d'anciens signaux de chaînes.

43.9.1 D'abord sur le téléviseur

Dans les réglages d'image du téléviseur, mettre le format sur « Adaptation à l'écran », « Just Scan », « 1:1 », « Plein » ou « Original » (le nom dépend de la marque). Cela supprime l'overscan à la source et c'est la solution la plus propre.

43.9.2 Puis dans KDE

  1. Sur le bureau, ouvrir en bas à gauche le menu de démarrage, choisir « Paramètres système ».

  2. Dans la liste de gauche, ouvrir « Affichage et moniteur » → « Configuration de l'affichage ».

  3. Sélectionner le téléviseur. Selon la version de Plasma, il y a un réglage « Overscan » (en pourcentage) ou « Échelle ».

  4. Augmenter lentement la valeur jusqu'à ce que le bord soit visible, puis appuyer sur « Appliquer » et confirmer dans les 15 secondes.

Dans l'OCC, il y a en plus la marge de la surface de verre (sims_look(rand=12)) : elle tient les contenus éloignés du bord de la fenêtre et aide quand il ne manque que quelques pixels.
