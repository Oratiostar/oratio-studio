1.1 Was ist das Terminal?

Das Terminal ist ein Fenster, in dem man dem Computer Textbefehle gibt. Auf dem Raspberry Pi läuft Linux. Fast alles, was sich mit der Maus erledigen lässt, geht auch über Befehle, und oft ist es so schneller und genauer. Das Terminal lässt sich direkt auf dem Pi oder über SSH von einem anderen Gerät benutzen.

Ein Befehl hat meistens diese Form:

befehl  -optionen  ziel

Beispiel:

ls -la /home/oratio

ls ist der Befehl, -la sind Optionen (Schalter), /home/oratio ist das Ziel.

1.2 Wo bin ich? Dateien und Ordner

Befehl Bedeutung Beispiel
pwd zeigt den aktuellen Ordner pwd
ls listet Dateien auf ls
ls -la alles, auch versteckte Dateien, mit Details ls -la
cd Ordner in einen Ordner wechseln cd Projekte
cd .. eine Ebene zurück cd ..
cd ~ in den Home-Ordner cd ~
mkdir Name Ordner anlegen mkdir Test
touch datei.txt leere Datei anlegen touch test.txt
cat datei.txt Dateiinhalt anzeigen cat test.txt
cp a.txt b.txt kopieren cp datei.txt kopie.txt
mv a.txt Ordner/ verschieben oder umbenennen mv datei.txt Ordner/
rm datei.txt löschen (endgültig, kein Papierkorb!) rm datei.txt

Wichtig: rm löscht sofort und ohne Rückfrage. Es gibt keinen Papierkorb. Ein Ordner wird mit rm -r Ordner gelöscht. Der Befehl rm -rf ist besonders gefährlich, weil er nie nachfragt.

Das Zeichen ~ steht für den Home-Ordner, bei mir /home/oratio. Mit der Tab-Taste werden Dateinamen automatisch vervollständigt, und mit den Pfeiltasten hoch/runter kommen frühere Befehle zurück.

1.3 Dateien bearbeiten mit nano

nano ist der einfachste Texteditor im Terminal. Ich brauche ihn ständig.

nano ~/.bashrc

Bedienung in nano (die Tastenkürzel stehen unten im Fenster):

  • Speichern: Strg + O, dann Enter
  • Beenden: Strg + X
  • Wenn nano nach dem Speichern fragt: Enter bestätigt den Dateinamen.

Beim Einfügen von langem Code in das Terminal kann es sehr lang dauern, ihn wieder zu löschen. In nano löscht Strg + K eine ganze Zeile.

1.4 Hilfe holen

man ls          # ausführliche Anleitung (Beenden mit q)
ls --help       # Kurzhilfe
history         # alle bisherigen Befehle
history | grep wlr    # nur Befehle, in denen "wlr" vorkommt
!!              # den letzten Befehl wiederholen

1.5 Der senkrechte Strich: die Pipe

Das Zeichen | (die Pipe) schickt die Ausgabe des ersten Befehls an den zweiten weiter. Ich habe sie ständig benutzt:

ps aux | grep python         # Prozesse anzeigen, aber nur die mit "python"
dmesg | tail                 # die letzten Kernel-Meldungen
wlr-randr | grep Scale       # nur die Zeile mit der Skalierung

1.6 Befehle verketten

Zeichen Bedeutung
&& zweiter Befehl nur, wenn der erste geklappt hat
; zweiter Befehl immer
& am Ende im Hintergrund starten (z. B. kanshi &)
> Ausgabe in eine Datei schreiben (überschreibt)
>> Ausgabe an eine Datei anhängen 
sudo apt update && sudo apt upgrade -y
echo "Text" >> datei.txt

1.7 Ein typischer Fehler: das zusätzliche Zeichen

Ein typischer Tippfehler: <wlr-randr --output HDMI-A-1 --scale 3 eingegeben. Das < vorn am Befehl bedeutet in der Shell: „lies den Inhalt aus einer Datei". Die Shell meldet dann, dass die Datei nicht gefunden wurde. Merke: Befehle exakt abtippen, jedes Zeichen zählt. Auch Groß- und Kleinschreibung zählt unter Linux.
