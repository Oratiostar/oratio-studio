33.1 Le nom du nouvel onglet

Après l'onglet de scripts est venu le souhait d'un onglet uniquement pour les commandes Raspberry Pi dont j'ai constamment besoin : régler l'écran en 4K, lire la température, redémarrer. Avant de construire, il fallait que le nom soit fixé, car il revient dans des fichiers, des classes et des libellés. Mes réflexions :

Candidat Évaluation
« Tools » trop général, ne dit pas qu'il s'agit du Pi
« Commander » sonne comme un gestionnaire de fichiers (comme un gestionnaire à deux fenêtres)
« Oratio Pi Tools » porte mon nom comme les autres parties et dit de quoi il s'agit

Règle de nommage pour fichiers et classes que je me suis fixée à cette occasion :

  • Fichiers et modules Python en minuscules avec tiret bas : pi_tools.py.
  • Classes en « CamelCase », sans tiret bas : PiToolsTab.
  • Les noms de dossiers peuvent commencer par une majuscule : Pi_Tools/.
  • Ce qui figure dans l'interface (« Oratio Pi Tools », avec espaces) n'est qu'un texte que l'on saisit à un endroit comme nom d'onglet. Il n'a rien à voir avec le nom du fichier.

from pi_tools import PiTools signifie : depuis le fichier pi_tools.py prendre la classe PiTools. Le premier mot est le fichier (le module), le second la classe qu'il contient.

33.2 Un onglet avec des boutons fixes

La première ébauche consistait en une classe avec des boutons et une fonction par commande :

class RaspberryPiTab(QWidget):
    def __init__(self):
        super().__init__()
        layout = QGridLayout()
        btn_4k = QPushButton("4K Scale 3")
        btn_reboot = QPushButton("Neustart")
        btn_temp = QPushButton("Temperatur")
        layout.addWidget(btn_4k, 0, 0)
        layout.addWidget(btn_reboot, 0, 1)
        layout.addWidget(btn_temp, 1, 0)
        self.setLayout(layout)
        btn_4k.clicked.connect(self.set_4k)
        btn_reboot.clicked.connect(self.reboot)
        btn_temp.clicked.connect(self.temp)

    def set_4k(self):
        subprocess.Popen(["wlr-randr", "--output", "HDMI-A-1",
                          "--mode", "3840x2160", "--scale", "3"])

    def reboot(self):
        subprocess.Popen(["lxterminal", "-e", "sudo reboot"])

    def temp(self):
        subprocess.Popen(["lxterminal", "-e", "vcgencmd measure_temp"])

Cela fonctionne. Le problème apparaît à la commande 20 : la classe reçoit une fonction pour chaque commande, le code devient confus, et chaque nouveau bouton signifie modifier du code Python.

33.3 Les données dans un fichier JSON

JSON est un format texte pour des listes et des entrées. Au lieu d'écrire chaque bouton en Python, un fichier indique ce qui existe. Le code Python lit le fichier et construit les boutons :

[
    {"name": "Backup", "file": "backup.py"},
    {"name": "Hash",   "file": "hashchecker.sh"},
    {"name": "Kanshi", "type": "import"},
    {"name": "OLED",   "file": "OLED/oled.py"}
]
with open("oratio_apps.json", "r") as f:
    apps = json.load(f)
for i, app in enumerate(apps):
    ...   # pro Eintrag eine Kachel anlegen

Conséquences que j'ai remarquées :

  • Le nombre de tuiles ne figure plus dans le programme. 25 entrées donnent 25 tuiles, 30 en donnent 30.
  • La position vient aussi du fichier : "row" et "col" (plus tard "slot"). Deux entrées à la même place se recouvrent, la dernière créée est au-dessus.
  • JSON exige une syntaxe exacte : guillemets, virgules entre les entrées, aucune après la dernière. Une virgule oubliée fait échouer tout le fichier. Vérifier : python3 -m json.tool oratio_apps.json.

33.4 Deux façons d’ouvrir un programme

Une entrée peut démarrer de deux façons, et le choix a des conséquences visibles :

Type Comment Quand c'est judicieux
run_file() lance un nouveau processus (subprocess.Popen) scripts : Hash-Checker, sauvegarde, scripts Bash et PowerShell
"type": "import" importe la classe et l'ouvre dans le programme en cours petites boîtes de dialogue : Kanshi, fenêtres d'information

Avec la boîte de dialogue Kanshi, j'ai vu la différence immédiatement : avec run_file, une seconde fenêtre est apparue en plus, parce qu'un second programme Python entier démarrait. Avec l'import, seule la boîte de dialogue s'ouvre :

if app.get("type") == "import" and app["name"] == "Kanshi3":
    dialog = KanshiDialog()
    dialog.exec_()
    return

Règle empirique : interface = importer, scripts = lancer comme processus.

33.5 Sortir les commandes du programme principal

Finalement, il y avait trop de commandes pour le fichier principal. La répartition que j'ai fixée :

Fichier Rôle
app_ui.py uniquement fenêtre, boutons, glissement, chargement du JSON, détection des clics
oratio_apps.json uniquement nom, icône, position, nom de l'outil
Pi_Tools/pi_tools.py uniquement les commandes : température du CPU, RAM, SSD, Wi-Fi, Bluetooth, USB, redémarrage, capture d'écran …

Dans le JSON, on trouve alors un outil au lieu d'un nom de fichier :

{"name": "CPU Temp", "tool": "cpu_temp"}

et le programme principal appelle pi_tools.cpu_temp(). Plus de 20 ou 50 fichiers individuels. Cette idée réapparaît dans le projet B (chapitre 38 : la Toolbox).

33.6 L’outil Kanshi : mise à l’échelle de l’écran d’un clic

Le Pi 5 sur le moniteur 4K a besoin d'une mise à l'échelle, sinon tout est minuscule (chapitre 10). Je voulais la choisir d'un clic. L'outil écrit le fichier de configuration de Kanshi (~/.config/kanshi/config) et redémarre Kanshi :

profile monitor
{
    output HDMI-A-1 mode 3840x2160 scale 3
}
subprocess.run(["pkill", "kanshi"], stderr=subprocess.DEVNULL)
subprocess.Popen(["kanshi"])

Sur le chemin vers une boîte de dialogue fonctionnelle, des erreurs sont apparues. Chacune a une leçon :

Observation Cause Ce que j'en fais
Après « OK », rien ne change ; après extinction et allumage du moniteur, l'échelle est de nouveau 1 le fichier de configuration n'a pas été (correctement) écrit, ou le nom de la sortie était faux regarder cat ~/.config/kanshi/config et wlr-randr : le nom (HDMI-A-1) doit correspondre exactement
pkill kanshi; kanshi dans le terminal agit immédiatement, le bouton non le bouton ne redémarre pas Kanshi proprement ou plusieurs processus Kanshi tournent pgrep -a kanshi montre combien tournent
La boîte de dialogue affiche toujours « 1 » alors que l'échelle 3 est active QInputDialog.getItem(..., 0, False) : le 0 est l'index de la valeur prédéfinie, donc toujours la première entrée calculer l'index à partir du réglage actuel
NameError: name 'config' is not defined la variable config a été créée dans une autre fonction et n'existe pas ici créer la variable dans la bonne portée ou la transmettre
Seulement avec l'échelle 2, tout le programme disparaît Wayland reconstruit les fenêtres lors de ce changement ; l'application Qt perd brièvement la connexion lancer dans le terminal et lire le message à la fermeture ; test : remplacer pkill/kanshi à titre d'essai par print("Scale:", scale). Si la fenêtre ne disparaît alors plus, c'est Kanshi ou le rechargement qui est en cause, pas PyQt
Au démarrage, on voit GLib-GObject-CRITICAL ... g_object_unref un avertissement des parties GTK/GLib sous Wayland le plus souvent inoffensif tant que le programme tourne ; d'abord déterminer quand il apparaît (démarrage, ouverture de fenêtre, fermeture)

Les variantes Kanshi, Kanshi Test, Kanshi 2, Kanshi 3 : j'ai développé plusieurs fois l'outil sous forme de copies au lieu de modifier le fichier en service. C'est pratique, mais cela a un inconvénient : en rangeant, une entrée est restée dans le JSON (Pi_Tools/Kanshi2.py) alors qu'elle n'existait plus. La tuile ne lançait alors tout simplement rien. Qui crée des copies supprime plus tard aussi les entrées.

33.7 L’apparence : couleurs et arrondis dans la feuille de style

L'interface a reçu un aspect via des feuilles de style Qt (semblables à CSS) :

btn.setStyleSheet("""
    QPushButton {
        background-color: #1a73e8;
        border-radius: 12px;
        font-size: 14pt;
    }
""")

Questions soulevées à cette occasion et résolues :

  • px ou pt ? px sont des points d'écran, pt des points typographiques qui changent avec l'échelle. Tailles de police en pt, espacements et arrondis en px.
  • Doubles accolades {{ }} dans une f-string : une { dans le texte doit s'écrire {{, car sinon {...} est traité comme une variable. Entre les deux accolades il n'y a pas d'espace.
  • Deux lignes avec background-color dans le code : la seconde écrase la première. Lors d'une modification, toujours chercher l'endroit où la valeur est réellement définie.

Après la suppression, des cases vides sont restées dans la fenêtre. J'avais retiré les boutons du code, mais le cadre (les widgets conteneurs) était toujours là. Un widget qui n'est plus nécessaire doit aussi perdre son conteneur : deleteLater() ou reconstruire la disposition.
