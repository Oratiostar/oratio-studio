45.1 Wozu er dient

Der Datei-Hash- und Duplikat-Prüfer berechnet für viele Dateien einen Fingerabdruck (SHA-256) und sortiert danach: Dateien mit gleichem Fingerabdruck sind inhaltlich identisch, auch wenn sie unterschiedlich heißen. So findet man doppelte Dateien und weiß, wie viel Platz sich sparen lässt. Er war eines der ersten Skripte in Projekt A (Kapitel 32) und ist als Programm in mehreren Formen vorhanden:

Das ist ein gutes Beispiel dafür, wie dieselbe Idee in drei Sprachen aussieht – ideal zum Vergleichen.

45.2 Die Idee in vier Schritten

  1. Alle Dateien einsammeln (Pfade einfügen oder per Auswahlfenster wählen).
  2. Für jede Datei den SHA-256-Wert berechnen.
  3. Dateien mit gleichem Wert in einer Gruppe sammeln.
  4. Gruppen mit mehr als einer Datei sind Duplikate; die Summe der „überzähligen“ Größen ist der Platz, den man zurückgewinnen kann.

Warum SHA-256 und nicht nur die Größe? Zwei Dateien können gleich groß, aber verschieden sein. Ein kryptografischer Hash ändert sich schon bei einem geänderten Bit komplett. Zwei verschiedene Dateien mit gleichem SHA-256 sind praktisch ausgeschlossen.

45.3 Der Kern im Bash-Skript

Im Skript steht die Hauptschleife über alle Dateien. Der Kern, leicht gekürzt:

declare -A hash_known hash_paths hash_counts hash_sizes   # assoziative Felder (Wörterbücher)
hash_order=()                                              # Reihenfolge, in der Hashes zuerst vorkamen

for file in "${files[@]}"; do
    file_size="$(stat -c '%s' -- "$file" 2>/dev/null || printf '0')"
    hash="$(sha256sum -- "$file" 2>/dev/null | awk '{print $1}')"

    if [[ -z "${hash_known[$hash]+vorhanden}" ]]; then     # Hash zum ersten Mal gesehen
        hash_known["$hash"]=1
        hash_order+=("$hash")
        hash_paths["$hash"]="$file"
        hash_counts["$hash"]=1
        hash_sizes["$hash"]="$file_size"
    else                                                   # schon bekannt: Duplikat
        hash_paths["$hash"]+=$'\n'"$file"
        hash_counts["$hash"]=$((hash_counts["$hash"] + 1))
    fi
done
Zeile Erklärung
declare -A legt ein assoziatives Feld an (Schlüssel → Wert), hier Hash → Pfade
stat -c '%s' Dateigröße in Bytes
sha256sum -- "$file" berechnet den Hash; -- schützt vor Dateinamen, die mit - beginnen
awk '{print $1}' nimmt nur die erste Spalte (den Hash, ohne den Dateinamen)
${hash_known[$hash]+vorhanden} liefert „vorhanden“, wenn der Schlüssel existiert, sonst leer; so lässt sich Existenz prüfen
$'\n' ein Zeilenumbruch als Trenner, damit mehrere Pfade in einem Feldwert stehen

Danach folgt die Auswertung:

for hash in "${hash_order[@]}"; do
    count="${hash_counts[$hash]}"
    size="${hash_sizes[$hash]}"
    if (( count > 1 )); then
        duplicate_group_count=$((duplicate_group_count + 1))
        reclaimable_bytes=$((reclaimable_bytes + (count - 1) * size))
    fi
done

(count - 1) * size ist der Platz, der frei würde, wenn von jeder Gruppe nur eine Datei bliebe.

45.4 Was das Skript zusätzlich kann

  • Eingabe: Pfade einzeln, als Block einfügen (nach 0,35 s ohne weitere Zeichen gilt der Einfügeblock als beendet) oder per grafischem Auswahlfenster.
  • Fortschritt: ein Dashboard mit Datei X von Y, verarbeiteten Bytes und Restzeit.
  • Ausgabe: Abschnitte „Identische Dateien“ (rot), „Dateien ohne Duplikat“ (grün), „Zusammenfassung“ (Gruppen, überzählige Dateien, Platzgewinn); auf Wunsch als Textbericht und CSV.
  • Fehlertoleranz: set -u (undefinierte Variable = Fehler), aber kein set -e: Eine nicht lesbare Datei bricht den Lauf nicht ab, sondern landet in einer Fehlerliste.
  • Voraussetzungen: bash, sha256sum, find, stat, sort, date – das Skript prüft sie beim Start.

45.6 Selbst ausprobieren

bash hashchecker.sh

oder nur den Kern im Terminal:

find ~/Bilder -type f -exec sha256sum {} + | sort | uniq -w64 -d --all-repeated=separate

Die Zeile berechnet von allen Dateien in ~/Bilder den Hash, sortiert und zeigt nur Zeilen, deren erste 64 Zeichen (der Hash) mehrfach vorkommen. Das ist die Kurzfassung des ganzen Programms.
