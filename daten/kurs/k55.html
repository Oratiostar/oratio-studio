55.1 Compilerfehler

Der Compiler nennt Datei:Zeile:Spalte und die Art des Fehlers. Meist ist der erste Fehler der echte, die folgenden sind Folgefehler.

'xyz' was not declared in this scope

Der Name ist an dieser Stelle unbekannt.

Ursache Lösung
Funktion wird vor ihrer Definition aufgerufen ('pageOratio' was not declared, playMelody was not declared) Funktion weiter oben definieren oder einen Prototyp ergänzen: void pageOratio();
Konstante oder Farbe gibt es in der Bibliothek nicht (GC9A01A_LIGHTGREY, NOTE_FS5) Eigene Konstante mit #define oder const anlegen, zum Beispiel #define NOTE_FS5 740, oder eine vorhandene Farbe verwenden
'sin' was not declared, 'cos' was not declared #include <cmath> ergänzen
Tippfehler oder falsche Schreibweise Namen vergleichen

error: expected unqualified-id before 'if'

Eine Anweisung (if, for, x = 1;) steht außerhalb einer Funktion. Alles Ausführbare gehört in setup(), loop() oder eine andere Funktion. Prüfen, ob die geschweiften Klammern { } vorher richtig geschlossen sind.

expected ';' before ...

Ein Semikolon fehlt, meist in der Zeile davor.

fatal error: xyz.h: No such file or directory (zum Beispiel Adafruit_I2CDevice.h, led-matrix.h)

Bedeutung: Die Header-Datei wird nicht gefunden.

Lösung:

  • Arduino/PlatformIO: Bibliothek fehlt. In platformio.ini unter lib_deps eintragen (adafruit/Adafruit BusIO) oder in der Arduino IDE installieren. Adafruit_I2CDevice.h gehört zu Adafruit BusIO.
  • Matrix-Beispiele auf dem Pi: Relativen Pfad prüfen (#include "../include/led-matrix.h") oder aus dem richtigen Ordner kompilieren.

*** [.pio/build/esp32dev/src/main.cpp.o] Error 1

Das ist nur das Ende: Der Compiler ist an main.cpp gescheitert. Die eigentliche Meldung steht darüber.

.red ... has no member named 'red'

In neueren Versionen der Matrix-Bibliothek heißen die Farbanteile .r, .g, .b. .red durch .r ersetzen. Bei Flackern: --led-slowdown-gpio=4.

55.3 PlatformIO

Could not initialize Project mit UnknownPackageError: Could not find the package with 'platformio/toolchain-gccarmnoneeabi @ ~1.90201.0' requirements

Bedeutung: PlatformIO sucht ein bestimmtes Toolchain-Paket in einer festen Version und findet für das verwendete System (zum Beispiel ARM64-Linux auf dem Pi) keine passende Ausgabe. Es ist nicht der Pico, VS Code oder das Internet kaputt.

Was eine Toolchain ist: Die Sammlung aus Compiler, Assembler und Linker, mit der aus dem C++-Code ein Programm für den Chip wird.

Lösung: Die Plattform und ihre Version prüfen und eine Plattform wählen, die für ARM64 gebaut ist (für den Pico die Arduino-Pico-Plattform von Earle Philhower), oder das Projekt auf einem x86-Rechner bauen. Die Hinweise zur Plattform stehen in platformio.ini.

No module named platformio

Im normalen Terminal ist PlatformIO nicht installiert, es liegt in VS Code in einer eigenen Umgebung. Aufruf:

~/.platformio/penv/bin/platformio --version

Fehlt die Datei oder ist die Umgebung beschädigt, löscht man nur diese Umgebung (rm -rf ~/.platformio/penv), schließt VS Code und startet es neu. PlatformIO baut sie neu auf. Die Projekte bleiben erhalten.

Falsche Boardangabe

Ein Nano-Klon braucht oft board = nanoatmega328 mit board_build.mcu/Bootloader atmega328old, sonst bricht der Upload ab (avrdude: stk500_getsync(): not in sync).
