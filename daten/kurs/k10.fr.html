La mise à l’échelle de l’écran est l’un des sujets les plus longs avec le Pi. Voici le savoir dans l’ordre, avec les essais ratés typiques, car c’est de là qu’on apprend le plus.

10.1 Le problème

Un écran 4K (3840 × 2160 pixels) affiche tout très petit sur le Pi : texte, menus, icônes. Je voulais conserver toute la résolution (image nette) tout en voyant tout plus grand.

10.2 Deux systèmes graphiques : Wayland et X11

echo $XDG_SESSION_TYPE

Sortie wayland ou x11. Mon Raspberry Pi OS (Debian 13, « Trixie ») utilise Wayland avec le gestionnaire de fenêtres labwc.

Wayland (nouveau, chez moi) X11 (plus ancien)
Régler l’écran wlr-randr xrandr
Fichier de démarrage automatique ~/.config/labwc/autostart autres

J’ai essayé X11. Le problème n’a pas été résolu, je suis donc revenu à Wayland.

10.3 La commande la plus importante : wlr-randr

wlr-randr

Elle affiche la sortie (par exemple HDMI-A-1 ou HDMI-A-2), la résolution actuelle, les résolutions possibles, Scale (l’échelle) et l’orientation. Le nom de la sortie n’est pas le même partout. Toujours exécuter d’abord wlr-randr et lire le nom.

wlr-randr --output HDMI-A-2 --mode 1920x1080                  # Full HD
wlr-randr --output HDMI-A-2 --mode 3840x2160                  # 4K
wlr-randr --output HDMI-A-2 --mode 3840x2160 --scale 2       # 4K, alles doppelt so groß
wlr-randr --output HDMI-A-2 --mode 3840x2160 --scale 3       # 4K, dreifach
wlr-randr --output HDMI-A-2 --scale 1                         # zurück
wlr-randr --output HDMI-A-2 --transform 180                   # Bild um 180 Grad drehen
wlr-randr --output HDMI-A-2 --transform normal                # zurück

Signification : Scale 1 = normal, Scale 2 = tout deux fois plus grand, Scale 3 = trois fois. La résolution reste 4K, seule l’interface devient plus grande. Avec mon moniteur 4K portable, Scale 3 était plus agréable que Scale 2.

Pour X11, l’équivalent est :

xrandr
xrandr --output HDMI-1 --mode 1920x1080 --rate 60

10.4 Problème 1 : après le redémarrage, tout est de nouveau petit

Une commande wlr-randr dans le terminal ne vaut que pour la session en cours. Au redémarrage, Wayland choisit de nouveau la résolution préférée du moniteur. Solution : une entrée de démarrage automatique.

nano ~/.config/autostart/display.desktop
[Desktop Entry]
Type=Application
Name=Display Setup
Exec=sh -c "sleep 3 && wlr-randr --output HDMI-A-2 --mode 3840x2160 --scale 3"

Le sleep 3 attend que le bureau ait fini de démarrer. Puis sudo reboot.

10.5 Pourquoi `cmdline.txt` n’a pas aidé

J’ai aussi essayé cette méthode :

sudo nano /boot/firmware/cmdline.txt

avec le paramètre video=HDMI-A-1:1920x1080@60D. Tout doit tenir sur une seule ligne. J’ai vérifié avec cat /proc/cmdline que le paramètre était bien présent. Wayland a pourtant redémarré en 4K, car le noyau a repris le paramètre, mais le bureau a ensuite réglé l’affichage à nouveau. Leçon : un réglage peut figurer dans une couche du système et être écrasé dans la suivante. C’est pourquoi la solution avec wlr-randr dans le démarrage automatique était plus fiable.

10.6 Problème 2 : moniteur éteint puis rallumé

Si seul le moniteur est éteint puis rallumé, Wayland le détecte de nouveau et remet l’échelle à 1. Le fichier de démarrage automatique ne s’exécute qu’à la connexion, pas une seconde fois. C’est ce qu’on appelle un problème de hotplug HDMI. Il y a deux solutions.

Solution A : Kanshi

Kanshi réagit quand un moniteur est branché ou débranché et applique un profil enregistré.

sudo apt install kanshi
mkdir -p ~/.config/kanshi
nano ~/.config/kanshi/config

Contenu (c’est ainsi que cela a fonctionné chez moi, dans l’ancienne notation sans accolades autour des options) :

profile {
    output HDMI-A-1 mode 3840x2160 scale 3
}

Ensuite, inscrire la ligne kanshi & dans ~/.config/labwc/autostart et se reconnecter.

Voici comment j’ai trouvé l’erreur (le dépannage est la vraie leçon) :

  1. ps aux | grep kanshi n’affichait que la ligne grep → Kanshi ne tourne pas.
  2. Au lancement manuel, on a obtenu : unexpected '{' in output – failed to parse config file. La version installée ne comprenait pas la notation output HDMI-A-1 { ... }.
  3. Configuration changée vers l’ancienne notation → Kanshi a démarré → wlr-randr affichait Scale: 3.000000 au lieu de 1.000000.
  4. L’option de débogage kanshi -v n’existait pas dans cette version (invalid option -- 'v'). Ce n’est pas un dysfonctionnement, seulement une version plus ancienne.

Solution B : script de surveillance (la solution « brutale, mais très fiable »)

Un petit script vérifie toutes les quelques secondes si l’échelle est toujours correcte et la corrige immédiatement.

nano ~/display_watchdog.sh
#!/bin/bash

while true
do
    SCALE=$(wlr-randr | grep "Scale:" | head -n1 | awk '{print $2}')

    if [ "$SCALE" != "3.000000" ]; then
        echo "Scale falsch → korrigiere"
        wlr-randr --output HDMI-A-1 --scale 3
    fi

    sleep 5
done

Ligne par ligne :

  • while true; do ... done – boucle infinie
  • SCALE=$(...) – enregistre la sortie de la commande dans la variable SCALE
  • if [ "$SCALE" != "3.000000" ] – « si l’échelle n’est pas 3 »
  • wlr-randr --output ... --scale 3 – corrige
  • sleep 5 – attendre 5 secondes (avec sleep 2, il réagit plus vite)

Ensuite le rendre exécutable (chmod +x ~/display_watchdog.sh), le tester avec ~/display_watchdog.sh, puis créer le fichier de démarrage automatique (voir section 5.4). Un tel script ne charge pratiquement pas un Pi 5.

Kanshi ou script de surveillance ?

Kanshi Surveillance
Principe attend l’événement « moniteur détecté » vérifie en permanence que tout est correct
Si le moniteur n’émet aucun événement sans effet fonctionne quand même
Effort fichier de config + programme petit script

Je soupçonnais que le moniteur Samsung n’envoyait aucun événement détectable lors de l’extinction et de l’allumage. Dans ce cas, seul le script de surveillance aide.

10.7 Perspective : mise à l’échelle automatique selon la résolution

Le concept : le script ne doit pas seulement vérifier l’échelle, mais aussi lire la résolution puis choisir la bonne valeur.

Résolution Scale
jusqu’à 1920×1080 1
2560×1440 et 3440×1440 2
3840×2160 3

Ainsi, chaque moniteur branché se règle automatiquement correctement.
