39.1 La boîte à outils Oratio

La Toolbox est un onglet à part avec des boutons pour les commandes de terminal. C'est la raison pour laquelle je n'ai pas à connaître beaucoup de commandes par cœur : chaque commande a un nom, une explication et un bouton « Exécuter ».

Trois zones (boutons tout en haut à gauche) : Pi Tools (spécifique au Raspberry Pi), Général (Linux en général), Livre (livre de commandes à consulter). En haut à gauche, un champ de recherche qui fouille tout.

Fichiers : Oratio_Toolbox/toolbox_menu.py (l'onglet), core.py (exécuter, étiquettes), pi_commands.py, general_commands.py, befehlsbuch.py.

Une commande dans la liste

Chaque commande est un appel de la fonction auxiliaire befehl(...) (l'exemple est composé pour l'illustration ; les noms exacts des catégories figurent dans le fichier concerné) :

befehl("bastel", "I2C-Geräte suchen", "Zeigt alle Adressen am I2C-Bus",
       "i2cdetect -y 1", art="anzeigen", need="i2cdetect")
Élément Signification
Catégorie dans quel groupe se trouve le bouton
Nom texte du bouton
Info explication sous le nom
Commande le texte exécuté dans le terminal
art Étiquette : anzeigen, aendern, installieren, gefaehrlich
need Programme qui doit être présent ; s'il manque, l'onglet propose l'installation
confirm demander confirmation avant
terminal faire tourner dans une fenêtre de terminal
felder Champs de saisie avec suggestions (par ex. /dev/ttyUSB0, 0x3c, 17)
star épingler en haut
ask, default, explain, timeout, preview Texte de confirmation, valeur par défaut, texte explicatif, limite de temps, aperçu

Les quatre étiquettes

Étiquette Couleur Signification
Afficher vert n'affiche que quelque chose, sans danger à tout moment
Modifie orange règle quelque chose ou modifie des fichiers
Installe bleu apporte des logiciels sur le Pi
Dangereux rouge peut effacer des données ou paralyser le système ; demande confirmation avant

L'étiquette est devinée à partir du texte de la commande (plutôt prudent que trop anodin). Si elle ne convient pas, on ajoute art="…" à la ligne. Pour le livre de commandes, l'étiquette vaut pour la commande elle-même, pas pour le bouton.

Habitude que j'en retiens : toujours essayer d'abord les commandes d'affichage vertes.

Comment la Toolbox a grandi en six étapes

Étape Contenu Nouvelles commandes
1 Étiquettes sur chaque commande ; catégorie « Bricolage & microcontrôleurs » (I2C/SPI, GPIO, ports série et ESP32, MicroPython, Pico, Arduino, PlatformIO, AVR, OpenOCD, CAN, GPS …) 57
2 WLAN & Bluetooth, réseau (DNS, routes, trafic, trouver des appareils), son (PipeWire, mixeur, enregistrement) 97
3 Lancer des programmes (35 lanceurs de programmes), écran, stockage & lecteurs, mises à jour & paquets, processus & services, sécurité & utilisateurs, système & infos, santé, caméra 280
4 Git & GitHub, build & compilateurs 86
5 Aides du terminal, fichiers & dossiers, texte, images/vidéo/PDF, partage & transfert, petits miracles (par ex. cowsay, figlet) 145

Le livre de commandes : un ouvrage de référence, le bouton s'appelle « Expliquer » et n'exécute rien. Il montre ce que fait la commande, si elle est installée sur ce Pi (vérifié en direct), le mot-clé du manuel, si la Toolbox a déjà un bouton pour elle (coche) et un avertissement pour les commandes dangereuses. « Copier » met la commande dans le presse-papiers. 22 groupes avec au total 1020 commandes (fichiers/dossiers, texte, shell, système, Raspberry Pi, GPIO/I2C, réseau, Bluetooth, audio, écran, X11, paquets, programmation, Git, Docker …). Entrées personnelles : dans befehlsbuch.py, dans GRUPPEN, une ligne ("befehl", "Was er macht"). Si le fichier manque ou contient une erreur, la zone « Livre » n'existe simplement pas (chapitre 36.3 : une pièce cassée n'arrête jamais l'ensemble).

Erreur apparue dans la Toolbox : les lanceurs de programmes ne s'ouvrent pas

  • Symptôme : Sauvegarde → « SD Card Copier » restait bloqué sur « ouverture … », rien ne se passait.
  • Premier essai : le bouton lançait via gtk-launch piclone et cachait tout message d'erreur.
  • Solution : le menu lance directement piclone ; le bouton le fait maintenant aussi. Le programme démarre détaché (setsid) ; après 2 s, le bouton vérifie s'il tourne encore (« … est ouvert ✓ »). S'il se termine immédiatement, le vrai message d'erreur apparaît dans le champ de résultat.
  • Pourquoi : qui supprime les messages d'erreur ne saura jamais ce qui a mal tourné. Cela vaut pour les 35 lanceurs de programmes.

Ajouter soi-même une commande

  1. Ouvrir le fichier approprié (pi_commands.py ou general_commands.py).
  2. Dans la bonne catégorie, ajouter une ligne befehl(...) (exemple ci-dessus).
  3. Vérifier la syntaxe de la commande elle-même : bash -n skript.sh (contrôle de syntaxe sans exécution) ou essayer la commande dans le terminal.
  4. Redémarrer le Control Center.

39.2 Appli de sauvegarde et clone amorçable

Fichier : Oratio_Menu/Apps/Oratio_Backup/oratio_backup.py. L'application copie le système entier sur un second disque, de sorte qu'il démarre dans un autre Pi.

Utilisation :

  1. Ouvrir l'application de sauvegarde → bouton « Copier tout le système sur un disque … ».
  2. Carte « 1. Source – copier depuis quel disque ? » (présélectionné : le système en cours).
  3. Carte « 2. Cible – sur quel disque ? ». Le disque système (NVMe) n'est jamais proposé. Après avoir branché, « Rechercher à nouveau ».
  4. Essai à blanc (case « Afficher seulement », cochée par défaut) : montre toutes les étapes et commandes et ne modifie rien.
  5. Exécution réelle : décocher, saisir le nom du disque (par ex. sda), le bouton devient rouge (« Effacer le disque et copier »).
  6. Case « Actualiser seulement (rapide) » : la cible n'est pas repartitionnée ; rsync ne transfère que le nouveau et le modifié. Condition : le disque a été créé une fois auparavant par le programme.

Les 8 étapes : vérifier → vider le disque cible → nouveau partitionnement (petite partition de démarrage FAT + reste comme système, nouvel identifiant) → créer les systèmes de fichiers → monter → copier le système avec rsync (sans /proc, /sys, /dev, /run, /tmp, /mnt, /media, fichier d'échange, .cache) → copier la zone de démarrage et réécrire cmdline.txt ainsi que fstab avec les nouveaux identifiants (PARTUUID) → vérification (e2fsck, fsck).

Pourquoi les identifiants sont réécrits : chaque partition a son propre PARTUUID. Si l'on copiait simplement le contenu, cmdline.txt renverrait encore à la partition de l'ancien système ; le clone ne trouverait pas son système de fichiers racine.

Pourquoi rsync et non dd : dd copie bloc par bloc et exige une cible de même taille ; rsync copie des fichiers et permet une autre répartition. rpi-clone n'a volontairement pas été choisi, parce que, selon des témoignages, il ne fonctionne pas sous Bookworm.

Conditions : rsync, sfdisk (de fdisk), mkfs.vfat (de dosfstools), e2fsprogs. S'il manque quelque chose, le script indique aussitôt la commande apt. Droits : sudo sans mot de passe, sinon pkexec.

Démarrer sur l'autre Pi : brancher le disque en USB, retirer la carte SD, allumer. Le Pi 5 démarre depuis USB si aucune SD amorçable n'est insérée ou si l'ordre de démarrage le permet (sudo raspi-config → Advanced Options → Boot Order). Un Pi 4 a besoin d'un firmware récent.

La chaîne d'erreurs lors du clonage (chronologique)

Étape Observation Cause et conséquence
1 rsync s'arrête avec le code 11, « No space left on device » Le disque contenait déjà d'anciennes zones (bootfs/rootfs). Si le système n'a pas pris en compte le nouveau partitionnement, on a formaté et copié dans l'ancienne zone système, plus petite – qui était aussitôt pleine
2 Mesure : après le partitionnement, relire le partitionnement et le vérifier ; rsync -S (les fichiers creux restent creux) ; assez d'inodes au formatage ; en cas d'erreur, journal avec df -h et df -i –
3 Le journal a montré : sda1 = 512 Mo, mais sda2 = seulement 3 Mo. La nouvelle vérification l'a reconnu et s'est arrêtée avant la copie La taille de la zone système était « reste du disque », que sfdisk déterminait lui-même
4 Solution : la taille est calculée et indiquée explicitement en secteurs ; avant, retirer les anciennes zones de la mémoire du système (partx -d) et vider les 4 premiers Mo du disque ; après le partitionnement, écrire la table dans le journal, la communiquer à nouveau au système (partx -d, blockdev --rereadpt, partprobe, partx -a) et vérifier. Le journal montre « Table sur le disque » contre « Comment le système voit le disque » On n'a pas pu établir avec certitude si les 3 Mo venaient de sfdisk ou du noyau (ancien partitionnement en mémoire) ; la nouvelle version corrige les deux

La leçon derrière : toujours vérifier que le système voit le partitionnement tel qu'il a été écrit sur le disque. Avec lsblk /dev/sda et sudo fdisk -l /dev/sda, on peut le vérifier à tout moment. Avant de démarrer, ne laisser aucune fenêtre ni gestionnaire de fichiers ouvert sur le disque cible.

Règle d'expérience : toujours d'abord l'essai à blanc, puis la première vraie copie sur un disque où il n'y a rien d'important. Cette fonction n'a pas été testée de façon définitive sur de vrais disques ; c'est un outil avec filet de sécurité, pas un remplacement pour une seconde sauvegarde indépendante.

39.3 Commande vocale (tout hors ligne)

Fichier : Oratio_Menu/sprachsteuerung.py et install_sprache.sh.

Briques :

Tâche Programme
Reconnaître la parole Vosk (petit modèle allemand, env. 45 Mo)
Lire la réponse à voix haute Piper (voix allemande « thorsten »), sinon espeak-ng, sinon seulement du texte
répondre à des questions libres Gemma (gemma3:4b) via Ollama
Microphone/lecture alsa-utils (arecord, aplay)

Installer (une seule fois, avec Internet) : soit bash Oratio_Menu/install_sprache.sh dans le dossier du projet, soit, dans la fenêtre « Commande vocale », en bas le bouton « Installer (un terminal s'ouvre) ». Le script installe alsa-utils, curl, unzip, espeak-ng (apt), Vosk (pip), le modèle Vosk et Piper avec voix dans Oratio_Menu/Modelle/. Chaque étape signale les erreurs par « !! ». La fenêtre montre sous « Prêt ? » avec des coches (✓/✗) ce qui manque encore, et « Tout est prêt ✓ ». Supprimer : effacer le dossier Modelle et pip3 uninstall vosk. Gemma manque ? ollama pull gemma3:4b et sudo systemctl start ollama.

Utilisation : symbole microphone en haut à droite → « Commande vocale … ». Toucher « Écouter », dire la commande, le texte apparaît pendant ce temps. S'il n'entend rien pendant 8 secondes, il s'arrête ; une phrase peut durer jusqu'à 15 s. Pour essayer sans microphone : saisir la commande dans le champ + Entrée.

Commandes (les mots de remplissage comme « bitte », « Oratio », « mal » sont ignorés ; nombres en mots ou en chiffres) : « Wie spät ist es », « Welcher Tag ist heute », « Lauter », « Leiser », « Lautstärke auf fünfzig Prozent », « Stumm », « Ton an », « Dunkelmodus an/aus », « Nicht stören an/aus », « Fokus aus », « Fokus », « Öffne » (chaque tuile et chaque fenêtre de réglages, les noms d'orthographe proche sont trouvés), « Zeige offene Apps », « Mach einen Screenshot », « Sperre den Bildschirm », « Was kannst du ». Volontairement pas par la voix : éteindre/redémarrer, point d'accès, WLAN activé/désactivé – pour que rien d'important n'arrive par erreur.

Questions libres à Gemma : ce qui n'est pas une commande connue part comme question à Gemma (gemma3:4b via Ollama, tout hors ligne). « Gemma réfléchit … » s'affiche pendant ce temps dans la fenêtre (sur le Pi 5 le plus souvent 5–20 s ; la première question après une longue pause plus longtemps, car le modèle est chargé). Les réponses sont volontairement courtes (2–3 phrases, sans énumérations), parce qu'elles sont lues à voix haute. Les 3 dernières questions sont transmises comme mémoire. Gemma répond dans la langue de la question. Un interrupteur désactive cela.

Mot de réveil : section « Mot de réveil » → interrupteur « Écouter mon nom » et champ « Nom ». Le microphone écoute en permanence, mais la reconnaissance ne guette que le nom (tout le reste est rejeté, rien n'est enregistré). Le nom est suivi d'un court bip, puis on dit la commande. Quand le Pi parle ou que Gemma réfléchit, l'écoute fait une pause, pour qu'il ne s'entende pas lui-même. L'interrupteur est mémorisé dans Json/oratio_stimme.json.

Le problème avec le nom : Vosk ne connaît que de vrais mots allemands. « Oratio » n'en est probablement pas un ; le programme prend alors comme substituts des mots à la sonorité proche (par ex. « Horatio »). Le champ en dessous montre à quoi il réagit. Mieux vaut des mots longs, clairs, réels (« Computer », « Hallo Pi »).

Limites : Vosk est allemand : les questions posées en français ou en anglais sont mal reconnues (la saisie fonctionne dans toutes les langues). Les réponses françaises sont lues par Piper avec la voix allemande. Avec du bruit de fond ou en marmonnant, des erreurs sont possibles. L'écoute permanente coûte un peu de temps de calcul.

39.4 Langues

Chaque langue est un fichier dans Sprache/ :

NAME = "Français"
NEUSTART_FRAGE = "Redémarrer maintenant ?"  # Text der Neustart-Frage
TEXTE = {
    "Home": "Accueil",
    "Einstellungen": "Paramètres",
    # ...
}

Le texte allemand est la clé ; si une traduction manque, le texte allemand s'affiche simplement. Une nouvelle langue naît en copiant un fichier existant, en changeant NAME et en traduisant TEXTE. Les marqueurs de place comme {n} doivent rester inchangés (voir l'erreur en 38.1).

L'Atlas (39.6) suit lui-même le réglage de langue du Control Center (de/fr/en/es), sans toucher aux fichiers de Sprache/.

39.6 Applis d’électronique : composants, académie, atlas

Trois applications répondent à la question « à quoi ressemble le composant et qu'ai-je le droit de brancher ? ». Elles sont construites de sorte que le contenu se trouve dans des fichiers JSON et que le code du programme ne fait qu'afficher.

Application Rôle Étendue
Bauteile ouvrage de référence avec brochage en dessin de circuit intégré, symboles, table de vérité, chronogramme, calculatrices 331 entrées en 10 catégories
Akademie jeu d'apprentissage : carte d'îles avec île du courant, usine logique, île du code, montagne binaire, port du réseau, arène de quiz (154 questions), course turbo, atelier de Voltis 24 trophées
Atlas recueil de tables électronique, pas un jeu : carte du monde colorée avec des mondes (bases, composants passifs, semi-conducteurs, métrologie, mémoire & débits, laboratoire & capteurs …) env. 470 pages, 86+ calculatrices

Naissance : d'abord « Bauteile » (106, puis 331 entrées). Ensuite l'« Akademie » comme jeu. Parce qu'on voulait un ouvrage de référence et non un jeu, l'« Atlas » est né – et il a repris plus tard toutes les pages de Bauteile, de sorte que « Bauteile » peut être supprimé. Le Labor (38.5) reste nécessaire pour les outils en direct, parce que l'Atlas n'accède pas au matériel.

Compléter soi-même (sans modifier les fichiers fournis) :

  • Bauteile : pour chaque catégorie x.json, l'application charge aussi tous les x_*.json. Un fichier personnel logik_meine.json suffit. Les broches s'écrivent "Name:Art" (i entrée, o sortie, v alimentation, g masse, x commande).
  • Akademie : les questions figurent dans Daten/fragen_<thema>.json ; une entrée est ["Frage", "richtige Antwort", ["falsch 1", "falsch 2", "falsch 3"], "Erklärung"]. Un fichier fragen_meine.json est chargé comme thème supplémentaire.
  • Atlas : fichier Daten/erg_meine.json : {"welt": "grund", "seiten": [ {"id": "x", "titel": "...", "kurz": "...", "tags": [], "bloecke": [ {"t": "text", "text": ["..."]} ] } ]}. Types de blocs : text, h2, hinweis (tipp/warn/merke/info/pi/fun), formel, liste, tabelle, kacheln, symbol, spezial, rechner. Un monde entièrement nouveau = fichier propre welt_xyz.json sur le modèle des existants.

Appréciation honnête : brochages, valeurs et données de capteurs proviennent de connaissances spécialisées, non recoupées avec des fiches techniques. Avant de câbler, toujours vérifier la fiche technique (l'application a pour cela le bouton « Chercher la fiche technique »). Vérifier particulièrement : 7476, 7490, 74193, ADC0804, DAC0808, 2N2222 (broches différentes du BC547), 4060, 4046, 7448, TSOP4838/VS1838 (ordre selon le fabricant). Les modules de 4–8 broches ont un ordre différent selon la carte.

39.7 Guides de fabrication maison (projet B)

A) Ajouter un nouvel onglet

  1. Créer un nouveau dossier, par ex. Notizen/ avec un fichier vide __init__.py et notizen_tab.py.
  2. Dans notizen_tab.py, écrire une classe dont le constructeur prend largeur et hauteur :
from PyQt5.QtWidgets import QWidget, QVBoxLayout, QLabel

class NotizenTab(QWidget):
    def __init__(self, width, height):
        super().__init__()
        lay = QVBoxLayout(self)
        lay.addWidget(QLabel("Hier entstehen Notizen"))
  1. Dans app_ui.py, ajouter la ligne et l'inscrire dans TABS :
NotizenTab = _tab_laden("Notizen.notizen_tab", "NotizenTab")
TABS = [..., ("Notizen", NotizenTab)]
  1. Redémarrer le Control Center. Si le dossier manque plus tard, seul l'onglet manque.

B) Un nouveau widget

  1. Nouveau fichier Oratio_Menu/Widget/mein_widget.py.
  2. Définir au moins KIND, NAME, SIZES, MIN et paint(c) (tableau au chapitre 37.4).
  3. Redémarrer le menu. Le widget apparaît de lui-même dans la galerie de widgets.

C) Une nouvelle application

  1. Dossier Oratio_Menu/Apps/Meine_App/ avec meine_app.py et icon.png.
  2. « Ajouter une application » dans le menu : nom, fichier, icône, couleur ; case « Ouvrir dans l'aspect Oratio » pour la variante fenêtre de verre.
  3. Ou écrire directement une entrée dans Json/oratio_apps.json (exemple en 36.7).

D) Une nouvelle commande Toolbox

Voir la fin de 39.1.

E) Une nouvelle langue

Voir 39.4.

F) Une nouvelle fonction avec fenêtre et recherche

Schéma du chapitre 38 : fichier dans Oratio_Menu/, ligne dans Fenster/zentrale.py, entrée dans suche.py, réglages dans Json/.

Avant chaque modification : faire une copie du dossier ou au moins du fichier concerné (cp datei datei.bak). Après la modification, vérifier d'abord la syntaxe : python3 -m py_compile datei.py. Seulement ensuite lancer.
