35.1 Plus d’applis que de place : les pages

Avec 25 tuiles, la grille était pleine. Deux voies ont été pesées :

Voie Principe Inconvénient
Catégories plusieurs groupes avec chacun une grille, commutables qui a beaucoup de catégories doit chercher dans chacune
Pages comme sur le téléphone : page 1, page 2, des points en bas il faut des règles pour les tuiles qui appartiennent à une autre page

La décision a été pour des pages avec des points en bas. Le slot (numéro de place) détermine la page : avec 4 × 6 places, les slots 0 à 23 appartiennent à la page 1, les slots 24 à 47 à la page 2.

Lors d'un essai, une application a disparu après que j'ai mis son slot à 24. Elle se trouvait maintenant sur la page 2, qui n'existait pas encore. Leçon : qui étend le modèle de données (pages) doit aussi étendre l'affichage (changement de page).

35.2 La grille doit s’adapter

La grille n'est pas un nombre fixe : 4 × 4, 4 × 5, 4 × 6 ou 5 × 3 doivent être possibles. Pour que le code s'y retrouve, il calcule tout à partir du nombre de colonnes et de lignes :

Seite = Slot // (Spalten * Zeilen)
Zeile = (Slot % (Spalten * Zeilen)) // Spalten
Spalte = Slot % Spalten

Si l'on change la taille de la grille, les applications se réorganisent automatiquement.

35.3 Agrandir une appli

Une application peut occuper plusieurs places (2 × 1 ou 2 × 2). Pour cela, chaque entrée du JSON reçoit une largeur "w" et une hauteur "h" en cases. Une grande application en repousse d'autres : les voisines glissent plus loin et, s'il n'y a pas de place, vers la page suivante.

35.4 Glisser vers un emplacement libre

Le code n'était d'abord conçu que pour « échanger application contre application ». Maintenant, chaque application devait pouvoir aller sur n'importe quelle place libre, y compris sur la page suivante. Pour cela, le programme doit savoir faire trois choses au relâchement :

  1. Calculer la case cible (page, ligne, colonne à partir de la position de la souris).
  2. Vérifier si elle est libre ou si une autre application s'y trouve.
  3. Libre : changer le slot. Occupée : échanger.

Changement de page pendant le glissement : si l'on maintient la tuile au bord, la page change après un court délai.

35.5 Une petite fenêtre avec bouton d’agrandissement

La fenêtre devait d'abord démarrer petite et s'agrandir par un bouton dans le coin. Cela se fait avec le cadre de fenêtre du système (bouton Agrandir) ou, plus tard, avec des boutons personnels.

35.6 L’indicateur à points et l’arrondi

Les points de page en bas doivent se trouver dans une barre arrondie comme sur l'iPhone. Une différence visible n'est apparue qu'après avoir rendu la barre aussi large que les points seulement, et non sur toute la largeur.

35.7 La fin du projet A

Le projet A s'est arrêté à une limite que j'ai consignée dans un tableau comparatif (chapitre 40) : le fichier avec les tuiles, le glissement, les effets et les pages était devenu très grand. Chaque nouvelle idée (arrière-plan, widgets, réglages) y aurait apporté encore plus. En même temps, des idées sans rapport avec les tuiles sont arrivées :

  • une vidéo au démarrage du Pi (une intro avec le logo Oratio),
  • une image de système d'exploitation personnelle (Oratio OS),
  • la question de savoir si le programme tournerait mieux en C++.

Telles étaient les raisons de repenser la structure. Le résultat est le projet B « Verre ».
