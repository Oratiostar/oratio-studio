42.1 Worum es geht

Das Programm ist hier in C++ mit Qt5 geschrieben statt in Python mit PyQt5. Aussehen, Bedienung und alle Einstellungsdateien (Json/, LED/led_config.json …) sind gleich geblieben. Dafür gibt es keinen Interpreter mehr: Das Programm wird gebaut und startet als fertige Datei.

Umfang: rund 23 000 Zeilen C++.

42.2 Bauen und starten

Aufgabe Befehl
Erstes Mal auf dem Pi (installiert Qt5 und Compiler, baut, richtet Dienste ein) bash install.sh
Nach Änderungen am Code bash build.sh
Alles von vorn bauen bash build.sh neu
Starten ./run_app.sh oder das Desktop-Symbol
Eine App allein starten ./oratio_control_center --run-app Oratio_Menu/Apps/Kanshi/kanshi.so
Dienste neu einrichten ./oratio_control_center --install-services

Von Hand: cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j4 && cmake --install build. Die fertigen Programme werden in den Projektordner installiert (CMAKE_INSTALL_PREFIX ist der Projektordner).

42.3 Aufbau des Bauplans

CMakeLists.txt legt Standard (C++17), AUTOMOC (Qt erzeugt den Hilfscode für Signale) und die Qt-Komponenten fest. Daraus entstehen:

  1. oratio_core (statische Bibliothek): gemeinsamer Teil ohne Fenster (Pfade, Dienste, LED-Muster, Lüftertreiber, OLED-Zeichnung, PS5).
  2. Dienste: led_service, fan_service, oled_service (eigene Programme, die im Hintergrund laufen).
  3. oratio_ui (Objektbibliothek): alles, was zum Fenster gehört (app.cmake listet die Quellen in OCC_UI_SOURCES).
  4. oratio_control_center: das Hauptprogramm.
  5. Apps als Plugins (.so): hash_checker.so, kanshi.so.

app.cmake prüft für jede Datei der Liste, ob sie existiert (if(EXISTS …)). Ein fehlender Tab-Ordner führt also nicht zum Abbruch, nur zu einem Programm ohne diesen Tab – dieselbe Fehlertoleranz wie in Python (Kapitel 36.3).

Widgets: file(GLOB … Oratio_Menu/Widget/*.cpp CONFIGURE_DEPENDS) – jede .cpp in diesem Ordner ist ein Widget. Am Ende der Datei steht REGISTER_WIDGET mit kind, name, sizes, min, fast, order, dazu die Funktion paint(c). Ein neues Widget entsteht durch Kopieren einer kleinen Datei (network.cpp), Ändern und bash build.sh.

42.4 Apps als Plugins

Ein Plugin ist eine Bibliothek, die das Menü zur Laufzeit öffnet (dlopen). Die Vorlage steht in Oratio_Menu/Apps/oratio_app.h. Eine App besteht aus einem normalen Qt-Fenster und einer einzigen Zeile am Ende:

#include "oratio_app.h"

class MeinFenster : public QWidget {
    // ... ganz normales Qt-Fenster ...
};

ORATIO_APP(MeinFenster)

Das Makro erzeugt die exportierte Funktion oratio_app_create(), die das Menü aufruft. Dann gilt:

  • Das Fenster erscheint als Glas-Karte im Tab; Titel = Fenstertitel; x schließt.
  • Eigene Farben der App fallen weg, das Menü legt Glas, Nachtmodus und Schrift darüber (Teile mit setProperty("keepStyle", true) behalten ihren Stil).
  • Meldungen über OratioApp::information/warning/critical/question erscheinen als Glas-Meldung in der Karte; außerhalb des Menüs sind es normale QMessageBox-Fenster.
  • accept()/close() der App schließt die Karte.

Neue App bauen: Ordner Oratio_Menu/Apps/<Ordner>/ mit <name>.cpp, dann in app.cmake die Zeile oratio_app_plugin(<Ordner> <name>), dann bash build.sh. Die .so landet im selben Ordner. Liegt neben einer .py-Datei eine gleichnamige .so, öffnet das Menü die .so als Glas-Karte; .py-Programme ohne .so laufen weiter mit python3 als eigenes Fenster.

42.5 Skripte im Oratio-Look

„App hinzufügen“ → „Im Oratio-Look öffnen“ an und „Im Terminal öffnen“ aus: Skripte (.sh, .py, .js, .pl, .rb, .lua, .php, .bash) laufen in einem Glasfenster. Die Ausgabe erscheint live, darunter eine Eingabezeile (für read und Ähnliches), dazu „Stopp“ und „Nochmal“. Das Fenster zu schließen beendet das Programm.

42.6 Toolbox als JSON-Listen

In der C++-Variante stehen die Toolbox-Befehle nicht mehr im Programmcode, sondern in Listen: pi_commands.json (Bereich „Pi Tools“) und general_commands.json („Allgemeine Tools“). core.cpp (Motor) und toolbox_menu.cpp (Aussehen) werden nicht angefasst. Fehlt eine Liste, startet alles trotzdem; dort steht „Datei fehlt“. Der Vorteil: Eine neue Zeile in einer Textdatei braucht keinen Neubau.

42.7 Vergleich Python gegenüber C++

Python (PyQt5) C++ (Qt5)
Änderung ausprobieren Datei speichern, neu starten bash build.sh, dann starten
Startzeit langsamer (Interpreter, Importe) schneller
Speicherbedarf höher niedriger
Fehler beim Schreiben erst beim Ausführen sichtbar viele schon beim Bauen
Zusätzliche Pakete PyQt5, Python-Bibliotheken Compiler, Qt5-Entwicklungspakete
Hilfsbibliotheken Python-Module nlohmann/json (im Projekt), PIL entfällt (Qt zeichnet Systemschriften)
Lernkurve flach steil (Zeiger, Header, CMake)
Geeignet für Ausprobieren, Lernen fertiges Gerät, das schnell und sparsam laufen soll

Ehrliche Einordnung: Die C++-Fassung wurde aus dem Python-Stand übertragen. Wer neue Funktionen entwickeln will, tut das zuerst in Python und überträgt sie später, wenn sie sich bewährt haben.
