17.1 Warum PlatformIO?

Die Arduino-IDE ist einfach. PlatformIO in VS Code ist für größere Projekte besser: mehrere Boards, eine Konfigurationsdatei (platformio.ini), Bibliotheksverwaltung, bessere Fehlermeldungen.

17.2 Installation

sudo apt update
sudo apt upgrade -y
sudo apt install code -y
code --version

Dann in VS Code:

  1. Links auf Extensions (Erweiterungen) klicken.
  2. PlatformIO IDE suchen und installieren.
  3. VS Code neu starten.
  4. Links auf den Alien-Kopf klicken, dann New Project.
  5. Projektname, Board und Framework: Arduino wählen.

Board-Namen:

  • Arduino Nano ATmega328
  • Arduino Mega or Mega 2560 ATmega2560
  • Espressif ESP32 Dev Module

17.3 Die platformio.ini

Das ist die Konfigurationsdatei des Projekts:

[env:esp32dev]
platform = espressif32
board = esp32dev
framework = arduino
monitor_speed = 115200
lib_deps =
    adafruit/Adafruit SSD1306
    adafruit/Adafruit GFX Library
    adafruit/Adafruit BusIO
  • platform – die Chip-Familie
  • board – das konkrete Board
  • framework – Arduino
  • monitor_speed – Baudrate des Seriellen Monitors
  • lib_deps – Bibliotheken, die automatisch geladen werden

Das Programm steht in src/main.cpp und beginnt mit #include <Arduino.h>.

17.4 PlatformIO-Befehle im Terminal

pio run                       # kompilieren
pio run --target upload       # hochladen
pio run -t clean              # aufräumen
pio pkg update                # Pakete aktualisieren
pio pkg install --library "adafruit/Adafruit BusIO"
pio system prune --force      # alte Reste löschen

17.5 Der I²C-Scanner – das wichtigste Diagnoseprogramm

Wenn ein I²C-Display nichts anzeigt, prüft man zuerst, ob der Mikrocontroller es überhaupt sieht:

#include <Wire.h>

void setup() {
  Serial.begin(9600);
  Wire.begin();
  Serial.println("I2C Scanner");
}

void loop() {
  byte error, address;
  int devices = 0;
  for (address = 1; address < 127; address++) {
    Wire.beginTransmission(address);
    error = Wire.endTransmission();
    if (error == 0) {
      Serial.print("Gefunden bei 0x");
      if (address < 16) Serial.print("0");
      Serial.println(address, HEX);
      devices++;
    }
  }
  if (devices == 0) Serial.println("Kein Geraet gefunden");
  delay(3000);
}

Dann den Seriellen Monitor mit der richtigen Baudrate (hier 9600) öffnen. Typische Meldung: Gefunden bei 0x3C. Das ist die Adresse des OLED. Wird nichts gefunden, liegt es an der Verkabelung, der Spannung oder dem Display. Mein ESP32 hat das Display „nur sporadisch" erkannt, deshalb habe ich es am Nano gegengetestet: Damit unterscheidet man zwischen einem Fehler am Display und einem am ESP32.

Verkabelung eines I²C-OLED am ESP32:

OLED ESP32
GND GND
VCC 3V3
SCL GPIO 22
SDA GPIO 21
RES nicht anschließen (offen)

Bei den Modulen, die ich am Nano hatte, war RES an 5 V angeschlossen („nicht offen lassen"). Das hängt vom Modul ab, also im Zweifel das Datenblatt oder die Rückseite prüfen.

17.6 Der Compilerfehler `esp32-hal-periman.h`

Der Compiler brach bei #include "esp32-hal-periman.h" ab. Diese Datei gehört zum ESP32-Core und wird von einer anderen Bibliothek eingebunden. Der Weg zur Lösung:

  1. Die ersten Zeilen der main.cpp prüfen. Es sollten nur die nötigen #includes drinstehen.
  2. pio pkg update, dann pio system prune --force und danach pio run.
  3. Prüfen, ob in main.cpp noch eine alte, nicht passende Bibliothek eingebunden ist.

Allgemeine Lehre: Fehler beim Kompilieren haben fast immer eine konkrete Zeile. Die Zeile kopieren, in main.cpp danach suchen und die Ursache eingrenzen.

17.7 LVGL – was hat es gebracht?

Was bringt LVGL (eine Grafikbibliothek für Displays)? Es macht Animationen und Bewegungen flüssiger, und man kann Menüs mit fertigen Elementen bauen. Es bringt aber nicht automatisch ein schöneres Aussehen. Die Optik muss man selbst gestalten.

17.8 SD-Karte am ESP32

Ein SD-Kartenmodul (SPI) lässt sich zusammen mit dem Display betreiben. Beide teilen sich SCK und MOSI, die SD-Karte bekommt einen eigenen Chip-Select:

SD-Modul ESP32
VCC 3,3 V
GND GND
MISO GPIO 19
MOSI GPIO 23
SCK GPIO 18
CS GPIO 13 
#include <SPI.h>
#include <SD.h>
#define SD_CS 13

void setup() {
  SPI.begin(18, 19, 23);
  if (SD.begin(SD_CS)) {
    Serial.println("SD Karte OK");
  } else {
    Serial.println("SD Fehler");
  }
}

17.9 Firmware sichern: esptool

Bevor bei einem fertigen Gerät (zum Beispiel einer DSTIKE-Uhr) die Werks-Firmware überschrieben wird, lässt sie sich sichern:

esptool.py --chip esp32s3 --port /dev/ttyUSB0 read_flash 0 0x1000000 backup.bin
esptool.py --chip esp32s3 --port /dev/ttyUSB0 write_flash 0 backup.bin

(Unter Windows heißt der Port COM3, auf dem Pi /dev/ttyUSB0 oder /dev/ttyACM0.) Damit ist jederzeit der Auslieferungszustand wiederherstellbar. Die Größe 0x1000000 entspricht 16 MB Flash, das hängt vom Gerät ab.
