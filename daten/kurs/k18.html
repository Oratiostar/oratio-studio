Warum nutzen farbige runde Displays SPI statt I²C? Weil sie sehr viele Pixel haben. I²C wäre zu langsam. Faustregel: wenige Pixel und schwarzweiß → I²C. Viele Pixel und Farbe → SPI.

18.2 Ein Datenblatt lesen (Beispiel)

Das Display IDT-0080-0160-IW50-DSN-B08 hat laut Datenblatt:

  • Controller ST7735S, Verbindung SPI
  • 0,96 Zoll, 80 × 160 Pixel, 65.000 Farben
  • Versorgung 3,0–3,6 V (also 3,3 V, nicht 5 V!)
  • Hintergrundbeleuchtung 20 mA

Pinbelegung:

Pin Funktion
SDA Daten (MOSI)
SCL SPI-Takt
RES Reset
VCC Versorgung
GND Masse
SPI4W Auswahl 3-Draht (0) oder 4-Draht (1, empfohlen)
RS Daten/Befehl (nur 4-Draht)
CS Chip Select
LEDK / LEDA Hintergrundbeleuchtung (Kathode / Anode)

So wird ein Datenblatt gelesen: Zuerst Controller, Spannung und Verbindungsart suchen, dann die Pinbelegung. Diese drei Infos entscheiden, ob und wie das Display funktioniert.

18.3 Beispiel: rundes GC9A01 am ESP32

#include <Arduino.h>
#include <Arduino_GFX_Library.h>

#define TFT_CS   5
#define TFT_DC   2
#define TFT_RST  4
#define TFT_SCK  18
#define TFT_MOSI 23

Arduino_DataBus *bus = new Arduino_ESP32SPI(TFT_DC, TFT_CS, TFT_SCK, TFT_MOSI, -1);
Arduino_GFX *gfx = new Arduino_GC9A01(bus, TFT_RST, 0, true);

void setup() {
  Serial.begin(115200);
  gfx->begin();
  gfx->fillScreen(BLACK);
  gfx->fillCircle(120, 120, 118, BLUE);
  gfx->fillCircle(120, 120, 90, BLACK);
  gfx->setTextColor(WHITE);
  gfx->setTextSize(3);
  gfx->setCursor(45, 90);
  gfx->println("Hallo");
  gfx->setTextColor(GREEN);
  gfx->setCursor(35, 125);
  gfx->println("Oratio");
}

void loop() {}

Die Pin-Konfiguration (CS, DC, RST, SCK, MOSI) ist das Herzstück. Stimmt die Pinbelegung nicht mit der Verkabelung überein, bleibt das Display schwarz.

18.4 Ein Projekt von einem Display zum nächsten wechseln

Das Programm besteht aus zwei Teilen: Hardware (Display-Controller, Pins, Bibliothek) und Inhalt (was gezeichnet wird). Beim Wechsel des Displays wird nur der Hardware-Teil getauscht. So kann dieselbe Uhr auf SSD1306, GC9A01 und ST7735 laufen.
