42.1 De quoi il s’agit

Ici, le programme est écrit en C++ avec Qt5 au lieu de Python avec PyQt5. L'apparence, l'utilisation et tous les fichiers de réglages (Json/, LED/led_config.json …) sont restés les mêmes. En contrepartie, il n'y a plus d'interpréteur : le programme est compilé et démarre comme un fichier fini.

Ampleur : environ 23 000 lignes de C++.

42.2 Compiler et lancer

Tâche Commande
Première fois sur le Pi (installe Qt5 et le compilateur, compile, met en place les services) bash install.sh
Après des modifications du code bash build.sh
Tout recompiler depuis le début bash build.sh neu
Démarrer ./run_app.sh ou l'icône du bureau
Lancer une seule application ./oratio_control_center --run-app Oratio_Menu/Apps/Kanshi/kanshi.so
Remettre en place les services ./oratio_control_center --install-services

À la main : cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j4 && cmake --install build. Les programmes terminés sont installés dans le dossier du projet (CMAKE_INSTALL_PREFIX est le dossier du projet).

42.3 Structure du plan de construction

CMakeLists.txt fixe le standard (C++17), AUTOMOC (Qt génère le code auxiliaire pour les signaux) et les composants Qt. Il en résulte :

  1. oratio_core (bibliothèque statique) : partie commune sans fenêtre (chemins, services, motifs de LED, pilote de ventilateur, dessin OLED, PS5).
  2. Services : led_service, fan_service, oled_service (programmes à part qui tournent en arrière-plan).
  3. oratio_ui (bibliothèque d'objets) : tout ce qui appartient à la fenêtre (app.cmake liste les sources dans OCC_UI_SOURCES).
  4. oratio_control_center : le programme principal.
  5. Applications comme plugins (.so) : hash_checker.so, kanshi.so.

app.cmake vérifie pour chaque fichier de la liste s'il existe (if(EXISTS …)). Un dossier d'onglet manquant n'entraîne donc pas d'abandon, seulement un programme sans cet onglet – la même tolérance aux erreurs qu'en Python (chapitre 36.3).

Widgets : file(GLOB … Oratio_Menu/Widget/*.cpp CONFIGURE_DEPENDS) – chaque .cpp de ce dossier est un widget. À la fin du fichier se trouve REGISTER_WIDGET avec kind, name, sizes, min, fast, order, plus la fonction paint(c). Un nouveau widget naît en copiant un petit fichier (network.cpp), en le modifiant et en lançant bash build.sh.

42.4 Les applis comme plugins

Un plugin est une bibliothèque que le menu ouvre à l'exécution (dlopen). Le modèle se trouve dans Oratio_Menu/Apps/oratio_app.h. Une application se compose d'une fenêtre Qt normale et d'une seule ligne à la fin :

#include "oratio_app.h"

class MeinFenster : public QWidget {
    // ... ganz normales Qt-Fenster ...
};

ORATIO_APP(MeinFenster)

La macro génère la fonction exportée oratio_app_create(), que le menu appelle. Alors :

  • La fenêtre apparaît comme une carte de verre dans l'onglet ; titre = titre de la fenêtre ; x ferme.
  • Les couleurs propres de l'application disparaissent, le menu pose par-dessus le verre, le mode nuit et la police (les éléments avec setProperty("keepStyle", true) gardent leur style).
  • Les messages via OratioApp::information/warning/critical/question apparaissent comme message de verre dans la carte ; hors du menu, ce sont des fenêtres QMessageBox normales.
  • accept()/close() de l'application ferme la carte.

Construire une nouvelle application : dossier Oratio_Menu/Apps/<Ordner>/ avec <name>.cpp, puis dans app.cmake la ligne oratio_app_plugin(<Ordner> <name>), puis bash build.sh. Le .so atterrit dans le même dossier. Si, à côté d'un fichier .py, il y a un .so du même nom, le menu ouvre le .so comme carte de verre ; les programmes .py sans .so continuent de tourner avec python3 dans leur propre fenêtre.

42.5 Scripts dans le style Oratio

« Ajouter une application » → « Ouvrir dans l'aspect Oratio » activé et « Ouvrir dans le terminal » désactivé : les scripts (.sh, .py, .js, .pl, .rb, .lua, .php, .bash) tournent dans une fenêtre de verre. La sortie s'affiche en direct, dessous une ligne de saisie (pour read et similaires), plus « Stop » et « Encore ». Fermer la fenêtre termine le programme.

42.6 Boîte à outils en listes JSON

Dans la variante C++, les commandes de la Toolbox ne figurent plus dans le code du programme, mais dans des listes : pi_commands.json (zone « Pi Tools ») et general_commands.json (« Outils généraux »). core.cpp (moteur) et toolbox_menu.cpp (apparence) ne sont pas touchés. Si une liste manque, tout démarre quand même ; on y lit « Fichier manquant ». L'avantage : une nouvelle ligne dans un fichier texte ne demande aucune recompilation.

42.7 Comparaison Python et C++

Python (PyQt5) C++ (Qt5)
Essayer une modification enregistrer le fichier, redémarrer bash build.sh, puis démarrer
Temps de démarrage plus lent (interpréteur, imports) plus rapide
Besoin en mémoire plus élevé plus faible
Erreurs d'écriture visibles seulement à l'exécution beaucoup dès la compilation
Paquets supplémentaires PyQt5, bibliothèques Python compilateur, paquets de développement Qt5
Bibliothèques auxiliaires modules Python nlohmann/json (dans le projet), PIL disparaît (Qt dessine les polices système)
Courbe d'apprentissage plate raide (pointeurs, en-têtes, CMake)
Convient pour essayer, apprendre appareil fini qui doit tourner vite et sobrement

Appréciation honnête : la version C++ a été portée depuis l'état Python. Qui veut développer de nouvelles fonctions le fait d'abord en Python et les porte plus tard, quand elles ont fait leurs preuves.
