Mon objectif : si le SSD tombe en panne, une copie du système d’exploitation doit exister, automatiquement, chaque jour ou chaque semaine.

9.1 Trois possibilités

  1. Clone sur un second SSD (programme rpi-clone) : le second SSD est immédiatement amorçable. Si le SSD 1 tombe en panne, on branche le SSD 2 et le travail continue.
  2. Fichiers de sauvegarde sur un disque dur externe (programme raspiBackup) : plusieurs versions, par exemple celle de la semaine dernière et celle d’il y a un mois.
  3. Sauvegarde par le réseau vers un NAS ou un autre ordinateur Linux.

9.2 Quelle solution ?

rpi-clone raspiBackup
Copie amorçable ja ja
Plusieurs anciennes versions non ja
Automatique ja ja
Retour en arrière en cas d’erreur tardive non, l’erreur est copiée aussi oui, avec une version plus ancienne

Exemple de la différence : qui installe quelque chose de faux le lundi et ne le remarque que le vendredi a déjà copié l’erreur dans le clone. Avec raspiBackup, on revient à l’état de dimanche. La « solution de luxe » est de combiner les deux. J’ai choisi raspiBackup. Ce n’est pas une appli avec fenêtre, mais un script en ligne de commande avec un installateur piloté par menu.

À retenir : une sauvegarde n’est une sauvegarde que lorsqu’on a testé qu’elle démarre vraiment.

9.3 Installation pas à pas (Pi 5 : NVMe comme système, second SSD comme sauvegarde)

  1. Brancher le second SSD et l’identifier avec lsblk (pas le SSD système !).
  2. Formater : sudo mkfs.ext4 -L BACKUP /dev/sda1
  3. Monter : sudo mkdir /backup et sudo mount /dev/sda1 /backup
  4. Installer raspiBackup :
curl -sSLO --fail https://raw.githubusercontent.com/framps/raspiBackup/master/published/raspiBackupInstallUI.sh
sudo bash ./raspiBackupInstallUI.sh
  1. Dans le menu, définir le chemin de sauvegarde (/backup). Une première sauvegarde se lance avec sudo raspiBackup.
  2. Automatiquement chaque semaine (par exemple dimanche à 3 h) via cron ou une minuterie systemd, comme proposé dans le menu d’installation.
