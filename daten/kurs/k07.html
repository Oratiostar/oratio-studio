Meine Frage war: Was ist mkfs? Ich will alles über Formatierung, Partitionen und die Befehle wissen. Hier die Antwort in Ordnung.

7.1 Was passiert bei einer Formatierung?

Eine neue SSD ist wie ein leeres Grundstück. Sie hat Speicherplatz, aber Linux weiß noch nicht, wo Dateien und Ordner liegen. Beim Formatieren entsteht diese Struktur: Verzeichnisse, Dateitabelle, Verwaltung des freien Platzes.

7.2 Die Namen der Laufwerke

Linux behandelt Geräte wie Dateien. Sie liegen unter /dev:

Name Bedeutung
/dev/mmcblk0 microSD-Karte
/dev/sda, /dev/sdb USB- oder SATA-Laufwerke
/dev/nvme0n1 NVMe-SSD
/dev/sda1 erste Partition auf sda
/dev/nvme0n1p1 erste Partition auf der NVMe
/dev/ttyUSB0 ein serielles USB-Gerät (zum Beispiel Arduino Nano)

Regel: Man formatiert nicht das ganze Laufwerk (/dev/sda), sondern eine Partition (/dev/sda1).

7.3 Partitionen und Partitionstabelle

Eine Partition ist ein Abschnitt eines Laufwerks. Eine 1-TB-SSD kann zum Beispiel in 500 GB für Linux und 500 GB für Daten aufgeteilt werden. Die Partitionstabelle gibt es in zwei Arten:

  • MBR – alt, maximal 2 TB und 4 Partitionen
  • GPT – modern, für große Laufwerke und viele Partitionen. Heute fast immer die richtige Wahl.

7.4 Der komplette Ablauf: neue SSD einrichten

Schritt 1: Laufwerk finden (immer zuerst!)

lsblk

Beispielausgabe:

nvme0n1   1TB   ← System
sda       1TB   ← Backup-SSD

Es muss genau feststehen, welches Laufwerk welches ist. Wer sich hier irrt, formatiert das System.

Schritt 2: Partitionstabelle und Partition anlegen

sudo parted -s /dev/sda mklabel gpt
sudo parted -s /dev/sda mkpart primary ext4 0% 100%

Das erste Kommando legt eine GPT-Tabelle an, das zweite erzeugt eine Partition über die ganze Größe. Alternativ geht es interaktiv mit sudo fdisk /dev/sda. Dort gilt: p zeigt, n neue Partition, d löscht, w speichert, q beendet ohne Speichern.

Schritt 3: Dateisystem anlegen

sudo mkfs.ext4 -L BACKUP /dev/sda1
  • mkfs = „make file system", Dateisystem erzeugen
  • ext4 = Typ, der Standard für Linux (schnell, stabil)
  • -L BACKUP = ein Name für das Laufwerk
  • /dev/sda1 = die Partition

Andere Dateisysteme: exFAT (Austausch mit Windows und Mac), FAT32 (alt, 4-GB-Dateilimit), NTFS (Windows).

Schritt 4: Einhängen (mounten)

sudo mkdir /backup
sudo mount /dev/sda1 /backup
df -h

Ein Laufwerk ist in Linux erst nutzbar, wenn es an einem Ordner eingehängt ist. Danach erscheint es unter /backup.

Schritt 5: Rechte setzen

sudo chown oratio:oratio /backup

Sonst gehört der Ordner root, und der eigene Benutzer darf dort nichts speichern.

Schritt 6: Aushängen, bevor das Laufwerk abgezogen wird

sudo umount /backup

7.5 Dauerhaft einhängen: fstab

Ein normales mount gilt nur bis zum Neustart. Damit die SSD beim Start immer eingehängt wird, steht sie in /etc/fstab:

cat /etc/fstab
sudo blkid                # zeigt die UUID jedes Laufwerks
sudo nano /etc/fstab

Beispielzeile (die UUID aus blkid verwenden, nicht /dev/sda1, weil sich diese Namen ändern können):

UUID=<UUID-AUS-BLKID>  /backup  ext4  defaults  0  2

Danach sudo mount -a zum Testen. Ein Fehler in /etc/fstab kann den Pi am Start hindern, also diese Datei besonders vorsichtig bearbeiten.

7.6 Weitere nützliche Befehle

lsblk -f                     # mit Dateisystem
findmnt                      # alle eingehängten Laufwerke als Baum
findmnt /                    # von welchem Laufwerk läuft das System?
sudo blkid                   # UUID und Typ

7.7 Geschwindigkeit messen

Mein Ziel war, die Geschwindigkeit von SD-Karte, USB-SSD und NVMe zu vergleichen.

sudo hdparm -Tt /dev/sda             # USB-SSD
sudo hdparm -Tt /dev/nvme0n1         # NVMe
sudo hdparm -Tt /dev/mmcblk0         # SD-Karte

-T misst den Zwischenspeicher, -t die echte Lesegeschwindigkeit. Genauer ist fio:

sudo apt install fio
sudo fio --name=USB-Read-Test --filename=/dev/sda --rw=read --bs=1M --size=2G --direct=1

Und der einfachste Schreibtest ohne zusätzliche Software:

dd if=/dev/zero of=test.img bs=1M count=1024 conv=fdatasync
rm test.img

Am Ende steht eine Zeile wie 1073741824 bytes copied, 2.5 s, 430 MB/s. Die Testdatei danach löschen. Der Test mit fio auf --filename=/dev/... liest direkt vom Laufwerk, das ist nur lesend und damit sicher. Schreibtests nie auf ein Laufwerk mit wichtigen Daten richten.

7.8 Bootreihenfolge beim Pi 5

Ich wollte „SD-Karte als Betriebssystem, NVMe nur zum Testen". Die Bootreihenfolge steht im EEPROM des Pi:

sudo rpi-eeprom-config | grep BOOT_ORDER

Über sudo raspi-config (Advanced Options, Boot Order) ändert man die Reihenfolge. Danach mit lsblk und findmnt / prüfen, von welchem Laufwerk das System tatsächlich startet.
