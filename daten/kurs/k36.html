36.1 Die Grundentscheidung

Projekt B beginnt mit einem Satz, den ich mir zur Regel gemacht habe:

app_ui.py startet alles. Jeder Tab und jedes Gerät hat einen eigenen Ordner mit einer eigenen .py-Datei und lässt sich einzeln löschen.

Ein neuer Tab ist damit eine Datei plus etwa drei Zeilen in app_ui.py. Ein Tab, den ich nicht mehr will, verschwindet, indem ich seinen Ordner lösche. Das Programm startet trotzdem.

Wichtig an der Aufteilung:

  • glass_ui.py gehört allen Tabs und bleibt immer liegen. Ohne diese Datei läuft nichts.
  • Dateien, die das Programm selbst erzeugt (Einstellungen, Verlauf), liegen in Json/.

36.3 app_ui.py: Tabs laden, ohne dass ein fehlender Ordner stört

Die Besonderheit von app_ui.py ist, dass ein fehlender Tab das Programm nicht stoppt:

def _tab_laden(modul, klasse):
    """Eine Tab-Klasse aus ihrem Ordner holen. Ordner gelöscht oder kaputt?
    Dann gibt es den Tab einfach nicht - der Rest startet trotzdem."""
    try:
        return getattr(__import__(modul, fromlist=[klasse]), klasse)
    except Exception as _ex:
        print(f"Tab {klasse} nicht geladen: {_ex}")
        return None

HomeTab    = _tab_laden("Oratio_Menu.oratio_menu", "HomeTab")
TowerTab   = _tab_laden("Tower.tower_tab", "TowerTab")
MenuTab    = _tab_laden("Oratio_Menu.oratio_menu", "MenuTab")
ToolboxTab = _tab_laden("Oratio_Toolbox.toolbox_menu", "ToolboxTab")
TABS = [("Home", HomeTab), ("Oratio Menu", MenuTab),
        ("Tower", TowerTab), ("Oratio Toolbox", ToolboxTab)]

Was hier steckt:

Baustein Bedeutung
__import__(modul, fromlist=[klasse]) lädt ein Modul, dessen Name als Text vorliegt
getattr(modul, klasse) holt die Klasse mit diesem Namen daraus
try ... except fängt jeden Fehler beim Laden ab
return None „es gibt diesen Tab nicht“
TABS = [...] die Reihenfolge der Liste ist die Reihenfolge in der Leiste

Danach legt das Hauptfenster nur noch die vorhandenen Tabs an:

for name, klasse in TABS:
    if klasse is None:
        continue
    tab = klasse(self.width(), self.height())
    self.tab_widget.addTab(tab, name)

Regel für jede Tab-Klasse: Der Konstruktor bekommt Breite und Höhe, also def __init__(self, width, height).

Dieser Gedanke zieht sich durch das ganze Projekt: Ein kaputtes Teil darf nie das Ganze stoppen. Derselbe Trick (try/except beim Laden) steckt in den Widgets (Kapitel 37) und in der Toolbox.

36.4 Start, Neustart und Installation

run_app.sh startet das Programm ohne sudo. Das ist die Folge aus Projekt A (Kapitel 32.5): Das Fenster braucht keine Systemrechte, deshalb gehören alle Dateien weiter dem normalen Benutzer. Lüfter, LED und OLED laufen als eigene Dienste im Hintergrund, die ihre Rechte selbst mitbringen. Das Skript hat noch eine Besonderheit: Es startet nach einem Absturz selbst neu.

FEHLER=0
while true; do
    START=$(date +%s)
    python3 app_ui.py
    CODE=$?
    [ "$CODE" -eq 0 ] && exit 0          # normales Beenden: nichts neu starten
    NOW=$(date +%s)
    if [ $((NOW - START)) -lt 60 ]; then FEHLER=$((FEHLER + 1)); else FEHLER=1; fi
    echo "Absturz (Code $CODE) - Details in Logs/oratio.log"
    [ "$FEHLER" -ge 3 ] && { echo "Zu viele Abstürze - Abbruch."; exit "$CODE"; }
    sleep 2
done

Die Logik: Endet das Programm mit Code 0, war es ein normales Schließen. Jeder andere Code ist ein Absturz, nach zwei Sekunden folgt ein Neustart. Stürzt es dreimal innerhalb einer Minute ab, gibt das Skript auf, damit kein Endlos-Neustart entsteht.

Fehlerprotokoll: Abstürze und Fehlermeldungen landen in Logs/oratio.log. Ab 1 MB wird die Datei zu oratio.log.1, und eine neue beginnt. Bei einem Problem ist das die erste Datei zum Nachsehen.

install.sh richtet einen neuen Pi in einem Zug ein:

  1. Raspberry Pi OS mit Desktop aufspielen, Benutzer oratio.
  2. Den ganzen Ordner vom alten Pi (USB-Stick) nach /home/oratio/ kopieren. Nur so kommen Apps, Widgets, Einstellungen und der PS5-Schlüssel mit.
  3. cd ~/Oratio_Control_Center und bash install.sh. Nicht mit sudo starten, das Skript fragt selbst danach.
  4. Den Fragen folgen, am Ende neu starten.

Das Skript darf beliebig oft laufen. Es prüft zuerst, ob es im Projektordner liegt und ob es nicht als root läuft. Danach installiert es die Pakete (apt) und kopiert die LED-Treiber nach /usr/local/lib.

Ohne Internet: Die Freenove-Treiberbibliotheken (libfreenove_ws2812_lib.so, libfreenove_pwm_lib.so) liegen im Projekt unter LED/Treiber/. Beide brauchen die PIO-Bibliothek des Pi (libpio.so.0), die normalerweise vorhanden ist. Internet braucht man nur für den ersten apt-Schritt, das Wetter, die PS5-Kopplung und Update-Kacheln.

Sudo ohne Passwort prüfen (für Neustart, Ausschalten und die Geräteschalter nötig):

sudo -k
sudo -n true && echo OK || echo "Passwort wird verlangt"

Kommt „Passwort wird verlangt“, bash install.sh erneut ausführen.

Tägliche Sicherung der Einstellungen: Beim Start kopiert das Programm einmal pro Tag alle Einstellungen aus Json/ nach Json/Backup/<Datum>/. Die letzten sieben Tage bleiben, ältere werden entfernt. Zurückholen: Programm beenden, die Dateien aus dem Datumsordner nach Json/ kopieren.

36.5 glass_ui.py: der Glas-Werkzeugkasten

Alles, was gemeinsam gebraucht wird, steht in einer Datei mit rund 1700 Zeilen:

Baustein Aufgabe
S(v) rechnet eine Größe mit dem Skalierfaktor um: derselbe Code sieht auf 1080p und 4K gleich aus
paint_glass(p, rect, ...) zeichnet eine Glasfläche (durchscheinend, heller Rand, Glanz)
GlassPanel ein Fenster im Glas-Look (Rahmen, Titelleiste, Schließen-Knopf)
GlassButton, GlassToggle, GlassMiniButton Schaltflächen, Schalter, kleine Knöpfe
GlassTabBar, GlassTabWidget die Tab-Leiste mit Glaskapseln
ui_font(px, weight) liefert die Schrift der Oberfläche (Inter)
set_night_mode, set_accent Nachtmodus und Akzentfarbe für alle Fenster
load_icon_pixmap, scaled_cached lädt Icons auf höchstens 512 Pixel begrenzt und merkt sich die skalierten Bilder
daily_backup, setup_logging tägliche Sicherung, Fehlerprotokoll

Dadurch sehen alle Fenster gleich aus, und eine Änderung am Glas-Look betrifft mit einer Zeile alles. In Projekt A war dagegen jede Kachel einzeln mit einem Stylesheet gestaltet.

Die vier Modi: Glas oder Matt, jeweils normal oder Nacht. Ein Fenster fragt nicht selbst, wie es aussehen soll, sondern ruft den Werkzeugkasten. Deshalb funktioniert ein neues Fenster sofort in allen vier Modi.

36.6 Wo liegt was? (im Ordner Oratio_Menu)

Das Menü war zeitweise eine Datei mit über 10 000 Zeilen. Ich habe sie nach Themen zerlegt, ohne das Verhalten zu ändern (der Code ist Zeichen für Zeichen derselbe, nur anders einsortiert). Die Gliederung ist heute die Landkarte des Projekts:

Kern/ – Grundbausteine ohne Fenster

Datei Inhalt
abhaengigkeiten.py optionale Teile mit Ersatz (Fensterleiste, Leisten-Vorgaben)
konstanten.py feste Zahlen: Rastergrenzen, Symbolgrößen, Farbschema, App-Fensterarten
stil.py Glas-Stil des Kontrollfensters
symbole.py alle selbst gezeichneten Symbole (draw_..._icon)
modell.py MenuItem und die Raster-Rechnerei (Seiten, freie Plätze)
umzug.py einmaliger Umzug alter Ordner und JSON-Dateien beim Start
programme.py installierte Programme, Startarten, Installation
system.py Befehle starten, WLAN/Bluetooth schalten, Helligkeit, Ton

Bausteine/ – sichtbare Bauteile: kacheln.py (App-Kachel, Raster, Seitenpunkte, Ziehbild), menueleiste.py (Glas-Leiste oben), dock.py, kontrollzentrum.py (Kontrollfenster).

Fenster/ – Glasfenster: einstellungen.py, verbindungen.py (WLAN, Bluetooth, Mikrofon, Energie), apps.py (App hinzufügen/bearbeiten, Mediathek), galerie.py (Widget-Galerie), zentrale.py (die Liste aller Einstellungen).

Ansicht/ – die Hauptansicht MenuView in Teilen (alle zusammen ergeben eine Klasse):

Datei Inhalt
ansicht.py Aufbau, Größe, Zeichnen, Ereignisse
speicher.py Laden, Speichern, Profile, Sicherung
leiste.py Menü-Leiste und Menü-Fenster
fenster.py Overlay oben rechts, Seiten-Fenster, Klick auf die Symbole
design.py Stil, Nachtmodus, Effekte, Schrift, Hintergrund, Dock-Look
laufende.py Leiste der laufenden Fenster
raster.py Seiten, Kacheln, Bearbeiten-Modus, Größe ändern

ziehen.py Apps im Raster ziehen
tastatur.py Bedienung per Tastatur und Joystick
starten.py Apps und Widgets starten, anlegen, löschen

Technik der Aufteilung: MenuView erbt von mehreren „Mixin“-Klassen, je eine pro Datei (class MenuView(ZiehenMixin, RasterMixin, ...)). Jede Datei enthält nur einen Teil der Methoden, zusammen ergeben sie eine Klasse.

Wo kommt eine neue Funktion hin? Als eigene Datei (wie mitteilungen.py, suche.py) oder als eigenes Fenster in Fenster/ – nicht wieder in eine Riesendatei.

Der Nachteil, den ich ehrlich notiere: Eine neue Idee berührt oft mehrere Teile, die zusammenpassen müssen (Ansicht, Fenster, Suche, Einstellungsliste). Bei einer Einzeldatei kann man alles in einem Rutsch suchen und ersetzen, bei vielen Dateien muss man wissen, welche zusammengehören. Die Updates in der Anleitung führen deshalb immer auf, welche Dateien sich ändern.

36.7 Die Einstellungsdateien (Json/)

Jedes Gerät und jede Funktion merkt sich ihren Zustand in einer eigenen JSON-Datei, die beim ersten Ändern von selbst entsteht:

Datei Inhalt
oratio_apps.json alle Kacheln (Apps und Widgets) mit Name, Farbe, Größe, Seite, Zeile, Spalte
oratio_home.json die Kacheln des Tabs „Home“
oratio_menu_settings.json Aussehen, Dock, Leisten, Effekte
oratio_wetter.json Ort fürs Wetter
oratio_stimme.json Sprachsteuerung
oratio_sperre.json Sperrbildschirm (der Code steht nur als Prüfsumme)
oratio_fokus.json Fokus-Profile
oratio_nutzung.json Nutzungsstatistik
Json/Profile/<Name>/ gespeicherte Einstellungs-Profile
Json/Backup/<Datum>/ tägliche Sicherung

Ein Eintrag in oratio_apps.json sieht so aus:

{"name": "Icon Werkstatt",
 "file": "/home/oratio/Oratio_Control_Center/Oratio_Menu/Apps/Icon_Werkstatt/icon_werkstatt.py",
 "icon": "Oratio_Menu/Apps/Icon_Werkstatt/icon.png",
 "color": "#000000", "terminal": false, "embed": true,
 "id": "icon_werkstatt", "slot": 8, "row": 0, "col": 8}
Schlüssel Bedeutung
file das Skript, das gestartet wird
icon Bild der Kachel
color Kachelfarbe
embed true = die App läuft im Glasfenster des Control Centers („Im Oratio-Look öffnen“)
terminal true = in einem Terminal-Fenster starten
slot, row, col Platz im Raster

Ein Widget hat statt file den Schlüssel "widget": "network" sowie w und h für die Größe in Kästchen.
