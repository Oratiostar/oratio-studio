32.1 Point de départ : le programme Freenove

La tour Freenove (chapitre 11) est livrée avec une interface Python toute faite. Elle a quatre onglets :

Monitor | LED | Fan | OLED

Le fichier app_ui.py construit la fenêtre principale. Chaque onglet est une classe à part qui appartient à son propre fichier (LED, ventilateur, OLED). L'interface se lance avec python3 app_ui.py ou via un petit script de démarrage run_app.sh. Tout le reste repose sur cette structure. Le fait que Qt (la bibliothèque d'interface) fournisse un widget d'onglets (QTabWidget) auquel on peut accrocher autant d'onglets que l'on veut est la base des étapes suivantes.

À retenir : qui étend un programme étranger étend d'abord une copie. J'ai copié le dossier avec tous les fichiers Python et n'ai travaillé que sur la copie. L'original est ainsi resté pour comparer.

32.2 Objectif : un onglet « Scripts »

Je voulais un cinquième onglet à droite d'OLED :

Monitor | LED | Fan | OLED | Scripts

Au clic, quatre rectangles (boutons) devaient apparaître, chacun portant le nom d'un script. Un clic sur un rectangle lance le script. Les premiers scripts étaient des programmes que j'avais déjà : un vérificateur de fichiers (Hash-Checker, voir chapitre 45), une sauvegarde, un test OLED et un script de mise à jour.

32.3 Le nouveau fichier

L'onglet reçoit son propre fichier pour que app_ui.py ne s'allonge pas davantage : app_ui_scripts.py. Il contient une classe avec une grille (QGridLayout) et quatre boutons :

from PyQt5.QtWidgets import QWidget, QPushButton, QGridLayout
import subprocess

class ScriptsTab(QWidget):
    def __init__(self):
        super().__init__()
        layout = QGridLayout()
        self.btn1 = QPushButton("Backup")
        self.btn2 = QPushButton("Update")
        self.btn3 = QPushButton("OLED Test")
        self.btn4 = QPushButton("Hash Checker")
        layout.addWidget(self.btn1, 0, 0)
        layout.addWidget(self.btn2, 0, 1)
        layout.addWidget(self.btn3, 1, 0)
        layout.addWidget(self.btn4, 1, 1)
        self.setLayout(layout)

        self.btn1.clicked.connect(lambda: self.run_script("backup.py"))
        self.btn4.clicked.connect(lambda: self.run_bash("hashchecker.sh"))

    def run_script(self, filename):
        try:
            subprocess.Popen(["python3", filename])
        except Exception as e:
            print(e)

    def run_bash(self, filename):
        try:
            subprocess.Popen(["lxterminal", "-e", f"bash {filename}"])
        except Exception as e:
            print(e)

Ce que font les éléments :

Élément Signification
QGridLayout dispose des éléments en lignes et colonnes : addWidget(élément, ligne, colonne)
QPushButton("Text") un bouton avec libellé
.clicked.connect(...) relie le clic à une fonction
lambda: ... une petite fonction anonyme ; nécessaire pour transmettre le nom de fichier au moment du clic
subprocess.Popen([...]) lance un autre programme sans que l'interface attende
lxterminal -e ... ouvre une fenêtre de terminal et y exécute une commande

32.4 Accrocher l’onglet dans app_ui.py

Dans app_ui.py, trois endroits suffisent :

  1. en haut from app_ui_scripts import ScriptsTab,
  2. là où les onglets sont créés, self.tab_widget.addTab(ScriptsTab(), "Scripts"),
  3. enregistrer et redémarrer.

C'est le principe pour chaque onglet supplémentaire : un fichier propre avec une classe QWidget, un import, un addTab.

32.5 Le Hash-Checker ne se lançait pas depuis le Control Center

Le script hashchecker.sh est un script Bash (shell), pas un script Python. Avec python3 hashchecker.sh, il ne se lançait pas. D'où la seconde fonction run_bash, qui l'exécute avec bash dans une fenêtre de terminal. J'avais testé le script lui-même au préalable dans le terminal, car cela exclut la source d'erreur la plus rapide :

cd ~/Dokumente/Code
bash hashchecker.sh

S'il ne fonctionne pas là, l'erreur est dans le script. S'il fonctionne là mais pas depuis le Control Center, elle est dans l'interface.

L'erreur avec sudo

C'est exactement ce cas qui s'est produit : lancé depuis le terminal (python3 app_ui.py), tout fonctionnait ; via ./run_app.sh, le Hash-Checker ne démarrait pas. La comparaison des deux chemins a montré : dans run_app.sh, il y avait sudo python app_ui.py. Ainsi, le programme entier tourne en tant qu'utilisateur root, et root a un autre dossier personnel, d'autres chemins et un autre environnement que l'utilisateur oratio. Les scripts qui ont besoin de chemins relatifs ou de l'affichage de l'utilisateur normal échouent alors.

La solution : lancer le programme en tant qu'utilisateur normal et n'utiliser sudo que là où une commande isolée en a vraiment besoin.

À retenir : si quelque chose fonctionne dans le terminal mais pas par script de démarrage ou icône, c'est l'environnement qui diffère : utilisateur, dossier actuel, variables d'environnement. Comparer d'abord, ne pas deviner. Un test simple : insérer dans la fonction print(os.getlogin()) et print(os.getcwd()) et essayer les deux chemins.

32.6 Lancer le script ou dans sa propre fenêtre ?

Au début, le script démarrait dans la même fenêtre que l'interface et la recouvrait. Une fenêtre propre (terminal ou QProcess) est la meilleure solution. À retenir : l'interface lance des programmes, elle ne devient pas elle-même le programme.

32.7 Quand l’onglet ne s’accroche pas : l’indentation

Dans cette partie du travail est apparue l'erreur de débutant la plus fréquente avec Python : l'indentation. Python reconnaît les blocs aux espaces en début de ligne. Si l'on mélange tabulations et espaces, le code a l'air correct dans l'éditeur et s'arrête pourtant :

TabError: inconsistent use of tabs and spaces in indentation
IndentationError: unexpected indent

La cause était mon éditeur (Geany) : il insérait en partie des tabulations, alors que je tapais moi-même des espaces. Règles à retenir :

  • Quatre espaces par niveau, jamais de tabulations.
  • Régler l'éditeur pour que la touche Tab insère des espaces.
  • Vérifier sans lancer : python3 -m py_compile datei.py indique la ligne.
  • Nettoyer un fichier mélangé : expand -t 4 datei.py > datei_neu.py.

Ce qui tourne particulièrement souvent mal en collant du code d'un tutoriel : le nouveau bloc doit commencer exactement au même niveau que les lignes voisines. Astuce : sélectionner d'abord la ligne précédente et regarder son indentation, puis coller.

32.8 La méthode selon laquelle j’ai travaillé

De ce chapitre, je retiens la façon dont j'ai abordé chaque étape suivante :

  1. Modifier une seule chose par étape, puis lancer et tester.
  2. Lancer dans le terminal (python3 app_ui.py), pas par une icône, pour que les messages d'erreur soient visibles.
  3. À chaque modification, savoir dans quel fichier et à quel endroit elle se trouve.
  4. Une erreur est d'abord circonscrite (script seul, interface seule), puis corrigée.
  5. Sauvegarder une version qui fonctionne avant de continuer à construire.
