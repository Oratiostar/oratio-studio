41.1 Worum es geht

In Projekt A und in der ersten Form von B wird das Ziehen aus Maus-Ereignissen zusammengebaut: mousePressEvent merkt sich den Anfang, mouseMoveEvent verschiebt ein Bild, mouseReleaseEvent entscheidet. In dieser Variante übernimmt Qt selbst das Ziehen mit QDrag, QMimeData und dropEvent. Das Verhalten ist gleich: auf belegten Platz = tauschen, auf leeren Platz = alter Platz bleibt leer, Seitenwechsel am Rand (0,75 s, danach 1,1 s), Lücke im Dock, Milchglas auf der Ziel-App.

Neu dadurch: Esc bricht das Ziehen ab (die App bleibt an ihrem Platz). Loslassen außerhalb des Fensters bedeutet abgebrochen.

41.2 Der Ablauf in vier Schritten

(aus der Beschreibung in Parts/view_dnd.py)

  1. Die Kachel oder das Dock-Symbol meldet „weit genug gezogen“ (Signal dragRequested). Die Ansicht startet _start_tile_drag bzw. _start_dock_drag.
  2. Dort wird ein QDrag mit dem schwebenden Bild gestartet. QDrag.exec_() läuft, bis losgelassen oder abgebrochen wird. Währenddessen laufen Timer und Animationen normal weiter.
  3. Die ganze Ansicht ist das Ziel. dragEnterEvent, dragMoveEvent, dragLeaveEvent und dropEvent bekommen die Zeigerposition und zeigen die Vorschau.
  4. Nach exec_() setzt _drag_done bzw. _dock_drag_done die App ein (losgelassen) oder nimmt alles zurück (Abbruch).

41.3 Der Kern in wenigen Zeilen

from PyQt5.QtCore import QMimeData, Qt
from PyQt5.QtGui import QDrag

def _run_qt_drag(self, image, hotspot, mime_type, payload):
    """Kehrt erst zurück, wenn losgelassen oder abgebrochen wurde."""
    data = QMimeData()
    data.setData(mime_type, payload)      # welche Art Ding wird gezogen (Kachel, Dock-Symbol)
    drag = QDrag(self)
    drag.setMimeData(data)
    drag.setPixmap(image)                 # das schwebende Bild
    drag.setHotSpot(hotspot)              # wo im Bild "angefasst" wurde
    return drag.exec_(Qt.MoveAction)

Damit die Ansicht Ziehvorgänge überhaupt annimmt, muss sie setAcceptDrops(True) setzen und die vier Ereignis-Methoden überschreiben. Die MIME-Namen für Kachel und Dock stehen in Parts/consts.py (MIME_TILE, MIME_DOCK, für das Kontrollfenster MIME_CC).

41.4 Vergleich zur Maus-Ereignis-Lösung

Maus-Ereignisse (A, erstes B) Qt-Drag&Drop
Code selbst verwaltet: Zustand, Schwelle, Bild Qt verwaltet Ablauf, Code kürzer
Abbruch mit Esc muss selbst gebaut werden geschenkt
Loslassen außerhalb muss selbst behandelt werden geschenkt
Schwebendes Bild eigenes Widget, das dem Zeiger folgt setPixmap
Laufen Animationen weiter? ja ja (exec_ hat eine eigene Ereignisschleife)
Fehlerbild Bild bleibt hängen, wenn Release verloren geht selten
Eigene Feinheiten (Randzeit, Vorschau) direkt im Move-Ereignis im dragMoveEvent

Wo Qt-Drag&Drop nicht passt: Beim Größe ändern der Kacheln im Kontrollfenster (untere rechte Ecke) bleibt die alte Maus-Logik, weil das kein Ziehen eines Dings ist, sondern ein Verändern.
