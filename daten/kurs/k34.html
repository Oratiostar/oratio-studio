34.1 Das Ziel

Wie auf dem Handy sollten die Kacheln mit der Maus verschiebbar sein: auf eine andere Kachel ziehen tauscht beide, auf einen leeren Platz ziehen setzt die Kachel dorthin. Die neue Position soll in der JSON-Datei stehen, damit sie nach dem Neustart bleibt.

34.2 Der Plan in drei Stufen

Ich habe das Ziehen bewusst nicht in einem Schritt gebaut, weil ein Fehler das ganze Tab lahmlegt:

Stufe Ziel Erfolgskontrolle
1 Erkennen, dass eine Kachel gezogen wird im Terminal erscheint „Ziehe: Backup“
2 Wissen, wo sie losgelassen wurde Ausgabe „von (0,0) nach (3,2)“
3 Tauschen und in JSON speichern nach Neustart bleibt die Reihenfolge

34.3 Stufe 1: eine eigene Schaltflächen-Klasse

Eine normale QPushButton meldet keine Mausbewegung. Deshalb bekommt jede Kachel eine eigene Klasse, die von QPushButton erbt und drei Maus-Ereignisse selbst behandelt:

from PyQt5.QtCore import Qt, QPoint

class DraggableButton(QPushButton):
    def __init__(self, text, parent=None):
        super().__init__(text, parent)
        self.drag_start_position = QPoint()

    def mousePressEvent(self, event):
        if event.button() == Qt.LeftButton:
            self.drag_start_position = event.pos()
        super().mousePressEvent(event)

    def mouseMoveEvent(self, event):
        if not (event.buttons() & Qt.LeftButton):
            return
        distance = (event.pos() - self.drag_start_position).manhattanLength()
        if distance < 10:
            return
        print(f"Ziehe: {self.text()}")

Was hier passiert:

  • mousePressEvent: Taste gedrückt, den Startpunkt merken.
  • mouseMoveEvent: Maus bewegt. Erst wenn sie mehr als 10 Pixel vom Startpunkt entfernt ist, gilt es als Ziehen. Das verhindert, dass ein normaler Klick versehentlich als Ziehen zählt.
  • mouseReleaseEvent kommt in Stufe 2.

Im Code genügt dann die Änderung btn = DraggableButton(...) statt btn = QPushButton(...).

34.4 Stufe 2 und 3: Ziel finden, tauschen, speichern

Beim Loslassen wird geprüft, über welcher anderen Kachel die Maus steht. Dazu holt man für jede Kachel ihr Rechteck in Fenster-Koordinaten und prüft, ob der Mauspunkt darin liegt. Dann gibt es zwei Fälle:

  1. Ziel ist belegt: beide Einträge in der Liste tauschen ihre Position.
  2. Ziel ist leer: nur der gezogene Eintrag bekommt die neue Position.

Danach schreibt das Programm die Liste in oratio_apps.json zurück.

Typische Fehler auf diesem Weg:

Meldung oder Symptom Ursache
Programm startet gar nicht mehr nach dem Einfügen Einrückung oder Syntax: im Terminal starten, die letzte Zeile der Fehlermeldung nennt die Art (IndentationError, SyntaxError, NameError)
self.row und print stehen auf unterschiedlicher Ebene Der neue Block gehört auf die Ebene der Nachbarzeilen

34.5 „Ganz langsam“ – und warum es plötzlich schnell war

Beim Ziehen ruckelte die Oberfläche stark. Ich hatte beim Entwickeln an vielen Stellen print(...) stehen, um zu sehen, was passiert. Nachdem ich alle Ausgaben auskommentiert hatte, lief das Ziehen flüssig.

Lehre: Eine Ausgabe in ein Terminal ist langsam, vor allem, wenn sie bei jeder Mausbewegung kommt (Hunderte Mal pro Sekunde). Ausgaben zur Fehlersuche gehören nach dem Test wieder heraus oder hinter eine Bedingung. Das gilt für jede Programmiersprache.

34.6 Das Aussehen der Kacheln

Icons und Namen

Die Kacheln zeigten zuerst den Namen im Button. Ich wollte nur das Icon als Bild und den Namen darunter, außerhalb der Schaltfläche. Dafür besteht eine Kachel aus einem Container, der eine Schaltfläche (mit Bild) und ein Textfeld darunter enthält.

Fallstricke:

  • Der Pfad zum Bild steht in der JSON. Ein falscher Pfad lässt das Bild leer, und der Pfad erscheint als Text im Button. Pfad prüfen: ls Pfad/zur/Datei.png.
  • Bilder sollen alle quadratisch und gleich groß sein. Ein Icon mit mehr Rand wirkt kleiner als eines, das den Rand ausnutzt. Besser: alle Bilder mit demselben Zeichenfeld (zum Beispiel 512 × 512 Pixel, transparenter Hintergrund) anlegen.
  • Mehrere Größen gleichzeitig (ICON_SIZE, BUTTON_SIZE, HOVER_ICON_SIZE): Wenn irgendwo ein alter fester Wert (QSize(40, 40)) stehen bleibt, springen Bilder beim Klicken auf eine falsche Größe. Alle Größen an einer Stelle als Konstanten sammeln.

Hover: die Kachel wird beim Darüberfahren größer

Fährt die Maus über eine Kachel, wächst das Icon um ein paar Pixel (von 40 auf 55). Der Container muss dafür Platz lassen, sonst wird das vergrößerte Bild abgeschnitten.

Der milchige Effekt beim Ziehen

Wenn eine Kachel über eine andere gezogen wird, soll die untere Kachel milchig-weiß aufleuchten. Der Weg dorthin war lang:

  1. Ein weißes Rechteck hinter dem Bild: nicht sichtbar, weil das PNG davor liegt. Alles, was man dem Hintergrund (background-color) gibt, liegt hinter dem Bild.
  2. Ein Qt-Effekt auf der Schaltfläche (QGraphicsColorizeEffect) färbt das Bild selbst ein:
effect = QGraphicsColorizeEffect()
effect.setColor(QColor(255, 255, 255))
effect.setStrength(0.25)
button.setGraphicsEffect(effect)
  1. Gefallen hat mir am Ende eine Überlagerung (Overlay): ein halbtransparentes weißes Widget in der Größe der Kachel, mit abgerundeten Ecken, liegt vor dem Bild. Es verändert die Datei des Icons nicht und passt sich der Kachelgröße an.

Dazu gehört eine Rundungsmaske, damit der Effekt nicht über die Ecken hinausläuft. Vorgehen: erst prüfen, ob die Qt-Version die Klasse kennt (from PyQt5.QtGui import QPainterPath und eine Zeile path = QPainterPath()), dann die Maske mit addRoundedRect bauen und als Clip verwenden.

Weitere Verbesserungen, die ich nacheinander getestet habe:

  • Die gezogene Kachel wird dunkler (wie beim Antippen am Handy), die Zielkachel heller.
  • Der Effekt soll symmetrisch sein (gleichmäßiger Abstand zum Rand, nicht ein Klecks).
  • Beim Ziehen sollen die anderen Kacheln ihre eigene Farbe behalten (Blau bleibt blau).
  • Das vergrößerte Bild wird am Rand abgeschnitten: Der Container braucht mehr Platz oder der Hover-Zuwachs muss kleiner sein.

34.7 Was ich aus diesem Kapitel mitnehme

  • Ein Effekt entsteht in Schichten: Was liegt hinter, was liegt vor dem Bild?
  • Erst prüfen, ob eine Qt-Funktion in der installierten Version existiert, bevor man sie überall einbaut.
  • Entwicklungs-Ausgaben bremsen.
  • Eine Änderung, ein Test.
